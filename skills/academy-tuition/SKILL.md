# 수강료 입력

## 시작 전에 읽는다

- `../academy-core/references/db-map.md` — DB id 를 얻는다. `수강료 납부`·`납부 월` 의 `collection://<uuid>` 가 여기 있다
- `../academy-core/references/write-gate.md` — 쓰기 관문 일곱 단계(되물음 → 사전 검증 → 미리보기 표 → 승인 → 쓰기 → 결과 보고 → 남은 항목 확인). 이 스킬은 이 절차를 그대로 따르되, 아래 「절차」에는 이 스킬 고유의 것만 적는다. 배치 상한도 여기 있다
- `../academy-core/references/name-resolution.md` — 발화의 사람 이름·클래스를 `이름 붙여넣기` relation에 넣을 **과목 페이지** url로 바꾸는 절차. 「클래스 전체 지정」의 퇴원생 제외 절차를 이 스킬의 월 마감에서 그대로 재사용한다
- `../academy-core/references/query-limits.md` — 조회를 시작하기 전에 반드시 읽는다. JOIN 금지, `date:<속성>:start` 컬럼명, relation uuid 정규화, formula·rollup 조회 불가, **연월 문자열 비교 함정**이 여기 있다
- `../academy-core/references/domain-rules.md` — 쓰기 불가 속성·퇴원 정합 판정 기준
- `../academy-core/references/completeness-checks.md` — 필수·되물음·공란 허용 세 분류. 「수강료 마감」행이 이 스킬 전용이다
- `../academy-core/references/write-safety.md` — 쓰기 동작의 자율·승인 경계

`~/.academy/config.json` 이 없으면 즉시 멈추고 `academy-setup` 을 안내한다.

## 언제 쓰나

- "김서준 8월 수강료 납부 완료"
- "고2 수학 전체 9월 수강료 행 만들어줘"
- "미납 누구야"

## 쓰는 속성

두 DB 에 걸친다.

**수강료 납부**

| 속성 | 타입 | 값 |
|---|---|---|
| `수강료` | number | 원 단위 금액. 학생마다 다를 수 있으므로 추측하지 않는다(아래 「금액은 매번 확인한다」) |
| `상태` | status | `미납` / `납부 완료` 중 하나 |
| `date:납부 날짜:start` | date | 납부 완료 처리할 때만 채운다 |
| `납부 월` | relation → 납부 월 | 최대 1개. 한 건이어도 배열로 감싼다(`["https://.../<uuid>"]`) |
| `이름 붙여넣기` | relation → **학생 과목별 페이지** | 최대 1개. `name-resolution.md` 로 얻은 과목 페이지 url |
| `비고` | text | 특이사항. 보통 비운다(`completeness-checks.md` 공란 허용) |

**납부 월**

| 속성 | 타입 | 값 |
|---|---|---|
| `납부 년월` | title | `2026년 9월` 형식. **0 패딩 없음.** 이 DB는 다른 DB와 달리 title 이 비어 있지 않다 — 새로 만들 때 반드시 채운다 |

`date:<속성>:start` 표기는 조회·쓰기 양쪽 모두 그대로 쓴다. relation 은 대시 없는 uuid 가 아니라 **페이지 url 배열**을 넣는다.

**쓰지 않는 것.** 쓰기 불가 속성의 권위 목록은 `../academy-core/references/db-map.md` 「DB별 쓰기 불가 속성」이다. `수강료 납부` 줄은 `납부 금액`·`납부 문자`·`세부 상태`·`미납 알림`·`클래스`(전부 formula)이고, `납부 월` 줄은 비어 있다(쓰기 불가 속성이 없다). 그 밖에 `수강료 납부`의 title(빈 이름 속성)은 채우지 않는다 — 넘기지 않으면 자동으로 `""` 가 된다.

## 절차

`write-gate.md` 일곱 단계를 그대로 따른다. 아래는 이 스킬 고유의 것만 적는다.

### 사전 검증 (2단계)

- **(가) 수업일 대조 — 적용하지 않는다.** `납부 날짜`는 수업일과 무관하다(학부모가 아무 날에나 낼 수 있다). `domain-rules.md` 「클래스 요일 정합」의 적용 대상은 출결·과제·시험뿐이다.
- **(나) 중복 — 이 스킬의 급소다. 키는 날짜가 아니라 `납부 월` + 과목 페이지다.** 한 학생의 한 과목은 한 달에 한 행만 있어야 한다. 월 마감(재원생 전원 대상 일괄 생성)에서 이미 그 달 행이 있는 학생을 빼지 않으면 **중복 청구**가 된다. 개인 처리든 월 마감이든 쓰기 전에 반드시 이 조회부터 한다.

  개인 건(학생 1명):
  ```sql
  SELECT id, "상태", "수강료" FROM "collection://<수강료 납부>"
  WHERE "납부 월" LIKE '%<납부월 대시 없는 uuid>%' AND "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'
  ```

  월 마감(대상자 전체, 한 번의 조회로 그 달 기청구자를 전부 얻는다):
  ```sql
  SELECT id, "이름 붙여넣기" FROM "collection://<수강료 납부>" WHERE "납부 월" LIKE '%<납부월 대시 없는 uuid>%'
  ```
  반환된 `이름 붙여넣기` 값에서 과목 페이지 uuid 를 뽑아 정규화한 뒤, 후보 명단(퇴원생을 이미 뺀 상태)에서 그 uuid 를 가진 행을 뺀다. 남는 것만 새로 만든다.

- **(다) 직전 과제 — 해당 없음.** `academy-homework` 전용이다.
- **(라) 퇴원 — 한다.** 판정은 `../academy-core/references/write-gate.md` 2단계 (라)를 따른다. 수강료는 `domain-rules.md` 「퇴원 정합」의 대상이다. 월 마감 경로는 아래 「월 마감」 2단계가 명단에서 아예 빼는 형태로 이 검증을 수행하고, **개인 건("김서준 8월 수강료 납부 완료")은 그 경로를 타지 않으므로** 이름 해석 때 읽은 `date:퇴원 날짜:start` 로 여기서 판정한다.

### 납부 월 찾기·만들기

`납부 월` DB 는 속성이 `납부 년월`(title) 하나뿐이고 개수가 학생 수와 무관하게 적으므로(`query-limits.md` 「행이 많은 DB」구분) 통째로 읽는다.

```sql
SELECT id, url, "납부 년월" FROM "collection://<납부 월>"
```

각 행의 `납부 년월`을 연·월 숫자로 파싱해 목표 연월과 비교한다(`query-limits.md` 「날짜·연월은 표시되는 텍스트로 비교하지 않는다」의 파싱 규칙을 그대로 쓴다) — 목표 문자열과 **정확히 일치하는지만** 보면, 구매자 데이터의 0 패딩이 흔들릴 때(예: `2026년 09월`) 이미 있는 달을 못 찾아 중복 `납부 월` 행을 새로 만들 위험이 있다. 파싱 비교로도 일치하는 행이 없을 때만 새로 만든다. 형식(`<연도>년 <월>월`, 0 패딩 없음)은 기존 행을 그대로 따른다.

### 개인 납부 완료 처리

`상태` 를 `납부 완료` 로 바꾸고 `date:납부 날짜:start` 를 **함께** 채운다. 둘 중 하나만 채우면 `미납 알림` formula 가 어긋난다 — `미납 알림` 자체는 쓸 수 없는 formula 이지만(「쓰지 않는 것」), 그 formula 가 읽는 원본 두 속성은 클로드가 같이 채워야 한다.

「사전 검증 (나)」 개인 건 조회로 그 달 행이 이미 있으면 **기존 행 수정**이다 — `notion-update-page` 를 `command: "update_properties"` 로 호출해 `상태`·`date:납부 날짜:start`(와 필요하면 `수강료`)만 넣는다. 행이 없으면(월 마감보다 결제가 먼저 들어온 경우 등) 새로 만들되 처음부터 `상태: 납부 완료`, `date:납부 날짜:start`, `수강료` 를 전부 채운 행을 만든다 — 미납 행을 거쳤다가 바로 바꾸지 않는다.

`미납 알림`·`납부 금액` formula 가 이 두 원본 속성을 정확히 어떻게 계산하는지는 수식 내부(`formulaCode://`)를 읽을 수 없어 미확인이다 — 상태·금액을 바꾼 뒤 노션 화면에서 두 formula 가 기대대로 나오는지 원장이 한 번 확인하도록 안내한다.

### 월 마감 (재원생 전원 대상 일괄 생성)

"9월 수강료 행 만들어줘" 는 대상 범위(클래스 하나 또는 재원생 전원)의 과목 페이지마다 1행씩 **미납 상태로** 만드는 것이다.

1. **대상 범위를 정한다.** 발화에 클래스가 있으면(`name-resolution.md` 「클래스 전체 지정」) 그 클래스 소속만, 없으면("재원생 전원", "다 청구해줘") 전체 클래스를 대상으로 같은 절차를 반복해 합친다.
2. **퇴원생을 제외한다.** `name-resolution.md` 「클래스 전체 지정」 3단계의 퇴원생 제외 절차(학생 DB `date:퇴원 날짜:start` 를 먼저 뽑아 정규화한 뒤 과목 페이지 명단에서 뺀다)를 그대로 쓴다. 청구 대상 월의 시작일보다 퇴원 날짜가 앞서면 완전히 제외한다. 퇴원 날짜가 그 달 **안에** 있으면(중도 퇴원) 전액 청구할지 일할 계산할지 자동으로 정하지 않는다 — `completeness-checks.md` 「수강료 마감」행(중도 등록·퇴원 일할 계산)에 따라 되묻는다.
3. **이미 그 달 행이 있는 학생을 제외한다.** 위 「사전 검증 (나)」 월 마감용 조회로 얻는다.
4. **금액을 확인한다.** 실측 분포에서 같은 시기의 수강료가 140,000원 ~ 620,000원까지 학생마다 다르게 나타난다 — 유형·학년만 보고 금액을 하나로 단정할 수 없다. 기본값을 묻고("얼마씩 청구할까요?"), 예외가 있으면 받는다("전부 30만원인데 김서준만 25만원" 같은 발화는 `name-resolution.md` 「클래스 전체에서 일부만 예외」의 배치 규칙대로 예외를 미리보기 위쪽에 올린다). **대상에 과목 페이지를 2개 이상 가진 학생이 있으면, 금액을 묻기 전에 그 금액이 과목당인지 학생 합계인지부터 확인한다** — 청구 단위가 과목 페이지라 다과목 학생은 필연적으로 여러 행을 받는데("얼마씩"의 "씩"이 행 단위인지 학생 단위인지가 갈린다), 두 해석이 섞이면 청구액이 어긋난다.
5. 최종 명단(범위 − 퇴원생 − 기청구자)으로 미리보기 표를 만든다. 열은 **학생 / 클래스 / 금액 / 상태(전부 미납)**다. 제외한 인원이 있으면 몇 명을 왜 뺐는지 미리보기 위에 요약으로 적는다("정예린은 퇴원(8/8)으로 제외, 4명은 이미 이번 달 청구가 있어 제외"). **이 표 안에 과목 페이지를 2개 이상 받는 학생이 있으면, 표 아래에 그 학생의 합계를 한 줄 덧붙인다**(예: "김서준 2건 = 600,000원"). 30행 기준·요약 형식은 `write-gate.md` 3단계를 그대로 따른다.
6. 배치가 `write-gate.md` 5단계의 배치 상한을 넘으면 그 단계대로 나눠 만든다 — 이 스킬은 계획 전체에서 한 번에 가장 많은 행을 만드는 동작이므로, 재원생 규모가 큰 학원에서는 클래스 단위로 나눠 배치하는 편이 성공·실패 보고를 추적하기 쉽다.

### 미납 조회 (읽기 전용)

"미납 누구야" 는 쓰기가 아니라 조회다. 미리보기·승인 단계를 거치지 않는다. 어느 달 기준인지 발화에 없으면 되묻는다 — 선택지는 **이번 달 / 최근 N개월**로 좁힌다. "전체 기간"을 선택지로 두면 원장이 그걸 고르는 순간 `수강료 납부`를 통째로 SELECT하게 되어 `query-limits.md` 「행이 많은 DB는 통째로 읽지 않는다」를 어긴다 — 재원생이 많은 학원이면 이 DB가 수천 행일 수 있다. 여러 달을 봐야 하면 `납부 월`에서 대상 연월들을 먼저 읽어 얻은 뒤, 달마다 나눠 조회해 합친다.

```sql
SELECT id, "이름 붙여넣기", "수강료" FROM "collection://<수강료 납부>"
WHERE "상태" = '미납' AND "납부 월" LIKE '%<납부월 대시 없는 uuid>%'
```

`이름 붙여넣기` 는 과목 페이지 uuid 뿐이므로 사람 이름으로 보여주려면 `학생 과목별 페이지`를 거쳐 학생 이름까지 한 단계 더 조회한다(`db-map.md` 「이름이 오해를 부르는 relation」).

## 주의

- 쓰기 절차·배치 상한(100건)·되돌리기는 `../academy-core/references/write-gate.md` 4~6단계를 따른다. **되돌리기의 생성분/수정분 두 갈래도 거기 있다** — 「개인 납부 완료 처리」로 고친 기존 행은 **수정분**이라 보관 페이지로 옮기지 않고 고치기 전 값으로 되돌린다(건별 승인). 그래서 「사전 검증 (나)」 개인 건 조회로 얻은 기존 `상태`·`수강료` 를 고치기 전에 기억해 두고, `date:납부 날짜:start` 는 원래 비어 있었으면 빈 값으로 되돌린다. 월 마감으로 만든 행과 새로 만든 `납부 월` 행은 생성분이다.
- 같은 발화에 신규 등록이 함께 나오면 등록을 먼저 확정한 뒤 그 학생의 과목 페이지 위에서 수강료를 처리한다. 순서와 이유는 `../academy-core/references/routing.md` 「신규 등록 + 수강료」를 본다 — 수강료 행이 과목 페이지를 참조하기 때문이다.
