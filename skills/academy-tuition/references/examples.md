# 발화 예시

아래 날짜는 전부 2026년 8월 기준이며, **2026-08-22(오늘)는 토요일**이다. 실측 재원 명단은 다음과 같다(재원 기준 총 16개 과목 페이지). **주의**: `name-resolution.md` 「클래스 전체 지정」 2단계의 클래스별 조회는 퇴원 여부를 걸지 않으므로 원본은 정예린(퇴원)을 포함한 **17개**를 반환한다 — 3단계에서 퇴원생을 빼야 아래 16개가 된다. 아래 예시들의 인원 산술은 전부 이 17 → 16 단계를 거친 뒤의 숫자다.

| 클래스 | 재원 명단 |
|---|---|
| 중3 수학 정규 | 서다현, 윤재우, 임채원, 한소율 (4) |
| 중3 영어 내신반 | 배건우, 임채원, 한소율 (3) |
| 고2 물리 기초 | 김서준, 오지호 (2) |
| 고2 수학 심화 A | 김서준, 박시우, 이하윤, 조민준 (4) |
| 고2 영어 내신반 | 김서준, 박시우, 이하윤 (3) |

**퇴원생**: 정예린(2026-08-08 퇴원, 「고2 물리 기초」 소속이었다), 조민혁(2026-02-26 퇴원, 과목 페이지 없음). 아래 어떤 예시에도 이 둘을 신규 청구 대상으로 넣지 않는다.

**`납부 월` 실측**: 2026년 1월 ~ 2026년 8월 8건이 이미 있다. 9월·10월 행은 아직 없다.

**`수강료 납부` 실측 분포(전수 기준 요약)**:

| 납부 월 | 상태 | 행 수 | 금액 |
|---|---|---|---|
| 2026년 7월 | 납부 완료 | 11 | 280,000 ~ 620,000 |
| 2026년 8월 | 납부 완료 | 8 | 140,000 ~ 620,000 |
| 2026년 8월 | 미납 | 3 | 280,000 균일 |
| 2026년 1·2월 | 납부 완료 | 각 9 | 300,000 균일 |
| 2026년 3~6월 | 납부 완료 | 각 9 | 금액 비어 있음 |

8월은 이미 11행(완료 8 + 미납 3)이 있어 과목 페이지 16개 중 5개 자리만 비어 있다 — 8월로 새 월 마감을 시연하면 전원 중복이 나므로, 아래 월 마감·중복 제외 예시는 아직 행이 없는 **9월**을 쓴다. 같은 이유로 총점 없이 시연할 신규 시험 예시가 없듯, 수강료도 실측 범위와 모순되는 날짜로 신규 예시를 만들지 않는다.

## 1. 개인 납부 완료 — "임채원 수학 8월 수강료 냈어"

새로 시작하는 상황이다.

**발화**: "임채원 수학 8월 수강료 냈어"

**클로드가 하는 일**: 임채원은 과목 페이지가 둘(수학·영어)이지만 발화에 "수학"이 있어 되묻지 않는다. `납부 월`(2026년 8월)을 조회해 url을 얻은 뒤, 「사전 검증 (나)」 개인 건 조회로 이미 그 달 행이 있는지 본다.

```sql
SELECT id, "상태", "수강료" FROM "collection://<수강료 납부>"
WHERE "납부 월" LIKE '%<2026년 8월 대시 없는 uuid>%' AND "이름 붙여넣기" LIKE '%<임채원 중3 수학 과목 페이지 대시 없는 uuid>%'
```

**이 학생·과목의 8월 행이 미납 상태(280,000원)로 이미 있다고 하자** — 실측에 8월 미납 3건·금액 280,000 균일이 있다는 사실은 그대로이고, 그중 하나를 임채원의 것으로 연결한 것은 이 예시를 위한 가정이다. 행이 있으므로 새로 만들지 않고 수정한다 — `상태` 를 `납부 완료` 로 바꾸고 `date:납부 날짜:start` 를 오늘(8/22)로 채운다.

**미리보기**:
```
임채원(중3 수학 정규)의 8월 수강료를 납부 완료로 처리합니다(기존 행 수정).

| 학생 | 금액 | 상태(기존 → 변경) | 납부 날짜 |
|---|---|---|---|
| 임채원 | 280,000 | 미납 → 납부 완료 | (없음) → 8/22 |

이대로 처리할까요?
```

**결과**: "임채원의 8월 수강료를 납부 완료로 처리했습니다." 기존 행 수정이라 되돌리기 범위에 들지 않는다.

## 2. 월 마감 — "고2 수학 심화 A 9월 수강료 행 만들어줘"

독립 상황이다(예시 3이 바로 이어진다).

**발화**: "고2 수학 심화 A 9월 수강료 행 만들어줘"

**클로드가 하는 일**: `납부 월`에서 `2026년 9월`을 조회한다. 0행 — 새로 만든다(title `납부 년월`을 `2026년 9월`로 채운다). 대상 범위는 「고2 수학 심화 A」로 한정된다 — `name-resolution.md` 「클래스 전체 지정」으로 소속 학생(김서준, 박시우, 이하윤, 조민준)을 얻는다. 이 반에는 퇴원생이 없다. 이미 9월 행이 있는 학생도 없다(9월은 아직 0행). 금액을 묻는다.

> 얼마씩 청구할까요?

원장이 "다 30만원이야"라고 답한다.

**미리보기**:
```
납부 월에 1건(2026년 9월)을 만들고, 수강료 납부에 4행을 만듭니다.

| 학생 | 클래스 | 금액 | 상태 |
|---|---|---|---|
| 김서준 | 고2 수학 심화 A | 300,000 | 미납 |
| 박시우 | 고2 수학 심화 A | 300,000 | 미납 |
| 이하윤 | 고2 수학 심화 A | 300,000 | 미납 |
| 조민준 | 고2 수학 심화 A | 300,000 | 미납 |

이대로 만들까요?
```

**결과**: "납부 월 1건과 수강료 납부 4행을 만들었습니다. 잘못됐으면 \"방금 거 취소해줘\" 라고 말씀하세요."

## 3. 중복 제외 — "이번엔 전체 재원생 9월 수강료도 다 만들어줘"

예시 2에 바로 이어지는 상황이다.

**발화**: "이번엔 전체 재원생 9월 수강료도 다 만들어줘"

**클로드가 하는 일**: 대상 범위가 전체 클래스로 넓어진다. 클래스별로 「클래스 전체 지정」 2단계를 반복해(퇴원생 포함) **17개** 과목 페이지를 얻고, 3단계로 퇴원생을 뺀다 — 정예린(2026-08-08 퇴원, 「고2 물리 기초」)은 9월 시작(9/1)보다 퇴원이 앞서므로 완전히 제외한다(**16개** 남음). 조민혁은 과목 페이지가 없어 애초에 후보에 없다. 이어서 「사전 검증 (나)」 월 마감용 조회로 9월 기청구자를 확인한다.

```sql
SELECT id, "이름 붙여넣기" FROM "collection://<수강료 납부>" WHERE "납부 월" LIKE '%<2026년 9월 대시 없는 uuid>%'
```

예시 2에서 만든 「고2 수학 심화 A」 4행(김서준, 박시우, 이하윤, 조민준)이 걸린다. 16개 후보에서 이 4명을 빼면 **12명**이 남는다. 이 범위에는 김서준처럼 과목 페이지를 여럿 가진 학생(물리·영어)이 섞여 있으므로, 금액을 묻기 전에 단위부터 확인한다.

> 나머지 12명도 얼마씩 청구할까요? 그리고 과목당 금액인가요, 학생당 합계인가요?

원장이 "과목당 30만원씩, 똑같이"라고 답한다.

**미리보기**:
```
수강료 납부에 12행을 만듭니다(정예린은 퇴원(8/8)으로 제외, 김서준·박시우·이하윤·조민준은 이미 9월 청구가 있어 제외).

| 학생 | 클래스 | 금액 | 상태 |
|---|---|---|---|
| 서다현 | 중3 수학 정규 | 300,000 | 미납 |
| 윤재우 | 중3 수학 정규 | 300,000 | 미납 |
| 임채원 | 중3 수학 정규 | 300,000 | 미납 |
| 한소율 | 중3 수학 정규 | 300,000 | 미납 |
| 배건우 | 중3 영어 내신반 | 300,000 | 미납 |
| 임채원 | 중3 영어 내신반 | 300,000 | 미납 |
| 한소율 | 중3 영어 내신반 | 300,000 | 미납 |
| 김서준 | 고2 물리 기초 | 300,000 | 미납 |
| 오지호 | 고2 물리 기초 | 300,000 | 미납 |
| 김서준 | 고2 영어 내신반 | 300,000 | 미납 |
| 박시우 | 고2 영어 내신반 | 300,000 | 미납 |
| 이하윤 | 고2 영어 내신반 | 300,000 | 미납 |

이 표에서 김서준은 2건(물리·영어) = 600,000원이다.

이대로 만들까요?
```

행이 12개라 30행 기준(`write-gate.md` 3단계) 안에 들어 전부 보여준다.

**결과**: "수강료 납부에 12행을 만들었습니다. 이미 청구된 4명은 건드리지 않았습니다. 김서준은 9월에 총 3건(수학·물리·영어, 합 900,000원)입니다. 잘못됐으면 \"방금 거 취소해줘\" 라고 말씀하세요." 이제 9월 16개 과목 페이지 전원이 청구된 상태다.

## 4. 금액 예외 — "중3 영어 내신반 9월 수강료 행 만들어줘, 다 30만원인데 배건우만 25만원"

독립 상황이다 — 예시 2·3과는 별개의 가정이다. 예시 2·3이 이미 9월을 처리했다는 것을 전제하지 않고, 실측 범위(1~8월)만 기준으로 다시 시작한다. 예시 2가 쓴 클래스(고2 수학 심화 A)와 겹치지 않도록 다른 클래스를 쓴다.

**발화**: "중3 영어 내신반 9월 수강료 행 만들어줘, 다 30만원인데 배건우만 25만원"

**클로드가 하는 일**: `납부 월`을 통째로 읽어 `2026년 9월`을 찾는다. 실측 범위(1~8월)엔 없으므로 0행 — 새로 만든다. 「중3 영어 내신반」소속은 배건우, 임채원, 한소율 셋이고 퇴원생은 없다. 9월 행이 아직 없으므로 「사전 검증 (나)」 결과도 0행이다. 이 클래스는 학생마다 과목 페이지가 하나씩만 걸리므로(임채원·한소율도 이 청구에서는 영어 한 건뿐) 「금액을 확인한다」의 과목당/학생당 구분은 여기선 갈리지 않는다. 금액은 이미 발화에 있다 — 기본값 300,000원에 배건우만 250,000원 예외다. `name-resolution.md` 「클래스 전체에서 일부만 예외」에 따라 예외 행을 표 위쪽에 올린다.

**미리보기**:
```
납부 월에 1건(2026년 9월)을 만들고, 수강료 납부에 3행을 만듭니다.

| 학생 | 클래스 | 금액 | 상태 |
|---|---|---|---|
| 배건우 | 중3 영어 내신반 | 250,000 (예외) | 미납 |
| 임채원 | 중3 영어 내신반 | 300,000 | 미납 |
| 한소율 | 중3 영어 내신반 | 300,000 | 미납 |

이대로 만들까요?
```

**결과**: "납부 월 1건과 수강료 납부 3행을 만들었습니다. 잘못됐으면 \"방금 거 취소해줘\" 라고 말씀하세요."

## 5. 미납 조회 — "미납 누구야"

독립 상황이다. 쓰기가 아니라 조회이므로 미리보기·승인 단계가 없다.

**발화**: "미납 누구야"

**클로드가 하는 일**: 어느 달 기준인지 발화에 없으므로 되묻는다 — "전체 기간"은 선택지에 넣지 않는다(`수강료 납부`를 통째로 읽게 되기 때문이다).

> 이번 달(8월) 기준으로 볼까요, 아니면 최근 몇 개월을 볼까요?

원장이 "이번 달"이라고 답한다. `납부 월`에서 `2026년 8월`의 url을 얻어 조회한다.

```sql
SELECT id, "이름 붙여넣기", "수강료" FROM "collection://<수강료 납부>"
WHERE "상태" = '미납' AND "납부 월" LIKE '%<2026년 8월 대시 없는 uuid>%'
```

3건이 나온다(실측과 일치 — 8월 미납은 정확히 3건, 금액 280,000 균일). `이름 붙여넣기` 는 과목 페이지 uuid 뿐이므로 `학생 과목별 페이지`를 한 번 더 조회해 이름으로 바꾼다. **아래 학생 이름은 이 조회 결과를 보여주는 형식을 설명하기 위한 가정이다** — 실제 이름은 조회해야 알 수 있다.

**결과** (쓰기 없음, 바로 보고):
```
8월 미납은 3명입니다. 전원 280,000원.

| 학생 | 클래스 | 금액 |
|---|---|---|
| (조회 결과 1) | ... | 280,000 |
| (조회 결과 2) | ... | 280,000 |
| (조회 결과 3) | ... | 280,000 |
```
