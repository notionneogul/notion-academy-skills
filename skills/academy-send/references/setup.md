# setup.md — 발송 세팅

한 번만 하는 절차다. 여섯 단계를 순서대로 하고, 결과는 전부 `~/.academy/config.json` 의 `send` 키 한 곳에 모인다. 키 규격(어느 이름에 무엇을 넣는지, `send` 가 선택 키라는 것)은 `../../academy-core/references/db-map.md` 「설정 파일 규격」이 권위 목록이다 — 여기서는 그 값을 어떻게 얻는지만 적는다.

`send` 키를 새로 만들 때 **`databases`·`message_formats`·`root_page` 등 기존 키는 그대로 둔다.** 파일을 통째로 다시 쓰지 않고 `send` 만 더한다.

어느 단계에서 막히든 **그 단계에서 멈추고 알린다.** 반쯤 채워진 `send` 키는 발송이 되는 것처럼 보이다가 학부모에게 빈칸이 나가는 상태다.

## 1. API 키

Solapi 콘솔의 API Key 관리에서 원장이 발급한다. 발급한 `api_key`·`api_secret` 을 **원장이 `~/.academy/config.json` 을 열어 `send.api_key`·`send.api_secret` 에 직접 넣는다.**

- **클로드는 키를 받아 적지 않는다.** 원장이 채팅에 붙여넣더라도 그 값을 파일에 쓰지 않고, 설정 파일에 직접 넣어 달라고 안내한다. 이미 붙여넣은 값은 답장에 되풀이하지 않는다.
- 넣었다고 하면 파일을 읽어 **존재만** 확인한다 — 두 값이 다 있고 비어 있지 않은지. **값을 화면에 출력하지 않는다.** 앞 네 글자나 글자 수도 적지 않는다.
- 키가 실제로 유효한지는 읽기만 하는 호출 한 번으로 본다: `GET /messages/v4/groups`. 200 이면 인증이 통과한 것이고, 401·403 이면 "키가 맞지 않는다"고만 알린다. 오류 응답 본문에 키 일부가 섞여 오면 그 부분은 옮기지 않는다.

`api_secret` 은 서명을 만들 때만 쓰고 요청 어디에도 실어 보내지 않는다(아래 「호출 형식」).

## 2. 발신 프로필

알림톡은 카카오 채널의 **발신프로필 키**로 나가고, 문자는 사전 등록된 **발신번호**로 나간다. 둘 다 원장이 콘솔 화면에서 읽어 준다.

- 콘솔의 카카오 알림톡 → 발신프로필 목록에서 발신프로필 키를 복사해 `send.sender_key` 에 넣는다.
- 등록·인증이 끝난 발신번호를 `send.sender_phone` 에 넣는다. 알림톡이 실패해 문자로 나갈 때와 자유 문장을 문자로 보낼 때의 발신번호다.
- **프로필이 여럿이면 원장에게 어느 채널로 나가야 하는지 묻는다.** 클로드가 고르지 않는다. 학원 채널이 아닌 프로필로 나가면 학부모에게 낯선 이름으로 도착한다.

**발신 프로필 목록을 불러오는 엔드포인트는 이 문서에 확정돼 있지 않다.** 확정된 것은 아래 「호출 형식」의 엔드포인트 표에 실린 것뿐이다 — 목록을 보려고 경로를 추측해 호출하지 않는다. 값은 원장이 콘솔에서 읽어 주고, 맞는지는 6단계 시험 발송으로 확인한다.

**채널별 건당 단가도 이 자리에서 함께 받는다.** 알림톡과 문자의 요금이 다르고, **Solapi 에 단가를 알려 주는 경로가 없다** — 발신 프로필·템플릿과 마찬가지로 원장이 콘솔의 요금 안내에서 읽어 준다. 값을 넣는 이름과 모양은 `../../academy-core/references/db-map.md` 「설정 파일 규격」의 `unit_price` 를 따른다.

- 두 채널의 단가를 각각 묻는다. **클로드가 시세를 기억해 채우지 않는다** — 요금제와 계약에 따라 다르다.
- 이 값이 비면 발송 미리보기가 예상 요금을 계산하지 못하고, 그러면 **그 미리보기는 승인 요청이 되지 못한다.** 세팅에서 채우고 넘어간다.

## 3. 우피 도메인

알림톡 버튼 URL 이 여기서 조립된다. 한 번 묻고 `send.oopy_domain` 에 저장한다.

- 형식은 `https://` 를 포함하고 끝에 슬래시를 붙이지 않는다(예: `https://academy.oopy.io`).
- 조립 규칙은 `../../academy-core/references/db-map.md` 「설정 파일 규격」에 있다. 버튼은 둘 — 「학생 개별 페이지」와 「클래스 공지」.
- **도메인을 추측해서 만들지 않는다.** 원장이 모르면 비워 두고 넘어가되, 비어 있으면 버튼 URL 을 채울 수 없다는 것을 발송 전에 알린다.
- 같은 값을 `academy-message` 도 읽는다(`#{개별페이지링크}` 조립). 여기서 정한 값이 그쪽에도 그대로 쓰인다.

## 4. 템플릿 고르기

콘솔의 알림톡 템플릿 목록에는 **학원과 무관한 것이 섞여 있다.** 한 계정을 다른 사업에도 쓰고 있으면 파일 전송·입금 완료·후기 안내 같은 템플릿이 함께 보인다. 실측 계정에서는 학원용이 「2026 학원관리」(2026.06.30 등록) 하나였고 나머지 일곱은 다른 사업 것이었다.

- **원장이 학원용만 고른다.** 클로드가 이름만 보고 학원용이라고 단정하지 않는다 — 「학원 템플릿 자동화 테스트」처럼 학원이라는 낱말이 들어간 시험용 템플릿이 섞여 있다.
- 고른 템플릿마다 **상황 이름표**를 붙인다. 원장이 발화에서 부를 이름이다(예: `주간 리포트`).
- `send.templates` 에 상황 이름표를 키로 저장한다. 값의 모양은 `../../academy-core/references/db-map.md` 「설정 파일 규격」을 본다.

**템플릿 목록을 불러오는 엔드포인트도 이 문서에 확정돼 있지 않다.** 2단계와 같다 — 원장이 콘솔에서 읽어 주고, 경로를 추측해 호출하지 않는다.

## 5. 변수 확인

**매핑이 아니라 확인이다. 매핑 표를 만들지 않는다.**

「2026 학원관리」의 변수 11개는 노션 `문자 양식` 의 토큰과 **글자까지 같다.**

`#{최근출결상태}` · `#{최근시험명}` · `#{최근성적}` · `#{최근평균}` · `#{최근시험피드백}` · `#{저번과제}` · `#{저번과제평가}` · `#{저번과제피드백}` · `#{최근수업}` · `#{최근과제안내}` · `#{특이사항}`

이름이 이미 같으므로 **대부분 그대로 통과한다.** 원장이 고른 템플릿의 변수를 이 11개와 대조해서, **다른 것이 있을 때만** 그 변수 하나에 무엇을 넣을지 묻는다. 같은 것은 묻지 않고 넘어간다.

이름이 하나라도 어긋나면 그 자리는 빈 채로 학부모에게 나간다. 그래서 확인은 발송 전에 하고, 결과는 6단계에서 눈으로 다시 본다.

이 값들은 전부 `학생 과목별 페이지` 의 formula 라 쿼리로 읽을 수 없다(`../../academy-core/references/query-limits.md`). 원본 데이터를 읽어 클로드가 만든다.

## 6. 시험 발송 1건

**원장 자신의 번호로** 보낸다. **학부모에게 먼저 보내지 않는다.** 세팅이 틀렸을 때 그 결과를 받는 사람이 원장이어야 한다.

학생 한 명의 실제 데이터로 채우되 받는 번호만 원장 자신의 번호로 바꾼다. 보내기 전에 잔액을 확인한다(아래 「호출 형식」의 잔액 조회 경로) — 모자라면 발송이 실패한다.

도착한 문자에서 네 가지를 확인한다.

1. 도착하는가 — 발신 프로필과 발신번호가 맞는지 여기서 드러난다(2단계).
2. 변수 자리가 채워졌는가 — 빈칸이나 `#{...}` 가 남아 있으면 5단계로 돌아간다.
3. **버튼 둘(「학생 개별 페이지」·「클래스 공지」)을 실제로 눌러 열리는가** — 도메인이 틀리면 여기서 드러난다(3단계).
4. 잔액이 줄었는가.

**시험 발송이 실패하거나 위 넷 중 하나라도 어긋나면 세팅을 끝내지 않는다.** 어느 단계로 돌아가야 하는지 알리고 그 단계부터 다시 한다. 넷이 다 맞으면 `send` 키가 완성된 것으로 본다 — 그 뒤의 실제 발송은 매번 미리보기와 승인을 거친다.

## 호출 형식

공식 SDK 소스로 확정한 것이다. **추측으로 바꾸지 않는다.** 기준 주소는 `https://api.solapi.com` 이다.

### 인증 헤더

```
Authorization: HMAC-SHA256 ApiKey=<api_key>, Date=<date>, salt=<salt>, signature=<signature>
```

- `date` — ISO 8601, 타임존 오프셋 포함
- `salt` — 임의 고유 문자열
- `signature` — `HMAC-SHA256(api_secret, date + salt)` 를 hex 로. **서명 대상은 `date` 와 `salt` 를 이어 붙인 문자열뿐이다. 본문은 들어가지 않는다**

### 엔드포인트

| 할 일 | 메서드 | 경로 |
|---|---|---|
| 발송·예약 | POST | `/messages/v4/send-many/detail` |
| 예약 취소 | DELETE | `/messages/v4/groups/{groupId}/schedule` |
| 그룹 목록 | GET | `/messages/v4/groups` |
| 그룹 하나 | GET | `/messages/v4/groups/{groupId}` |
| 그룹 안의 메시지 | GET | `/messages/v4/groups/{groupId}/messages` |
| 잔액 조회 | GET | `/cash/v1/balance` |

잔액 조회 응답은 `{"balance": <숫자>, "point": <숫자>}` 다. **건당 단가는 어느 응답에도 없다** — `send.unit_price` 로 원장에게 받는다(위 2단계).

**이 표 밖의 경로는 확정된 것이 없다.** 필요해 보여도 만들어 내지 않고, 그 값은 원장이 콘솔에서 읽어 주는 것으로 대신한다.
