# 출결 입력

## 시작 전에 읽는다

- `../academy-core/references/db-map.md` — DB id 를 얻는다. `출석부` 의 `collection://<uuid>` 가 여기 있다
- `../academy-core/references/write-gate.md` — 쓰기 관문 일곱 단계(되물음 → 사전 검증 → 미리보기 표 → 승인 → 쓰기 → 결과 보고 → 남은 항목 확인). 이 스킬은 이 절차를 그대로 따르되, 아래 「절차」에는 이 스킬 고유의 것만 적는다
- `../academy-core/references/name-resolution.md` — 발화의 사람 이름을 `학생` relation에 넣을 **과목 페이지** url로 바꾸는 절차
- `../academy-core/references/query-limits.md` — 조회를 시작하기 전에 반드시 읽는다. JOIN 금지, `date:<속성>:start` 컬럼명, relation uuid 정규화, formula·rollup 조회 불가가 여기 있다
- `../academy-core/references/domain-rules.md` — 클래스 요일 정합, 보강 자동화 규칙의 판정 기준
- `../academy-core/references/completeness-checks.md` — 필수·되물음·공란 허용 세 분류
- `../academy-core/references/write-safety.md` — 쓰기 동작의 자율·승인 경계

`~/.academy/config.json` 이 없으면 즉시 멈추고 `academy-setup` 을 안내한다.

## 언제 쓰나

- "고2 수학 전체 출석"
- "김서준 오늘 지각"
- "어제 이하윤 결석으로 바꿔줘"
- "8월 20일 결석한 애들 보강 잡아줘"

## 쓰는 속성

대상 DB는 `출석부`. 아래 다섯 속성만 쓴다.

| 속성 | 타입 | 값 |
|---|---|---|
| `date:출석 날짜:start` | date | 출결이 발생한 날짜(`YYYY-MM-DD`) |
| `출결상태` | select | `출석` / `지각` / `미출석` / `보강` 중 하나 |
| `학생` | relation → **학생 과목별 페이지** | `name-resolution.md` 로 얻은 과목 페이지 url. relation 값은 한 건이어도 배열로 감싼다(`["https://.../<uuid>"]`) |
| `date:보강 날짜:start` | date | 보강을 예약할 때만 채운다 |
| `보강완료` | checkbox | 보강 수업을 실제로 마친 뒤에만 체크한다. 쓰기 형식은 아래를 본다 |

`date:<속성>:start` 표기는 조회 쿼리뿐 아니라 `notion-create-pages`·`notion-update-page` 의 `properties` 키로도 그대로 쓴다 — 두 도구 모두 date 속성을 `date:{property}:start`(및 필요하면 `:end`, `:is_datetime`) 로 나눠 받는다. 실측 확인: `notion-create-pages` 로 만든 행이 `"date:출석 날짜:start":"2026-08-22"` 로 그대로 반환됐다.

**`보강완료` 는 쓸 때도 `"__YES__"` / `"__NO__"` 문자열이다.** 실측 확인: `notion-create-pages` 로 `"보강완료": "__YES__"` 를 넘겨 행을 만들자 응답이 `"보강완료":"__YES__"` 로 그대로 반환됐다(2026-08-22 확인, 확인 후 그 행은 보관 페이지로 옮겨 정리했다). 조회 결과 표기(`typeof()` 전수 129행)와 쓰기 입력 형식이 같다.

**쓰지 않는 것.** 쓰기 불가 속성의 권위 목록은 `../academy-core/references/db-map.md` 「DB별 쓰기 불가 속성」이다. `출석부` 줄은 `보강 디데이`·`출석 문자`(formula)와 `클래스`(rollup)다 — `학생` relation만 채우면 클래스는 화면에 자동으로 따라온다. 그 밖에 title 속성은 이름이 빈 문자열이고 실측 표본 전부 비어 있다 — 채우지 않는다. 실측으로도 title 을 넘기지 않으면 자동으로 `""` 로 설정된다.

## 절차

`write-gate.md` 일곱 단계를 그대로 따른다. 아래는 이 스킬에서 각 단계가 구체적으로 무엇을 확인·채우는지, 이 스킬 고유의 것만 적는다.

### 되물음 (1단계)

필수 항목은 `write-gate.md` 1단계 표를 따른다. 그 외에 지각·미출석인데 보강 날짜가 없으면 한 번 확인한다(`../academy-core/references/completeness-checks.md` 「되물음」 분류) — "보강 날짜를 지금 잡을까요, 나중에 잡을까요?" 기본값은 비워 두는 쪽이다.

발화에 "결석"이 나오면 `출결상태` 값으로 바로 쓰지 않는다. select 옵션에는 `출석`·`지각`·`미출석`·`보강` 넷뿐이고 "결석"은 없다. **구어체 "결석"은 `미출석`으로 매핑한다.**

학생 이름만 있고 클래스가 없어도, **그날 수업이 있는 과목 페이지가 하나뿐이면** 되묻지 않는다(`name-resolution.md` 「학생 이름으로 지정」 4단계의 날짜 기반 예외). 예시 1·4가 이 예외를 쓴다.

### 사전 검증 (2단계)

`write-gate.md` 의 (가)·(나)·(라)를 전부 한다. (다) 직전 과제 검증은 `academy-homework` 전용이라 이 스킬과 무관하다.

- **(가) 수업일 대조.** `출석 날짜`에만 적용한다. `보강 날짜`는 이 대조 대상이 아니다(`domain-rules.md` 「클래스 요일 정합」).
- **(나) 중복.** 실측으로 확인한 조회:

  ```sql
  SELECT id, "출결상태" FROM "collection://<출석부>" WHERE "date:출석 날짜:start" = '<날짜>' AND "학생" LIKE '%<과목 페이지 대시 없는 uuid>%'
  ```

  걸리면 전환할 경로는 아래 「수정」 절이다.
- **(라) 퇴원 — 한다.** 판정은 `../academy-core/references/write-gate.md` 2단계 (라)를 따른다. 출결은 `domain-rules.md` 「퇴원 정합」의 대상이고, "정예린 오늘 지각" 처럼 이름으로 지목한 발화가 이 검증이 없으면 그대로 통과한다 — 퇴원 날짜는 `name-resolution.md` 「학생 이름으로 지정」 1단계 쿼리에서 이미 읽는다.

### 미리보기 표 (3단계)

신규 생성 시 기본 열은 **학생 / 날짜 / 출결 / 클래스**다. 수정·보강처럼 기존 값이 바뀌는 경우에는 무엇이 바뀌는지 보이도록 열을 바꾼다(예시 4·7 참고). 전체 반에 예외가 섞이면 `name-resolution.md` 「클래스 전체에서 일부만 예외」의 배치 규칙(예외를 위로)을 따른다. 30행 기준·요약 형식은 `write-gate.md` 3단계를 그대로 따른다.

### 보강 처리

"8월 20일 결석한 애들 8월 27일에 보강" 같은 발화는 새 행을 만드는 게 아니라 **기존 미출석·지각 행을 찾아 `보강 날짜` 만 채우는 수정이다.** 이 필드가 어떻게 `출결상태` 를 바꾸는지는 `../academy-core/references/domain-rules.md` 「보강 자동화」를 본다 — 그래서 보강은 신규 생성이 아니라 기존 행 수정이다.

**`보강완료` 를 체크할 때는 `보강 날짜` 가 반드시 채워져 있어야 한다.** 반대로 `보강 날짜` 만 채우는 것(보강 예약)은 정상이다 — 예시 7이 이 경우다. 보강 수업을 실제로 마친 뒤에만 `보강완료` 를 체크한다(`domain-rules.md` 「보강 자동화」).

### 수정 (기존 행 고치기)

"어제 이하윤 결석 아니라 지각이었어" 는 새 행을 만드는 게 아니라 기존 행의 `출결상태` 를 바꾸는 것이다.

1. 해당 날짜·해당 과목 페이지로 출석부를 조회한다(사전 검증 (나) 와 같은 조회를 재사용한다).
2. 행이 없으면 「쓰기」 절차대로 새로 만든다. 행이 있으면 그 행의 `id` 로 `notion-update-page` 를 `command: "update_properties"` 로 호출해 바뀌는 속성만 넣는다. 나머지 속성은 생략하면 그대로 유지된다.
3. 승인 경계는 `../academy-core/references/write-safety.md` 「기존 행 수정: 건별 승인」을 따른다 — 미리보기 표에 그 행을 "기존 행 수정"으로 표시해 원장이 무엇이 바뀌는지 보고 승인하게 한다.

## 주의

- 쓰기 절차·배치 상한(100건)·되돌리기는 `../academy-core/references/write-gate.md` 4~6단계를 따른다. **되돌리기의 생성분/수정분 두 갈래도 거기 있다** — 「수정」 절차로 고친 기존 행은 **수정분**이라 보관 페이지로 옮기지 않고 고치기 전 값으로 되돌린다(건별 승인). 그래서 고치기 전에 기존 `출결상태`·`보강 날짜` 값을 먼저 읽어 둔다.
- 같은 발화에 진도·과제나 시험 점수가 함께 나오면, 출결을 먼저 확정한 뒤 그 명단 위에서 다음 스킬로 넘어간다. 순서와 넘기는 방법은 `../academy-core/references/routing.md` 를 본다.
