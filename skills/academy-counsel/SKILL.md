# 상담 입력

## 시작 전에 읽는다

- `../academy-core/references/db-map.md` — DB id 를 얻는다. `재원생 상담` 의 `collection://<uuid>` 가 여기 있다
- `../academy-core/references/write-gate.md` — 쓰기 관문 일곱 단계(되물음 → 사전 검증 → 미리보기 표 → 승인 → 쓰기 → 결과 보고 → 남은 항목 확인). 이 스킬은 이 절차를 그대로 따르되, 아래 「절차」에는 이 스킬 고유의 것만 적는다
- `../academy-core/references/name-resolution.md` — 발화의 사람 이름을 `이름 붙여넣기` relation에 넣을 **과목 페이지** url로 바꾸는 절차
- `../academy-core/references/query-limits.md` — 조회를 시작하기 전에 반드시 읽는다. JOIN 금지, `date:<속성>:start` 컬럼명, relation uuid 정규화, formula·rollup 조회 불가가 여기 있다
- `../academy-core/references/domain-rules.md` — 쓰기 불가 속성 판정 기준. 클래스 요일 정합·점수 상한은 이 스킬에 적용되지 않고, 퇴원 정합은 대상 목록(출결·과제·시험·수강료)에 상담이 없어 막지 않되 알리는 형태로 적용된다(아래 「사전 검증」 참고)
- `../academy-core/references/completeness-checks.md` — 필수·되물음·공란 허용 세 분류
- `../academy-core/references/write-safety.md` — 쓰기 동작의 자율·승인 경계

`~/.academy/config.json` 이 없으면 즉시 멈추고 `academy-setup` 을 안내한다.

## 언제 쓰나

- "김서준 어머니 상담했어. 수학 성적 걱정하시고 주 1회 추가 보강 원하심"
- "오늘 상담 기록 넣어줘"
- "저번 상담 기록에 한 줄 추가해줘"

## 쓰는 속성

대상 DB는 `재원생 상담`. 아래 세 속성만 쓴다.

| 속성 | 타입 | 값 |
|---|---|---|
| `date:상담 날짜:start` | date | 상담이 있었던 날짜(`YYYY-MM-DD`) |
| `상담 기록` | text | 원장이 말한 내용을 문장으로 다듬은 것 |
| `이름 붙여넣기` | relation → **학생 과목별 페이지** | `name-resolution.md` 로 얻은 과목 페이지 url. 한 건이어도 배열로 감싼다(`["https://.../<uuid>"]`) |

`date:<속성>:start` 표기는 `notion-create-pages`·`notion-update-page` 의 `properties` 키로도 그대로 쓴다. relation 은 대시 없는 uuid 가 아니라 **페이지 url 배열**을 넣는다.

**쓰지 않는 것.** 쓰기 불가 속성의 권위 목록은 `../academy-core/references/db-map.md` 「DB별 쓰기 불가 속성」이다. `재원생 상담` 줄은 `필터`(formula)와 `클래스`(rollup)다. 그 밖에 title(빈 이름 속성)은 채우지 않는다 — 넘기지 않으면 자동으로 `""` 가 된다.

## 절차

`write-gate.md` 일곱 단계를 그대로 따른다. 아래는 이 스킬 고유의 것만 적는다.

### 사전 검증 (2단계)

이 스킬은 `write-gate.md` 2단계 네 검증 중 어느 것도 그대로 쓰지 않는다 — (나)와 (라)는 형태를 바꿔서 한다.

- **(가) 수업일 대조 — 적용하지 않는다.** `domain-rules.md` 「클래스 요일 정합」의 적용 대상은 출결·과제·시험뿐이다. 상담은 주말 학부모 통화나 방문 상담처럼 수업일과 무관하게 발생하므로 요일을 대조하지 않는다.
- **(나) 중복 — 차단하지 않고 경고한다.** `write-gate.md` 2단계의 (나)는 원래도 자동 중단이 아니라 경고다. 상담은 로그성 기록이라 같은 날 같은 학생에게 여러 건이 있는 것이 정상이지만(오전 전화 상담 + 오후 방문 상담 등), 새 행을 만들기 전에 같은 날·같은 과목 페이지 상담이 이미 있는지 한 번은 조회해 있으면 알린다 — 그렇지 않으면 같은 상담을 다시 말하거나 세션을 다시 열었을 때 조용히 중복 행이 생긴다.

  ```sql
  SELECT id, "상담 기록" FROM "collection://<재원생 상담>"
  WHERE "date:상담 날짜:start" = '<날짜>' AND "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'
  ```

  걸리면 막지 않고 되묻는다.

  > 오늘 이 학생 상담이 이미 1건 있습니다. 새 상담인가요, 그 기록에 이어 붙일까요?

  "이어 붙일까요"를 고르면 아래 「과거 상담 기록 수정」으로 넘어간다. "새 상담"을 고르면 그대로 새 행을 만든다. 처음부터 "저번 상담 기록에 한 줄 추가해줘"처럼 **기존 기록 수정**을 원하는 발화면 이 조회 없이 바로 「과거 상담 기록 수정」으로 간다.
- **(다) 직전 과제 — 해당 없음.** `academy-homework` 전용이다.
- **(라) 퇴원 — 막지 않되 알린다.** `domain-rules.md` 「퇴원 정합」의 대상은 출결·과제·시험·수강료이고 상담은 빠져 있다 — 퇴원 사유 확인·종료 상담처럼 퇴원일 이후에도 정당한 상담이 있기 때문이다. 그래서 퇴원 날짜 이후 시점의 상담이어도 막지 않지만, 미리보기에 "퇴원(날짜) 이후 상담입니다"라고 한 줄 알린다 — 원장이 날짜를 착각한 경우(퇴원 처리 전에 있었던 상담을 뒤늦게 입력하려던 경우 등)를 눈으로 잡을 수 있게 한다.

### 지어내지 않는다

`상담 기록`에는 원장이 실제로 말한 내용만 문장으로 다듬어 넣는다. 원장이 언급하지 않은 판단·평가·감정을 채우지 않는다 — "학부모님이 만족하셨다", "아이가 힘들어한다" 같은 문장은 원장이 그렇게 말했을 때만 쓴다. 발화가 짧으면 문장도 짧게 다듬는다. 빠진 맥락을 그럴듯하게 채워 넣지 않는다.

### 템플릿 안내문 구별

`상담 기록`을 읽어 최근 상담을 파악해야 하는 상황(「과거 상담 기록 수정」, 다른 스킬로의 인계)에서, 값이 `상담 내용 입력`·`상담 내용을 편하게 쭉 작성하기`·`상담 내용 작성하기`처럼 노션 템플릿이 기본으로 넣어 둔 안내문이면 실제 상담 기록으로 읽지 않는다. 구매자가 템플릿을 막 복제한 상태에서는 이런 안내문이 남아 있는 행이 실제 기록보다 많을 수 있다. 안내문으로 보이는 값을 만나면 "아직 실제 상담이 기록되지 않은 것 같다"고 원장에게 알리고, 그 행을 이전 상담으로 취급하지 않는다.

### 과목이 여럿인 학생

상담은 보통 학생 단위로 이뤄지는데 `이름 붙여넣기` relation은 과목 페이지를 가리킨다. 학생이 과목 페이지를 하나만 가지고 있으면 그것으로 정한다. 둘 이상이면(`name-resolution.md` 「학생 이름으로 지정」 4단계) 발화에 과목이 이미 있으면 그것을 쓰고, 없으면 어느 과목 상담인지 되묻는다. 상담 내용이 특정 과목을 가리키는 단어(예: "수학 성적", "영어 단어")를 담고 있으면 그것도 과목 판단의 근거로 쓴다.

### 과거 상담 기록 수정

"저번 상담 기록에 한 줄 추가해줘"는 새 행을 만드는 것이 아니라 그 학생의 **가장 최근 상담 행을 찾아 수정**하는 것이다.

```sql
SELECT id, url, "date:상담 날짜:start", "상담 기록"
FROM "collection://<재원생 상담>"
WHERE "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'
ORDER BY "date:상담 날짜:start" DESC LIMIT 1
```

조회한 값이 「템플릿 안내문 구별」에 해당하면 이어붙일 실제 기록이 없다는 뜻이므로, 이어붙이지 말고 새 상담으로 취급할지 원장에게 확인한다.

`상담 기록`은 text 속성이라 **부분 추가가 아니라 전체 값을 다시 써야 한다.** 기존 문장 뒤에 원장이 준 새 문장을 이어 붙인 전체 텍스트를 만든 뒤, `notion-update-page` 를 `command: "update_properties"` 로 호출해 `상담 기록` 하나만 넣는다. 다른 속성은 생략하면 유지된다. 이 수정이 **같은 실행에서 방금 자기가 만든 행**을 고치는 것이면 `write-safety.md` 표의 「이번 실행에서 자기가 만든 행 수정」(자율)에 따라 승인 없이 진행하고, **이전 실행에서 만든 기존 행**을 고치는 것이면 같은 표의 「기존 행 수정」(건별 승인)을 따른다.

## 주의

- 쓰기 절차·배치 상한(100건)·되돌리기는 `../academy-core/references/write-gate.md` 4~6단계를 따른다. **되돌리기의 생성분/수정분 두 갈래도 거기 있다** — 「과거 상담 기록 수정」으로 고친 기존 행은 **수정분**이라 보관 페이지로 옮기지 않고 고치기 전 값으로 되돌린다(건별 승인). 이 스킬은 이어붙이기 전에 기존 `상담 기록` 전문을 이미 읽으므로(text 는 부분 추가가 안 된다) 그 값이 그대로 되돌리기의 재료다.
- 같은 발화에 문자 발송이 함께 나오면 상담을 먼저 확정한 뒤 넘긴다. 순서와 이유는 `../academy-core/references/routing.md` 「상담 + 문자」를 본다 — 문자가 최근 상담 내용을 읽기 때문이다.
