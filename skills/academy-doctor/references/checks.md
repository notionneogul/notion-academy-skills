# checks.md — 검사 항목

**먼저 `../../academy-core/references/query-limits.md` 를 읽는다.** 노션 쿼리 도구의 제약(JOIN 금지, 날짜 컬럼명, relation uuid 정규화, formula·rollup 조회 불가, 연월 문자열 비교, 큰 DB 조회 범위)이 전부 거기 있다. 아래 조회 방법은 그 제약을 이미 지킨 형태로 적혀 있다.

각 항목은 SQL로 건수를 먼저 세고, 예시가 필요하면 `LIMIT 3` 을 붙여 상세 조회한다. `<DB명>` 은 `~/.academy/config.json` 의 `databases` 값(`collection://<uuid>`)으로 치환한다.

정합성 위반 항목의 조회 절차는 academy-core 스킬의 `references` 폴더에 있는 `domain-rules.md` 의 "검증 방법" 열과 동일한 판정 기준을 따른다. 새로 지어내지 않는다.

## 빈 값·고아

| 분류 | 항목 | 조회 방법 | 심각도 | 고치는 법 |
|---|---|---|---|---|
| 빈 값·고아 | 출석부 고아 행 (학생 연결 없음) | `SELECT id FROM "collection://<출석부>" WHERE "학생" IS NULL` | 경고 | 학생 relation을 연결한다. 테스트용 빈 행이라면 행 자체를 치우는 것은 3단계 이후 지원한다. 지금은 어떤 행이 문제인지 보고만 하고, 사용자가 노션에서 직접 처리하도록 안내한다 |
| 빈 값·고아 | 과제 고아 행 (이름 붙여넣기 없음) | `SELECT id FROM "collection://<과제>" WHERE "이름 붙여넣기" IS NULL` | 경고 | 위와 같음 |
| 빈 값·고아 | 시험 고아 행 (이름 붙여넣기 없음) | `SELECT id FROM "collection://<시험>" WHERE "이름 붙여넣기" IS NULL` | 경고 | 위와 같음 |
| 빈 값·고아 | 수강료 납부 고아 행 (이름 붙여넣기 없음) | `SELECT id FROM "collection://<수강료 납부>" WHERE "이름 붙여넣기" IS NULL` | 경고 | 위와 같음 |
| 빈 값·고아 | 재원생 상담 고아 행 (이름 붙여넣기 없음) | `SELECT id FROM "collection://<재원생 상담>" WHERE "이름 붙여넣기" IS NULL` | 경고 | 위와 같음 |
| 빈 값·고아 | 과목 페이지 없는 학생 | `SELECT id FROM "collection://<학생>" WHERE "학생 과목별 페이지" IS NULL` | 오류 | 학생의 `학생 과목별 페이지`를 만들어 연결한다. 없으면 출결·과제가 붙을 곳이 없다(과목 페이지 필수 규칙) |
| 빈 값·고아 | 출석부 날짜 없는 행 | `SELECT id FROM "collection://<출석부>" WHERE "date:출석 날짜:start" IS NULL` | 오류 | 날짜를 채운다. 어느 수업인지 불명확하면 학생 측에 확인 후 입력 |
| 빈 값·고아 | 과제 날짜 없는 행 | `SELECT id FROM "collection://<과제>" WHERE "date:수업 날짜:start" IS NULL` | 오류 | 위와 같음 |
| 빈 값·고아 | 시험 날짜 없는 행 | `SELECT id FROM "collection://<시험>" WHERE "date:시험 날짜:start" IS NULL` | 오류 | 위와 같음 |
| 빈 값·고아 | 학생 0명인 클래스 | 1단계: `SELECT url, "클래스명" FROM "collection://<클래스>"` — 클래스는 학생 수와 무관하게 개수가 적은 DB라 통째로 읽어도 된다<br>2단계: `SELECT id, "클래스" FROM "collection://<학생 과목별 페이지>"` — 학생 수 × 과목수만큼 행이 있으므로, 학생이 많으면 클래스 단위로 나눠 여러 번 조회한다<br>대조: 2단계 각 행의 "클래스" 값(JSON 배열 문자열)에서 대시 없는 uuid를 뽑아, 1단계 url에 있는 클래스 중 한 번도 등장하지 않는 것을 추린다 | 참고 | 폐강된 반이면 그대로 둔다. 신설 직후라면 학생 연결이 아직 안 된 것이니 확인만 한다 |

## 정합성 위반

| 분류 | 항목 | 조회 방법 | 심각도 | 고치는 법 |
|---|---|---|---|---|
| 정합성 위반 | 클래스 요일 불일치 | 1단계: `SELECT url, "클래스명", "참여 요일" FROM "collection://<클래스>"` — 행이 적은 DB라 통째로 읽는다<br>2단계: `SELECT id, "클래스" FROM "collection://<학생 과목별 페이지>"`<br>3단계: `SELECT id, "date:출석 날짜:start", "학생" FROM "collection://<출석부>" WHERE "출결상태" != '보강'` — `출결상태 = 보강` 행은 정규 요일 밖이 정상이라 뺀다(`domain-rules.md` 「클래스 요일 정합」) (과제는 `date:수업 날짜:start`, 시험은 `date:시험 날짜:start`) — 출석부는 학생 수 × 기간만큼 늘어나는 DB다. 전 행을 끌어오지 말고 클로드가 계산한 cutoff 날짜를 리터럴로 넣어 점검 기간을 자르거나, 클래스 단위로 나눠 조회한다<br>대조: 3단계 각 행의 "학생"(=학생 과목별 페이지 relation) 값에서 대시 없는 uuid를 뽑아 2단계와 매칭해 클래스를 찾고, 1단계에서 그 클래스의 참여 요일을 가져온다. 날짜의 요일을 클로드가 계산해 참여 요일 안에 있는지 비교한다 | 경고 | 날짜를 클래스 요일에 맞게 정정한다. 실제 보강이었다면 그 행은 결석 행에 `보강 예정일` 을 잡고 `출결상태 = 보강` 행을 따로 두는 방식으로 고친다(`domain-rules.md` 「보강」) |
| 정합성 위반 | 점수가 총점 초과 | 1단계: `SELECT url, "시험명", "총점" FROM "collection://<시험 카테고리>"` — 시험 카테고리는 시험 종류 수만큼만 있는 DB라 통째로 읽어도 된다<br>2단계: `SELECT id, "점수", "재시험 점수", "시험 카테고리" FROM "collection://<시험>"`<br>대조: 2단계 각 행의 "시험 카테고리" 값(JSON 배열 문자열)에서 대시 없는 uuid를 뽑아 1단계 결과의 url과 맞춘 뒤, 점수·재시험 점수를 그 총점과 비교한다 | 오류 | 점수를 총점 이하로 정정하거나, 총점 자체가 잘못 입력됐는지 시험 카테고리를 확인한다 |
| 정합성 위반 | 퇴원일 이후 데이터 | 1단계: `SELECT url, "date:퇴원 날짜:start" FROM "collection://<학생>" WHERE "date:퇴원 날짜:start" IS NOT NULL` — 퇴원한 학생만 걸리므로 결과가 적다<br>2단계: `SELECT id, url, "학생" FROM "collection://<학생 과목별 페이지>"` 를 읽어, 1단계 학생 url의 대시 없는 uuid가 "학생" 값에 포함된 과목 페이지를 추린다(그 과목 페이지의 url이 다음 단계의 대조 기준)<br>3단계: `SELECT id, "date:출석 날짜:start", "학생" FROM "collection://<출석부>" WHERE "학생" LIKE '%<2단계 과목 페이지의 대시 없는 uuid>%' AND "date:출석 날짜:start" > '<해당 학생 퇴원일>'` (과제는 `date:수업 날짜:start`, 시험은 `date:시험 날짜:start` 와 relation `이름 붙여넣기`, 수강료 납부는 `date:납부 날짜:start`) | 경고 | 퇴원 날짜가 맞는지 먼저 확인한다. 오기입이면 건별 승인을 받아 날짜를 정정한다. 오기입이 아니면 행 자체를 치우는 것은 3단계 이후 지원한다. 지금은 어떤 행이 문제인지 보고만 하고, 사용자가 노션에서 직접 처리하도록 안내한다 |
| 정합성 위반 | 보강완료인데 보강 예정일 없음 | `SELECT id FROM "collection://<출석부>" WHERE "보강완료" = '__YES__' AND "date:보강 예정일:start" IS NULL` | 경고 | 보강 예정일을 채우거나 보강완료 체크를 해제한다 |
| 정합성 위반 | 보강 행 없이 보강완료만 켜진 결석 행 | 1단계: `SELECT id, "학생", "date:보강 예정일:start" FROM "collection://<출석부>" WHERE "보강완료" = '__YES__' AND "출결상태" IN ('지각', '미출석')`<br>2단계: 1단계 각 행의 `학생` uuid 와 `보강 예정일` 로 `SELECT id FROM "collection://<출석부>" WHERE "학생" LIKE '%<대시 없는 uuid>%' AND "date:출석 날짜:start" = '<보강 예정일>' AND "출결상태" = '보강'` 을 돌린다. 0행이면 걸린다 | 경고 | **옛 방식(체크박스만)으로 처리돼 보강 알림톡이 나가지 않았을 수 있다**고 보고한다. 고치지 않는다 — 원장이 원하면 `academy-attendance` 로 보강 완료를 다시 처리한다(보강 행 생성). 이 스킬은 새 행을 만들지 않는다 |

## 중복

| 분류 | 항목 | 조회 방법 | 심각도 | 고치는 법 |
|---|---|---|---|---|
| 중복 | 같은 학생·같은 날 출결 2행 | `SELECT "학생", "date:출석 날짜:start", COUNT(*) FROM "collection://<출석부>" WHERE "출결상태" != '보강' GROUP BY "학생", "date:출석 날짜:start" HAVING COUNT(*) > 1` — 보강 행은 그날 정규 출결 행과 따로 있을 수 있어 뺀다. 보강 행끼리의 중복은 같은 조회를 `WHERE "출결상태" = '보강'` 으로 한 번 더 돈다 | 경고 | 어느 행이 최신인지 확인해 나머지를 목록으로 보고한다. 행 자체를 치우는 것은 3단계 이후 지원한다. 지금은 어떤 행이 문제인지 보고만 하고, 사용자가 노션에서 직접 처리하도록 안내한다 |
| 중복 | 같은 학생·같은 날·같은 과제 2행 | `SELECT "이름 붙여넣기", "date:수업 날짜:start", "과제 안내", COUNT(*) FROM "collection://<과제>" GROUP BY "이름 붙여넣기", "date:수업 날짜:start", "과제 안내" HAVING COUNT(*) > 1` — 같은 날 **다른** 과제가 여럿인 것은 정상이라 과제 이름까지 묶는다 | 경고 | 위와 같음 |
| 중복 | 같은 시험에 2행 | `SELECT "이름 붙여넣기", "시험 카테고리", COUNT(*) FROM "collection://<시험>" GROUP BY "이름 붙여넣기", "시험 카테고리" HAVING COUNT(*) > 1` | 경고 | 위와 같음 |
| 중복 | 같은 납부월에 2행 | `SELECT "이름 붙여넣기", "납부 월", COUNT(*) FROM "collection://<수강료 납부>" GROUP BY "이름 붙여넣기", "납부 월" HAVING COUNT(*) > 1` | 경고 | 위와 같음 |
| 중복 | 동명이인 의심 | `SELECT "이름", COUNT(*) FROM "collection://<학생>" GROUP BY "이름" HAVING COUNT(*) > 1` | 참고 | `생년월일`·`학교` 로 실제 동일인인지 구분한다. 진짜 동명이인이면 문제 없음 |

## 이상값

| 분류 | 항목 | 조회 방법 | 심각도 | 고치는 법 |
|---|---|---|---|---|
| 이상값 | 동일 과목수 학생 대비 수강료 편차 | 1단계: `SELECT url, "학생" FROM "collection://<학생 과목별 페이지>"` — 학생별 과목수를 세는 데 쓴다. 학생이 많으면 클래스 단위로 나눠 조회해 합친다<br>2단계: `SELECT id, "수강료", "이름 붙여넣기" FROM "collection://<수강료 납부>"`<br>대조: 2단계 각 행의 "이름 붙여넣기"(과목 페이지 relation) 값에서 대시 없는 uuid를 뽑아 1단계와 매칭해 소속 학생을 찾는다. 학생별로 과목수와 수강료를 묶고, 과목수가 같은 학생 그룹끼리 평균을 내 크게 벗어난 값을 추린다 | 참고 | 형제 할인·특별 할인 등 정상 사유가 있는지 먼저 확인한다 |
| 이상값 | 3개월 넘은 미납 | 1단계: `SELECT url, "납부 년월" FROM "collection://<납부 월>"` — 행이 적은 DB(월 단위)라 통째로 읽는다. **`납부 년월` 에는 부등호 조건을 걸지 않는다.** 값이 `2026년 1월` 처럼 0 패딩이 없어 사전순 비교가 틀린다(`'2026년 12월' < '2026년 5월'` 이 참이 된다)<br>2단계: 클로드가 1단계 각 행의 `납부 년월` 에서 연·월을 **숫자로 파싱**해(`2026년 1월` → 2026, 1) 실행 시점 기준 3개월 전 연월(연×12+월로 환산)보다 이전인 달의 url 만 추린다<br>3단계: `SELECT id, "상태", "납부 월" FROM "collection://<수강료 납부>" WHERE "상태" = '미납'`<br>대조: 3단계 각 행의 "납부 월" 값에서 대시 없는 uuid를 뽑아 2단계에서 추린 url 목록에 있으면 대상으로 잡는다 | 참고 | 퇴원 처리 대상인지, 독촉이 필요한지 원장에게 확인한다 |
| 이상값 | 미래 날짜 데이터 | `SELECT id FROM "collection://<출석부>" WHERE "date:출석 날짜:start" > '<오늘 날짜, 클로드가 실행 시점 날짜로 채운다>'` (과제는 `date:수업 날짜:start`, 시험은 `date:시험 날짜:start` 로 동일하게 실행) | 참고 | 예정된 입력이면 정상이다. 날짜 오기입이면 정정한다 |

## 플레이스홀더 잔존

검사 문자열: `이름 1`, `이름 2`, `클래스 1`, `클래스 2`, `학교 이름`, `선생님 1`, `양식 1`, `상담 내용 입력`, `상담 내용 작성하기`, `피드백 내용 작성`, `신입생 1`.

**여러 검사에 동시에 걸리면 샘플 데이터가 통째로 남아 있는 것이다.** 한 건씩 이름을 고쳐 나가는 것보다 `academy-setup` 의 「샘플 데이터 정리」로 한 번에 치우는 편이 빠르다 — 샘플 행을 `🗃️ 샘플 보관` 페이지로 옮겨 DB 를 비우고, 「샘플 되돌려줘」로 되돌릴 수 있다. 아래 표의 「고치는 법」은 **실제 데이터에 샘플 문자열이 몇 건만 섞여 있을 때** 쓴다.

| 분류 | 항목 | 조회 방법 | 심각도 | 고치는 법 |
|---|---|---|---|---|
| 플레이스홀더 잔존 | 학생 이름 샘플값 | `SELECT id FROM "collection://<학생>" WHERE "이름" LIKE '%이름 1%' OR "이름" LIKE '%이름 2%'` | 참고 | 실제 학생 이름으로 정정한다 |
| 플레이스홀더 잔존 | 클래스명 샘플값 | `SELECT id FROM "collection://<클래스>" WHERE "클래스명" LIKE '%클래스 1%' OR "클래스명" LIKE '%클래스 2%'` | 참고 | 실제 클래스명으로 정정한다 |
