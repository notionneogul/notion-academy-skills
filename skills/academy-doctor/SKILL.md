# 데이터 점검

시작 전에 읽는다.

- `../academy-core/references/db-map.md`
- `../academy-core/references/query-limits.md` — 조회를 시작하기 전에 반드시 읽는다. 여기 적힌 제약을 벗어난 쿼리는 조용히 틀린 답을 낸다
- `../academy-core/references/domain-rules.md` — 정합성 판정 기준이 여기 있다

검사 항목 전체와 조회 방법은 `references/checks.md` 를 본다. 발화 예시는 `references/examples.md` 를 본다.

**기본은 읽기 전용이다.** 고칠 수 있는 항목은 제안까지만 하고, 사용자가 승인하면 그때 수정한다. 수정 시 `../academy-core/references/write-safety.md` 의 경계를 따른다.

**이 스킬이 하는 쓰기는 값 수정뿐이다.** 건별 승인을 받아 빈 속성을 채우거나 잘못 들어간 값을 고치는 것까지다. 행을 옮기거나 없애지 않는다 — 보관 페이지로 옮기기, 휴지통으로 보내기, 행 삭제는 어느 것도 하지 않는다. 행 자체를 치워야 하는 문제는 어떤 행이 문제인지 보고만 하고, 사용자가 노션에서 직접 처리하도록 안내한다. 행을 치우는 기능은 3단계 이후에 별도로 추가된다.

## 출력 형식

심각도 세 단계로 묶는다.

| 단계 | 기준 | 예 |
|---|---|---|
| 오류 | 수식이 잘못된 값을 내거나 문자가 깨진다 | 점수 > 총점 |
| 경고 | 지금은 돌아가지만 곧 문제가 된다 | 클래스 요일 불일치, 퇴원 후 데이터, 중복 입력, 보강 행 없이 보강완료만 켜진 결석 행(보강 알림톡이 안 나갔을 행) |
| 참고 | 확인만 필요하다 | 3개월 넘은 미납, 샘플 텍스트 잔존 |

각 항목마다 **건수 · 예시 3건 · 고치는 방법**을 낸다. 건수만 내면 원장이 찾아다녀야 한다.

문제가 없으면 그렇게 말한다. 없는 문제를 만들어내지 않는다.

## 규모 처리

행이 많으면 SQL 집계로 먼저 건수를 세고, 예시가 필요한 항목만 상세 조회한다. 전 행을 끌어와 눈으로 훑지 않는다.
