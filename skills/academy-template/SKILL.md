# 알림톡 템플릿 준비

**속성을 만들고 본문을 뽑는다. 값은 채우지 않고, 등록하지도 발송하지도 않는다.**

문자는 완성된 한 덩어리를 그대로 보내면 되지만 알림톡은 그렇게 못 보낸다. 승인된 템플릿 본문은 고정이고 바뀌는 것은 `#{변수}` 자리뿐이라, 한 덩어리를 넣을 자리가 없다. 항목별로 쪼갠 값이 필요하고, **그 값이 담길 노션 속성이 먼저 있어야 한다.** 그 속성을 만드는 것이 이 스킬이다. 알림톡을 쓰지 않는 원장은 이 스킬을 부를 일이 없다.

## 시작 전에 읽는다

- `../academy-core/references/write-safety.md` — 쓰기 경계표. **「스키마 변경 — 속성 추가」 행이 이 스킬의 경계다.** 미리보기와 승인을 거쳐 속성을 더하는 것은 스킬 열셋 가운데 이 스킬 하나뿐이고, 바로 아래 「속성 삭제·이름 변경」 행은 이 스킬도 하지 않는다
- `../academy-core/references/write-gate.md` — 쓰기 관문. **4단계가 무엇을 승인으로 볼지 정한다.** 3단계 미리보기는 이 스킬에서 「만들 속성 표」 한 장이다
- `../academy-core/references/db-map.md` — `학생 과목별 페이지` 의 DB id 와 「설정 파일 규격」. **이 스킬이 만드는 속성은 지문이 아니다** — 이유는 「지문표에 넣지 않는 속성」에 있다
- `../academy-core/references/query-limits.md` — 1단계에서 항목별 원본 데이터를 확인할 때의 제약. **formula 는 쿼리 결과에 나타나지 않는다** — 2단계에서 이름 충돌을 쿼리로 확인할 수 없는 이유이기도 하다

`~/.academy/config.json` 이 없으면 속성을 만들지 말고 멈춘 뒤 `academy-setup` 을 안내한다. 어느 DB 에 속성을 더할지 알 방법이 없다.

## 언제 쓰나

- "월간 리포트 알림톡 만들래"
- "알림톡 템플릿 준비해줘"
- "알림톡에 상담 내용도 넣고 싶어"
- "academy-message 가 속성이 없다고 해"
- "알림톡 변수 속성 만들어줘"

## 쓰는 속성

| 어디에 | 무엇을 |
|---|---|
| 노션 `학생 과목별 페이지` | **텍스트 속성을 만든다.** 값은 채우지 않는다 — `academy-message` 의 일이다 |
| `~/.academy/config.json` 의 `send.templates.<이름>` | `variables`(속성명 목록)·`fixed_length`(고정 본문 글자수). 규격은 `../academy-core/references/db-map.md` 「설정 파일 규격」 |
| Solapi | **아무것도 보내지 않는다.** 등록은 원장이 콘솔에서 한다 |

## 절차

### 1. 항목을 정한다

기본 다섯을 제안한다 — 출결 · 시험 · 과제 · 총평 · 다음 과제. 원장이 빼거나 더하면 그대로 따른다.

**다섯 중 총평은 원본 DB 가 따로 없다.** 출결·시험·과제에서 도출하는 항목이라 확인할 원본이 앞의 셋과 같다 — 총평만 따로 조회하지 않는다. `academy-message` 「3. 근거 수집」의 항목표에 총평 행이 없는 것도 같은 이유다.

**제안하기 전에 각 항목의 원본 데이터가 실제로 있는지 먼저 확인한다.** 상담을 넣자고 했는데 그 반에 상담 기록이 없으면 빈 변수가 그대로 학부모에게 나간다. 알림톡은 그 빈칸을 나중에 메울 방법이 없다 — 본문이 승인되고 나면 변수 자리만 바뀌기 때문이다.

**대상 반의 재원생 전원을 놓고 항목마다 몇 명분이 있는지 세어 보고 그 수를 원장에게 그대로 말한다.** 절반만 있는 항목은 넣을지 말지 원장이 정한다. 조회 범위(기본 한 달)와 항목별로 어느 DB 의 무엇을 읽는지는 `../academy-message/SKILL.md` 「3. 근거 수집」이 권위 절차다 — **여기서 다시 적지 않고 그것을 그대로 쓴다.**

### 2. 속성명을 정한다

**속성명에 공백을 쓰지 않는다.** 원장이 이미 등록해 둔 「2026 학원관리」 템플릿의 변수 11개가 전부 공백 없는 이름이다(`#{최근출결상태}`·`#{최근시험명}`·`#{저번과제평가}` 등, `../academy-send/references/setup.md` 「5. 변수 확인」). 변수명과 속성명이 글자까지 같아야 하므로 속성명도 같은 모양으로 맞춘다.

기본 접두어는 `클로드` 다 — `클로드출결`·`클로드시험`·`클로드과제`·`클로드총평`·`클로드다음과제`. **템플릿이 여럿이 될 것 같으면 접두어를 상황 이름(`월간`·`주간`)으로 할지 묻는다.** 월간과 주간이 같은 칸을 나눠 쓰면 나중에 만든 쪽이 앞의 값을 덮는다.

**만들기 전에 `notion-fetch` 로 `학생 과목별 페이지` 데이터 소스를 읽어 지금 있는 속성의 이름과 타입을 본다.** 응답에 속성마다 타입이 붙어 오고, 수식도 함께 나온다 — `academy-setup` 이 지문을 대조할 때 쓰는 것과 같은 경로다(`../academy-setup/SKILL.md` 「연결 절차」 4).

**행을 조회해서 보지 않는다.** `../academy-core/references/query-limits.md` 「formula·rollup은 컬럼으로 조회 불가」에 따라 **수식 속성은 쿼리 결과에 아예 나타나지 않는다** — 이름이 겹치는지조차 알 수 없다. 이 DB 는 수식만 40개라(`../academy-core/references/db-map.md` 「DB별 쓰기 불가 속성」) 쿼리로 확인하면 「충돌 없음」으로 잘못 보고 이미 있는 이름에 속성을 하나 더 만들게 된다.

겹치는 이름이 있으면 그 이름으로 새 속성을 만들지 말고, 스키마에서 읽은 **타입에 따라 갈린다.**

- **텍스트면** 그 칸을 그대로 쓸지 다른 이름으로 갈지 원장에게 묻는다. 그대로 쓰기로 하면 새로 만들지 않고 그 이름을 `variables` 에 넣는다
- **텍스트가 아니면(수식·select·rollup 등) 그 이름을 쓰지 않고 다른 이름으로 간다.** 타입을 바꾸는 것은 `../academy-core/references/write-safety.md` 「스키마 변경 — 그 밖」이 금지한다. 텍스트가 아닌 칸을 `variables` 에 넣으면 `academy-message` 가 값을 쓰지 못해 **그 변수 자리가 빈 채로 학부모에게 나간다** — 왜 다른 이름으로 가는지 알리고 새 이름을 제안한다

### 3. 미리보기 + 승인

만들 속성의 이름과 타입을 표로 보이고 승인을 받는다. **승인 판정은 `../academy-core/references/write-gate.md` 4단계다** — 명시적인 긍정만 승인이고 침묵은 승인이 아니다.

```
`학생 과목별 페이지` 에 텍스트 속성 5개를 만듭니다.

| 속성명 | 타입 | 담을 것 |
|---|---|---|
| 클로드출결 | 텍스트 | 한 달치 출결 요약 |
| 클로드시험 | 텍스트 | 한 달치 시험 회차와 추세 |
| 클로드과제 | 텍스트 | 한 달치 과제 평가 |
| 클로드총평 | 텍스트 | 종합 코멘트 |
| 클로드다음과제 | 텍스트 | 다음 수업 진도와 과제 |

전 학생 행에 칸이 하나씩 늘어납니다. 값은 비어 있습니다. 만들까요?
```

### 4. 속성을 만든다

`notion-update-data-source` 의 `data_source_id` 에 `학생 과목별 페이지` 를 주고, `statements` 에 `ADD COLUMN "<이름>" RICH_TEXT` 를 준다. 세미콜론으로 이어 **다섯 개를 한 번에** 만드는 것을 실측으로 확인했다.

```
statements: ADD COLUMN "클로드출결" RICH_TEXT; ADD COLUMN "클로드시험" RICH_TEXT; ADD COLUMN "클로드과제" RICH_TEXT; ADD COLUMN "클로드총평" RICH_TEXT; ADD COLUMN "클로드다음과제" RICH_TEXT
```

만든 뒤에는 **스키마를 다시 읽어**(`notion-update-data-source` 가 돌려주는 스키마를 그대로 보거나 `notion-fetch` 로 다시 읽는다) 이름과 타입이 의도대로 붙었는지 확인하고 몇 개를 만들었는지 보고한다. **여기서도 행을 조회해서 확인하지 않는다** — 2단계와 같은 이유다. **값이 든 텍스트 속성이 컬럼으로 온다는 것은 확인됐지만 갓 만들어 전 행이 빈 칸인 속성까지 그런지는 확인된 바 없다**(`../academy-core/references/query-limits.md`) — 방금 만든 칸이 정확히 그 상태다.

**`DROP COLUMN` 과 `RENAME COLUMN` 은 이 스킬이 쓰지 않는다.** 사유는 `../academy-core/references/write-safety.md` 「스키마 변경 — 속성 삭제·이름 변경」 행에 있다.

### 5. 템플릿 본문을 출력하고 안내한다

머리표와 맺음말은 고정 본문에 넣고, 학생마다 달라지는 내용은 전부 `#{속성명}` 변수로 둔다. **변수명은 2단계에서 정한 속성명과 글자까지 같아야 한다.** 학생 이름 자리는 `#{이름}` 을 쓰고 **이 이름으로 속성을 만들지 않는다.** 그 값은 `학생` DB 의 `이름`, 곧 **사람 이름**이고 발송할 때 `academy-send` 가 채운다(`../academy-send/SKILL.md` 「절차 — 발송」 3단계 「가」). **`학생 과목별 페이지` 의 title 은 「김서준 수학」이라 사람 이름이 아니다** — 사람 이름을 얻으려면 `학생` DB 까지 두 단계를 가야 한다(`../academy-core/references/db-map.md` 「이름이 오해를 부르는 relation」). 그래서 `#{이름}` 은 `variables` 목록에 넣지 않는다 — 이 스킬이 만든 칸이 아니다.

본문을 출력하면서 셋을 함께 한다.

1. **고정 본문 글자수를 세어 알린다.** 변수 자리(`#{...}`)를 뺀 나머지를 센다. 줄바꿈도 한 자로 센다 — 그래야 실제 발송 본문보다 짧게 잡히지 않는다. 남는 자리는 `1,000 − 이 수` 이고, 상한의 근거는 `../academy-send/references/setup.md` 「본문 길이 상한」이다
2. `~/.academy/config.json` 의 `send.templates.<이름>` 에 `variables`(속성명 목록)와 `fixed_length`(방금 센 수)를 저장한다. **`academy-message` 의 알림톡 모드가 학생별 글자수를 판정할 때 이 값을 쓴다** — 없으면 변수 합계만 세고 정확하지 않다고 밝히게 된다. **이미 그 이름표로 저장된 항목이 있으면 이 둘만 채우고 `template_id`·`name` 은 그대로 둔다 — 항목을 통째로 덮어쓰지 않는다.** 등록이 끝난 뒤 속성을 더 만들려고 이 스킬을 다시 부르는 일이 있는데, 그때 덮어쓰면 등록된 template id 가 날아가 발송이 멈춘다. `../academy-send/references/setup.md` 「4. 템플릿 고르기」가 반대 방향으로 같은 못을 박는다
3. **원장이 솔라피 콘솔에서 직접 등록한다.** 등록하고 나면 template id 를 설정에 넣어야 하는데, 그것은 `../academy-send/references/setup.md` 「4. 템플릿 고르기」가 하는 일이다 — 여기서 다시 하지 않고 그리로 넘긴다. **넘길 때 방금 저장한 상황 이름표를 그대로 말해 준다** — 그 단계는 같은 키의 `template_id`·`name` 만 채우고 `variables`·`fixed_length` 는 그대로 두는데, 이름표가 갈리면 반씩 채워진 키가 둘 남는다

## 주의

- **속성을 지우지 않는다.** `DROP COLUMN` 을 쓰지 않는다. **왜 이것이 이 저장소의 어떤 동작보다 나쁜지는 `../academy-core/references/write-safety.md` 「스키마 변경 — 속성 삭제·이름 변경」 행에 있다 — 여기서 다시 적지 않는다.** 원장이 지워 달라고 하면 하지 않고, 노션에서 직접 지우는 방법과 그 결과를 알린다
- **속성 이름을 바꾸지 않는다.** `RENAME COLUMN` 을 쓰지 않는다. 사유는 같은 행에 있다. 바꿔야 하면 **템플릿을 다시 등록해야 한다**는 것을 알리고 멈춘다
- **Solapi 에 등록하지 않는다.** 카카오 심사가 걸린 절차다. 본문을 만들어 주고 원장이 콘솔에서 등록한다
- **값을 채우지 않는다.** 만든 칸은 비어 있는 채로 둔다 — 채우는 것은 `academy-message` 의 알림톡 모드다
- **알림톡 본문 상한은 1,000자다.** 무엇을 어떻게 세는지(치환이 끝난 본문 전체를 센다, 버튼은 빠진다)는 `../academy-send/references/setup.md` 「본문 길이 상한」이 권위 출처다 — 여기서 다시 적지 않는다. 이 스킬이 할 일은 하나다: **고정 본문이 길수록 변수에 쓸 수 있는 자리가 줄어드니 머리표와 맺음말을 짧게 잡는다**

## 예시

발화 → 처리 → 만든 속성 → 템플릿 본문 흐름은 `references/examples.md` 를 본다.
