# 문자 양식 쓰기

**`문자 양식` DB 의 행만 만들고 고친다. 데이터베이스 구조(속성)는 바꾸지 않고, 발송하지 않는다.**

알림톡 문구는 `문자 양식` 행의 본문에 `#{변수}` 를 넣어 만든다. 템플릿의 `양식(...)` 수식이 학생마다 변수를 채우고 Make 가 보낸다. 변수 이름이 한 글자라도 틀리면 **그 자리가 빈칸이나 `#{…}` 그대로 학부모에게 나간다** — 한 번 나간 문자는 되돌릴 수 없다. 그래서 이 스킬의 핵심은 쓰기 전에 변수를 대조하는 것이다.

## 시작 전에 읽는다

- `../academy-core/references/db-map.md` — `문자 양식` 지문, 「문자 양식 변수」(변수 이름 규칙과 발송 시각)
- `../academy-core/references/write-gate.md` — 쓰기 관문(되물음 → 사전 검증 → 미리보기 → 승인 → 쓰기 → 되돌리기)
- `../academy-core/references/domain-rules.md` — 「발송」
- `../academy-core/references/write-safety.md` — 기존 행 수정은 건별 승인, 스키마 변경은 하지 않는다

## 언제 쓰나

- "출결 알림 문구 새로 만들어줘"
- "위클리 리포트 양식에 총평 넣어줘"
- "이 문구 변수 맞는지 봐줘"
- "미납 알림 문구 좀 부드럽게 바꿔줘"

## 쓰는 속성

`문자 양식` DB:

| 속성 | 타입 | 내용 |
|---|---|---|
| `이름` | title | 양식 이름(예: `출결 알림 - 기본`) |
| `문자 양식` | text | 알림톡 본문. `#{변수}` 를 넣는다 |
| `선택` | select | `데일리리포트` / `출석알림` / `위클리리포트` / `납부알림` / `미납알림` 중 하나 — 이미 있는 선택지만 쓴다 |
| `사용` | checkbox | 이 양식을 쓸지. 원장이 켜라고 했을 때만 켠다 |
| `설명` | text | 양식 메모. 원장이 말했을 때만 쓴다 |

**쓰지 않는 것.** `학생` relation(어느 학생에게 이 양식을 쓸지)은 원장이 노션에서 고른다. **데이터베이스 속성을 만들거나 지우거나 이름을 바꾸지 않는다** — `write-safety.md` 「스키마 변경」. 새 변수가 필요해 속성을 더해야 하면 원장이 노션에서 직접 만든다.

## 절차

`write-gate.md` 사전 검증 네 항목 중 (가) 수업일 대조·(다) 평가 대상·(라) 퇴원은 해당 없다 — 날짜가 붙은 행도, 학생에게 딸린 행도 아니다. **(나) 중복은 한다** — 2단계.

### 1. 문구와 종류 받기

원장에게서 본문과 `선택`(어느 알림인지)을 받는다. 새 양식인지 기존 양식을 고치는지 가린다. 기존 양식이면 `문자 양식` DB 를 읽어 해당 행을 찾고 지금 본문을 보인다.

### 2. 중복 확인

같은 `선택` 에 `사용` 이 켜진 행이 이미 있으면 알린다. 둘 다 켜져 있으면 어느 쪽이 쓰일지 모호하다 — 새 행을 켤지, 기존 행을 끌지, 기존 행을 고칠지 묻는다.

### 3. 변수 대조

`db-map.md` 「문자 양식 변수」의 규칙대로 대조한다.

1. `학생 과목별 페이지` 스키마를 `notion-fetch` 로 읽는다(속성 이름과 타입이 함께 온다). **행을 조회해서 확인하지 않는다** — `query-limits.md`
2. 속성 이름마다 **띄어쓰기를 뺀** 목록을 만든다(`개별 페이지 링크` → `개별페이지링크`)
3. 문구의 `#{X}` 를 전부 뽑아 그 목록에 있는지 본다
4. **하나라도 없으면 쓰기 전에 멈춘다.** 없는 변수와, 글자가 가장 가까운 후보를 함께 보인다

> `#{출결문자}` 에 해당하는 속성이 없습니다. `#{출석문자}` 를 뜻하셨나요? (「나만의 양식 만들기」 설명에 적힌 `#{출결문자}` 는 오타입니다)

원장이 바로잡은 문구로 다시 대조한다. 원장이 「그대로 써」라고 해도 없는 변수가 든 문구는 쓰지 않는다 — 학부모에게 `#{출결문자}` 가 그대로 나간다.

`#{클로드총평}` 이 있으면 결과 보고에 「총평은 `academy-message` 로 채우고, Make 가 보내기 전에 써 두셔야 실립니다」를 붙인다.

### 4. 미리보기

`| 이름 | 선택 | 사용 | 본문 |` 표로 보인다. 기존 행 수정이면 고치기 전 본문과 나란히 보인다. 본문은 줄바꿈을 살려 보인다. uuid 는 넣지 않는다.

### 5. 승인 후 쓰기

승인의 판정은 `write-gate.md` 4단계를 따른다. 새 행은 `notion-create-pages`, 기존 행 수정은 `notion-update-page` `command: "update_properties"` 로 쓴다. 기존 행 수정은 `write-safety.md` 「기존 행 수정」 경계라 4단계 표가 건별 승인이다.

되돌리기는 `write-gate.md` 6단계를 따른다 — 새로 만든 행은 **생성분**이라 보관 페이지로 옮기고, 고친 본문은 **수정분**이라 4단계에서 읽어 둔 본문으로 되돌린다.

결과 보고에 「발송은 Make 가 합니다 — 출결 알림은 기록 즉시, 나머지는 정해진 시간에 나갑니다」를 붙인다(`domain-rules.md` 「발송」).

## 주의

- **발송하지 않는다.** 「이 문구로 보내줘」라고 해도 양식만 쓰고 발송 방식을 설명한다
- **변수가 맞아도 값이 비면 빈칸으로 나간다.** 수식 값은 도구로 읽을 수 없어(`query-limits.md`) 클로드는 이름만 대조한다. 실제로 무엇이 채워지는지는 원장이 노션에서 학생 한 명의 `양식(...)` 칸을 열어 확인한다 — 결과 보고에 이 한 줄을 붙인다
- `선택` 에 없는 새 종류(예: 「시험알림」)는 만들지 않는다 — select 선택지를 더하는 것도 스키마 변경이다. 원장이 노션에서 선택지를 더한 뒤 다시 부른다
- 알림톡 본문은 1,000자 상한이 있다. 변수가 채워진 뒤 길이는 알 수 없으니, 고정 문구가 길면 한 줄로 알린다
