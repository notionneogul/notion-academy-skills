# 발화 예시

## 연결

| 발화 | 해석 | 처리 |
|---|---|---|
| "학원 템플릿 연결해줘" | 최초 연결 | 링크를 요청한다 |
| "노션 연결" / "셋업" | 최초 연결 | 같음 |
| 링크만 덜렁 붙여넣음 | 연결 의도로 본다 | 그 링크로 바로 스캔한다 |
| "다시 연결해줘" | 재연결 | 기존 설정을 보여주고 덮어쓸지 묻는다 |
| "연결 잘 됐나 확인해줘" | 상태 점검 | config.json 을 읽어 DB 14개와 저장 시각을 보고한다. 스캔하지 않는다 |
| "학원이 두 개인데" | 다중 워크스페이스 | 현재 설정은 하나만 지원한다고 알리고, 어느 쪽을 연결할지 묻는다 |
| "커넥터에 페이지가 안 보여요" | 권한 문제 | 노션에서 페이지를 커넥션에 추가하는 절차를 안내한다 |
| "DB 이름을 바꿨어요" | 지문 불일치 예상 | 스캔 후 어긋난 DB 를 보고하고, 원래 이름으로 되돌리거나 db-map 을 고쳐야 한다고 안내한다 |

## 샘플 데이터 정리

| 발화 | 해석 | 처리 |
|---|---|---|
| "샘플 지워줘" / "샘플 데이터 정리해줘" | 통째로 비우기 | DB별 행 수를 세어 미리보기 표를 만들고 승인을 받는다 |
| "남의 데이터 치워줘" / "이거 다 제 학원 게 아닌데요" | 같음 | 같음 |
| "샘플 이름만 제 학생 이름으로 바꿔줘" | 제공하지 않는 방식 | 이름만 바꾸면 남의 날짜·점수·상담 기록이 그대로 남는다고 알리고, 통째로 비운 뒤 새로 등록하는 길을 안내한다 |
| "출석부만 비워줘" | 일부만 | 로그 6종은 잎이라 단독으로 옮겨도 남는 쪽이 깨지지 않는다. 그 DB 만 미리보기·승인 후 **「DB 하나를 옮기는 루프」를 그대로 돈다 — 목록 기록도 똑같이 한다.** 반대로 "학생만 지워줘" 는 로그가 사라진 학생을 가리키게 되므로 순서를 설명하고 되묻는다 |
| "지워도 되돌릴 수 있어요?" | 안전 확인 | 삭제가 아니라 `🗃️ 샘플 보관` 페이지로 옮기는 것이고 값이 그대로 살아난다고 답한다(`write-safety.md` 「되돌리기 절차」). 되돌리기 목록을 그 페이지에 적어 두므로 세션이 바뀌어도 된다는 것도 함께 알린다 |
| "샘플 되돌려줘" | 되돌리기 | 보관 페이지 본문의 「되돌리기 목록」을 먼저 읽고, 뿌리에서 잎으로 반대 순서로 되돌린다. 목록이 없으면 되돌릴 수 없다고 말하고 멈춘다 — 추측으로 아무 DB 에나 넣지 않는다 |
| "보관 페이지 지워도 돼?" | 마무리 확인 | 이 페이지는 다른 스킬의 「방금 거 취소해줘」도 함께 쓰는 공용 보관소라, 안에 샘플 말고 다른 것이 있는지 먼저 확인하라고 답한다. 지우면 행과 함께 「되돌리기 목록」도 사라져 되돌릴 수 없다는 것을 함께 알린다 |
| "문자가 안 나가요" (정리 직후) | 부작용 | `문자 양식` 의 `학생` 연결이 비었을 가능성이 크다. 노션에서 각 양식의 `학생` 속성에 새 학생을 연결하도록 안내한다 |
