# 데이터베이스 지문과 설정 파일 규격

이 문서는 「학원 관리 PRO X」 개편판(2026-09) 기준입니다. 근거는 2026-09-03·09-12 실측입니다.

## 설정 파일 규격

스킬은 사용자의 노션 템플릿과 연결하기 위해 설정 파일을 읽습니다. 경로는 `~/.academy/config.json`입니다.

파일 형식은 다음과 같습니다:

```json
{
  "template_version": "3.0",
  "root_page": "https://www.notion.so/...",
  "connected_at": "2026-09-12",
  "databases": {
    "학생": "collection://...",
    "학생 과목별 페이지": "collection://...",
    "클래스": "collection://...",
    "출석부": "collection://...",
    "과제": "collection://...",
    "시험": "collection://...",
    "시험 카테고리": "collection://...",
    "수강료 납부": "collection://...",
    "납부 월": "collection://...",
    "재원생 상담": "collection://...",
    "신입생": "collection://...",
    "학교": "collection://...",
    "클래스 공지사항": "collection://...",
    "문자 양식": "collection://..."
  }
}
```

- `template_version`: 템플릿 버전(문자열)
- `root_page`: 루트 페이지 URL(문자열)
- `connected_at`: 연결 날짜(문자열, `YYYY-MM-DD` 형식)
- `databases`: 한글 데이터베이스명을 `collection://<uuid>` 형식의 문자열에 매핑합니다(14개)

파일이 없거나 `databases` 키에 14개 미만의 데이터베이스가 있으면 연결되지 않은 상태로 보고 `academy-setup` 실행을 안내한 뒤 중단합니다.

설정 파일에는 API 키를 두지 않습니다. 알림톡은 템플릿과 Make 가 보내므로 클로드가 발송 설정을 가질 일이 없습니다(`domain-rules.md` 「발송」).

## 스키마 지문표

각 데이터베이스는 이름만으로 판별하지 않고 다음 속성 조합으로 확인합니다:

| 데이터베이스 | 지문 (이 속성들이 모두 있어야 한다) |
|---|---|
| 학생 | `이름`(title) · `생년월일`(date) · `성별`(select: 남/여) · `학년 수정`(number, 수식 `학년`의 수동 보정값) · `학교`(relation→학교) · `학부모 전화번호`·`학생 전화번호`(phone_number) · `특이사항`(text) · `퇴원 날짜`(date) · `학생 과목별 페이지`(relation→학생 과목별 페이지) |
| 학생 과목별 페이지 | `이름`(title) · `학생`(relation→학생) · `클래스`(relation→클래스) · `출석부`(relation→출석부) · `과제`(relation→과제) · `시험`(relation→시험) · `재원생 상담`(relation→재원생 상담) · `수강료 납부`(relation→수강료 납부) · `문자 양식`(relation→문자 양식) · `클로드총평`(text) · `요일 변경`(multi_select) · `전송완료`(checkbox) |
| 클래스 | `클래스명`(title) · `참여 요일`(multi_select) · `시작 시간`(text) · `운영시간(분)`(number) · `담당 선생님`(select) |
| 출석부 | `출석 날짜`(date) · `출결상태`(select: 출석/지각/미출석/보강) · `보강 예정일`(date) · `보강완료`(checkbox) · `학생`(relation→**학생 과목별 페이지**) |
| 과제 | `수업 날짜`(date) · `수업 진도`(text) · `과제 안내`(text) · `평가`(select: 우수/보통/미흡) · `피드백`(text) · `이름 붙여넣기`(relation→**학생 과목별 페이지**) — 행마다 학생 1명입니다. 같은 날 과제가 여럿이면 행이 여럿입니다. 제목(`""`)에는 `과제 안내` 와 같은 과제 이름이 들어갑니다 |
| 시험 | `시험 날짜`(date) · `점수`·`재시험 점수`(number) · `평가`(select: 통과/재시험/미응시) · `피드백`(text) · `시험 카테고리`(relation→시험 카테고리) · `이름 붙여넣기`(relation→**학생 과목별 페이지**) — 행마다 학생 1명입니다. 같은 날 시험 카테고리가 다른 행이 여럿일 수 있습니다 |
| 시험 카테고리 | `시험명`(title) · `유형`(select: 단어시험/모의고사/데일리테스트/주간평가/월간평가) · `총점`(number) · `시험`(relation→시험) |
| 수강료 납부 | `수강료`(number, 원) · `상태`(status: 미납/납부 완료) · `납부 날짜`(date) · `납부 월`(relation→납부 월) · `이름 붙여넣기`(relation→**학생 과목별 페이지**) |
| 납부 월 | `납부 년월`(title) — 속성이 이것 하나뿐인 것이 지문입니다 |
| 재원생 상담 | `상담 날짜`(date) · `상담 기록`(text) · `이름 붙여넣기`(relation→**학생 과목별 페이지**) |
| 신입생 | `이름`(title) · `상태`(status: 상담 전/상담 중/등록 완료/미등록) · `상담 날짜`(date) · `생년월일`(date) · `성별`(select: 남/여) · `학년 수정`(number) · `학교`(relation→학교) · `학부모 전화번호`·`학생 전화번호`(phone_number) · `특이사항`(text) · `재원생 등록`(button) |
| 학교 | `학교명`(title) · `선택`(select: 초등학교/중학교/고등학교) · `인원 수`(rollup) |
| 클래스 공지사항 | `이름`(title) · `클래스`(relation→클래스) · `공유 링크`(formula) |
| 문자 양식 | `이름`(title) · `문자 양식`(text) · `사용`(checkbox) · `선택`(select: 데일리리포트/출석알림/위클리리포트/납부알림/미납알림) · `설명`(text) · `학생`(relation→**학생 과목별 페이지**) |

## 지문표 참고

### 이름이 오해를 부르는 relation

relation 속성의 **이름과 실제 대상 DB가 다릅니다.** 위 표에서 굵게 표시한 것들이 그렇습니다.

| 속성 | 있는 곳 | 실제 대상 |
|---|---|---|
| `학생` | 출석부 | `학생 과목별 페이지` (`학생` DB가 아닙니다) |
| `학생` | 문자 양식 | `학생 과목별 페이지` |
| `이름 붙여넣기` | 과제 · 시험 · 수강료 납부 · 재원생 상담 | 전부 `학생 과목별 페이지` |

출석부·과제·시험·수강료 납부·재원생 상담에서 사람 이름을 얻으려면 `학생 과목별 페이지`를 거쳐 `학생` DB까지 두 단계를 가야 합니다. 한 단계로 끝난다고 보고 쓰면 엉뚱한 DB 를 가리키게 됩니다.

지문이 맞지 않으면 조용히 넘어가지 않습니다. 어느 데이터베이스가 어떤 속성 때문에 어긋났는지 사용자에게 보고하고 멈춥니다. 템플릿이 개편 전 버전이거나 사용자가 속성 이름을 바꾼 경우입니다. 이 스킬 세트는 개편판만 지원합니다.

## DB별 쓰기 불가 속성

`domain-rules.md` 「쓰기 불가 속성」이 가리키는 권위 목록입니다. **formula·rollup·button 에는 값을 쓰지 않습니다** — 무시되거나 실패합니다. 각 쓰기 스킬의 「쓰지 않는 것」은 이 표를 가리킵니다.

| 데이터베이스 | formula | rollup | button |
|---|---|---|---|
| 학생 | `학년` · `참여 요일 및 시간` | — | `국어` · `영어` · `수학` · `과학` · `퇴원` |
| 학생 과목별 페이지 | `KPI 분석` · `KPI 점수` · `개별 페이지 링크` · `개별 페이지 링크 (알림톡)` · `과제문자` · `과제안내` · `납부문자` · `납부알림` · `당일 수업` · `데일리리포트` · `미납문자` · `미납알림` · `상담 관리` · `시험문자` · `양식(납부알림)` · `양식(데일리리포트)` · `양식(미납알림)` · `양식(위클리리포트)` · `양식(출결알림)` · `위클리과제` · `위클리리포트` · `위클리시험` · `위클리출결` · `이름(3글자)` · `참여 요일 및 시간` · `최근 상담 날짜` · `최근 상담 내용` · `출결알림` · `출석문자` · `클래스 공지 링크` · `클래스 공지 링크 (알림톡)` · `퇴원생` · `특이사항 문자` · `특이사항(수식)` · `학생 전화번호` · 요일별 수식 `월`~`일` | `시작 시간` · `참여 요일` | `출석` · `지각` · `미출석` |
| 클래스 | `오늘 출석 인원` | — | `공지사항 생성` |
| 출석부 | `보강 디데이` · `출석 문자` | `클래스` | `보강` |
| 과제 | `DP` · `클래스(그룹)` · `평가 점수` · `과제 문자` · `필터` | `클래스` | — |
| 시험 | `DP` · `성적(%)` · `평균` · `시험 문자` · `시험 유형` · `클래스(그룹)` · `필터` | `클래스` · `시험 유형(그룹)` | — |
| 시험 카테고리 | `시험 날짜` · `평균` | — | — |
| 수강료 납부 | `납부 금액` · `납부 문자` · `세부 상태` · `미납 알림` · `클래스` | — | — |
| 납부 월 | 없음 | 없음 | 없음 |
| 재원생 상담 | `필터` | `클래스` | — |
| 신입생 | `학년` | — | `재원생 등록` |
| 학교 | — | `인원 수` | — |
| 클래스 공지사항 | `링크` · `공유 링크` | — | — |
| 문자 양식 | 없음 | 없음 | 없음 |

`학년`(학생·신입생)만 쓰기 경로가 따로 있습니다 — 값을 넣을 곳은 `학년 수정`(number)이고, formula 인 `학년` 이 그 값을 읽습니다.

`학생 과목별 페이지` 의 `학생 전화번호` 는 formula 입니다(`학생` DB 의 같은 이름 속성은 phone_number 입니다). 번호를 고칠 때는 `학생` DB 에 씁니다.

**버튼은 클로드가 누를 수 없습니다.** 값을 쓸 수 없는 것과 별개로 실행도 못 합니다 — 버튼이 하는 일이 필요하면 원장에게 눌러 달라고 안내합니다(`academy-enroll`).

## 제목 속성이 빈 데이터베이스

다음 데이터베이스들은 제목 속성의 **이름 자체가 빈 문자열**입니다:
- `출석부`
- `과제`
- `시험`
- `수강료 납부`
- `재원생 상담`

이는 설계된 것이므로 이름을 채우려 하지 않습니다. SQL 조회에서 `SELECT *`를 쓰고 빈 이름 컬럼을 직접 지정하지 않습니다. 지정하면 파싱 오류가 납니다.

**`과제` 는 제목 이름은 비어 있지만 값은 채웁니다** — 과제 이름(`과제 안내` 와 같은 값)을 넣습니다(`academy-homework`). SQL 로 과제를 찾을 때는 제목 컬럼 대신 같은 값인 `과제 안내` 로 대조합니다.

## 문자 양식 변수

알림톡 문구는 `문자 양식` DB 의 `문자 양식`(text)에 `#{변수}` 를 넣어 만듭니다. 템플릿의 `양식(...)` 수식이 학생마다 변수를 채우고, Make 가 보냅니다. **클로드는 발송하지 않습니다.**

**변수 이름 규칙:** `#{X}` 의 `X` 는 `학생 과목별 페이지` 의 속성 이름에서 **띄어쓰기를 뺀 것**과 글자까지 같아야 합니다.

| 변수 | 속성 |
|---|---|
| `#{이름}` | `이름` |
| `#{출석문자}` | `출석문자` |
| `#{시험문자}` | `시험문자` |
| `#{과제문자}` · `#{과제안내}` | `과제문자` · `과제안내` |
| `#{납부문자}` · `#{미납문자}` | `납부문자` · `미납문자` |
| `#{개별페이지링크}` · `#{클래스공지링크}` | `개별 페이지 링크` · `클래스 공지 링크` |
| `#{클로드총평}` | `클로드총평` — 클로드가 쓰는 유일한 속성입니다(`academy-message`) |
| `#{위클리출결}` · `#{위클리시험}` · `#{위클리과제}` | `위클리출결` · `위클리시험` · `위클리과제` |

이 표는 편의용 요약이고, **판정 기준은 위 규칙**입니다. 원장이 속성을 새로 만들면 그 이름에서 띄어쓰기를 뺀 것도 변수가 됩니다. 템플릿의 「나만의 양식 만들기」 설명에 적힌 `#{출결문자}` 는 오타이며 그런 속성은 없습니다 — 맞는 것은 `#{출석문자}` 입니다.

`문자 양식` 의 `선택` 값 「출석알림」과 수식 이름 `양식(출결알림)` 은 표기가 다르지만 같은 종류를 가리킵니다.

**발송 시각:** 출결 알림은 출석부에 행이 생기는 순간 나갑니다. 리포트·납부 알림은 Make 가 정해진 시간에 보냅니다. 그래서 `클로드총평` 은 **그 발송 시각 전에** 써 둬야 문자에 실립니다.

수식 값은 도구로 읽을 수 없습니다(`query-limits.md`). 클로드는 변수 **이름**만 대조하고, 채워진 결과는 원장이 노션에서 봅니다.
