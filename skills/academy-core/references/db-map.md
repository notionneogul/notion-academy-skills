# 데이터베이스 지문과 설정 파일 규격

## 설정 파일 규격

스킬은 사용자의 노션 템플릿과 연결하기 위해 설정 파일을 읽습니다. 경로는 `~/.academy/config.json`입니다.

파일 형식은 다음과 같습니다:

```json
{
  "template_version": "2.0",
  "root_page": "https://www.notion.so/...",
  "connected_at": "2026-08-21",
  "databases": {
    "학생": "collection://...",
    "학생 과목별 페이지": "collection://...",
    "클래스": "collection://...",
    "출석부": "collection://...",
    "과제": "collection://...",
    "시험": "collection://...",
    "시험 카테고리": "collection://...",
    "수강료 납부": "collection://...",
    "납부 월": "collection://...",
    "재원생 상담": "collection://...",
    "신입생": "collection://...",
    "학교": "collection://...",
    "클래스 공지사항": "collection://...",
    "문자 양식": "collection://...",
    "과제 M": "collection://..."
  },
  "message_formats": {
    "주간 리포트": "원장이 준 문자 예시 원문…"
  },
  "send": {
    "provider": "solapi",
    "api_key": "원장이 직접 넣습니다",
    "api_secret": "원장이 직접 넣습니다",
    "sender_key": "카카오 발신프로필 키",
    "sender_phone": "01012345678",
    "oopy_domain": "https://academy.oopy.io",
    "unit_price": { "알림톡": 9, "문자": 20 },
    "templates": {
      "월간 리포트": {
        "template_id": "…",
        "name": "2026 월간 리포트",
        "variables": ["클로드출결", "클로드시험", "클로드과제", "클로드총평", "클로드다음과제"],
        "fixed_length": 122
      }
    }
  }
}
```

- `template_version`: 템플릿 버전(문자열)
- `root_page`: 루트 페이지 URL(문자열)
- `message_formats`: **선택 키입니다.** `academy-message` 가 원장이 준 문자 예시를 이름 붙여 저장하는 곳입니다. 없어도 정상이고, **없다고 해서 미연결로 보지 않습니다** — 연결 판정은 `databases` 만 봅니다. 노션이 아니라 이 파일에 두는 이유는 `academy-message` 의 「양식 확인」 절에 있습니다.
- `send`: **선택 키입니다.** `academy-send` 가 알림톡·문자를 실제로 보낼 때 읽는 값이고, 세팅 절차는 `academy-send` 의 `references/setup.md` 에 있습니다. 없으면 **알림톡 갈래 전체가 멈춥니다** — 발송뿐 아니라 `academy-template` 이 `variables`·`fixed_length` 를 저장하는 자리와 `academy-message` 알림톡 모드가 그 목록을 읽는 자리가 같은 키이기 때문입니다. **나머지 아홉 스킬과 `academy-message` 의 문자 모드는 정상입니다.** `message_formats` 와 마찬가지로 **없다고 해서 미연결로 보지 않습니다** — 연결 판정은 `databases` 만 봅니다.
  - `provider`: 발송 대행사(문자열, 현재 `solapi`)
  - `api_key`·`api_secret`: **원장이 직접 넣습니다.** 스킬은 읽어서 호출에만 쓰고 **화면에 출력하지 않습니다** — 원장이 채팅에 붙여넣더라도 클로드가 이 파일에 대신 써 넣지 않습니다
  - `sender_key`: 카카오 발신프로필 키(알림톡이 나가는 채널)
  - `sender_phone`: Solapi 에 등록·인증된 발신번호(문자로 나갈 때)
  - `oopy_domain`: 우피 도메인. 알림톡 버튼 URL 과 `academy-message` 의 `#{개별페이지링크}` 가 `<oopy_domain>/<페이지 id 에서 대시 제거>` 로 조립됩니다. **추측해서 만들지 않습니다** — 없으면 그 자리를 비웁니다
  - `unit_price`: 채널별 건당 단가입니다. 원 단위 정수이고 모양은 `{ "알림톡": 9, "문자": 20 }` 입니다. **Solapi 에 단가를 알려 주는 경로가 없어 원장이 콘솔의 요금 안내에서 읽어 줍니다.** `academy-send` 가 미리보기에서 예상 요금(건수 × 채널 단가)을 계산할 때 씁니다 — 이 값이 없으면 요금을 계산할 수 없습니다
  - `templates`: 원장이 붙인 상황 이름표를 알림톡 템플릿에 매핑합니다. 콘솔 목록에는 학원과 무관한 템플릿이 섞여 있으므로 원장이 고른 것만 들어갑니다. 위 예시는 `academy-template` 이 속성을 만들고 본문을 뽑아 준 월간 리포트 템플릿입니다 — **실측으로 확인된 「2026 학원관리」 템플릿의 변수 11개는 이것과 다릅니다**(`academy-send` 의 `references/setup.md` 「5. 변수 확인」)
    - `template_id`·`name`: 원장이 솔라피 콘솔에서 읽어 주는 값입니다. 넣는 절차는 `academy-send` 의 `references/setup.md` 「4. 템플릿 고르기」입니다
    - `variables`: 그 템플릿의 `#{변수}` 자리에 대응하는 **속성명 목록**(문자열 배열)입니다. 변수명과 `학생 과목별 페이지` 속성명이 글자까지 같아야 하므로 **이 목록이 어떤 이름을 쓰는지의 권위 목록**입니다. **선택 키입니다** — `academy-template` 이 만든 템플릿에만 들어 있고, `setup.md` 「4. 템플릿 고르기」로 기존 템플릿을 골라 등록만 한 항목에는 없습니다. 없으면 어느 속성을 읽을지 알 수 없으므로 `academy-template` 을 안내하고 멈춥니다(아래 「지문표에 넣지 않는 속성」과 같은 처리입니다). **`academy-send` 도 이 키를 읽어 갈래를 가릅니다** — 있으면 그 속성값을 **노션에서 그대로 읽어** 변수에 넣고 원본에서 다시 계산하지 않으며, 없으면 변수가 formula 를 가리키는 것으로 보고 원본 데이터에서 계산합니다(「절차 — 발송」 3단계). 그래서 `setup.md` 「4. 템플릿 고르기」로 등록만 한 템플릿의 발송은 이 키가 없어도 그대로 됩니다. **Solapi 발송 요청 본문의 `kakaoOptions.variables` 와는 다른 것입니다** — 그쪽은 `#{...}` 꼴 키에 값을 담은 것이고(`#{이름}` 처럼 이 목록에 없는 변수도 그쪽에는 들어갑니다)(`academy-send` 의 「절차 — 발송」), 이 키는 `#{}` 없는 속성명만 나열합니다
    - `fixed_length`: 변수 자리를 뺀 **고정 본문 글자수**(정수, 줄바꿈 포함)입니다. `academy-message` 의 알림톡 모드가 학생별 본문이 상한에 드는지 판정할 때 이 값에 변수 값 길이를 더합니다 — 없으면 변수 합계만 세고 정확하지 않다고 밝힙니다. 위 예시의 `122` 는 `academy-template` 이 만든 본문 하나를 실제로 센 값입니다
- `connected_at`: 연결 날짜(문자열, `YYYY-MM-DD` 형식)
- `databases`: 한글 데이터베이스명을 `collection://<uuid>` 형식의 문자열에 매핑합니다(15개)

파일이 없거나 `databases` 키에 15개 미만의 데이터베이스가 있으면 연결되지 않은 상태로 보고 `academy-setup` 실행을 안내한 뒤 중단합니다.

## 스키마 지문표

각 데이터베이스는 이름만으로 판별하지 않고 다음 속성 조합으로 확인합니다:

| 데이터베이스 | 지문 (이 속성들이 모두 있어야 한다) |
|---|---|
| 학생 | `이름`(title) · `생년월일`(date) · `성별`(select: 남/여) · `학년 수정`(number, 수식 `학년`의 수동 보정값) · `학교`(relation→학교) · `학부모 전화번호`·`학생 전화번호`(phone_number) · `특이사항`(text) · `퇴원 날짜`(date) · `학생 과목별 페이지`(relation→학생 과목별 페이지) |
| 학생 과목별 페이지 | `이름`(title) · `학생`(relation→학생) · `클래스`(relation→클래스) · `출석부`(relation→출석부) · `과제`(relation→과제) · `시험`(relation→시험) · `재원생 상담`(relation→재원생 상담) · `수강료 납부`(relation→수강료 납부) · `문자 양식`(relation→문자 양식) · `KPI 점수`(formula) · `전송완료`(checkbox) |
| 클래스 | `클래스명`(title) · `참여 요일`(multi_select) · `시작 시간`(text) · `운영시간(분)`(number) · `담당 선생님`(select) |
| 출석부 | `출석 날짜`(date) · `출결상태`(select: 출석/지각/미출석/보강) · `보강 날짜`(date) · `보강완료`(checkbox) · `학생`(relation→**학생 과목별 페이지**) |
| 과제 | `수업 날짜`(date) · `수업 진도`(text) · `과제 안내`(text) · `평가`(select: 우수/보통/미흡) · `피드백`(text) · `이름 붙여넣기`(relation→**학생 과목별 페이지**) · `과제 M`(relation→과제 M) |
| 시험 | `시험 날짜`(date) · `점수`·`재시험 점수`(number) · `평가`(select: 통과/재시험/미응시) · `피드백`(text) · `시험 카테고리`(relation→시험 카테고리) · `이름 붙여넣기`(relation→**학생 과목별 페이지**) |
| 시험 카테고리 | `시험명`(title) · `유형`(select: 단어시험/모의고사/데일리테스트/주간평가/월간평가) · `총점`(number) · `시험`(relation→시험) |
| 수강료 납부 | `수강료`(number, 원) · `상태`(status: 미납/납부 완료) · `납부 날짜`(date) · `납부 월`(relation→납부 월) · `이름 붙여넣기`(relation→**학생 과목별 페이지**) |
| 납부 월 | `납부 년월`(title) — 속성이 이것 하나뿐인 것이 지문이다 |
| 재원생 상담 | `상담 날짜`(date) · `상담 기록`(text) · `이름 붙여넣기`(relation→**학생 과목별 페이지**) |
| 신입생 | `이름`(title) · `상태`(status: 상담 전/상담 중/등록 완료/미등록) · `상담 날짜`(date) · `생년월일`(date) · `성별`(select: 남/여) · `학년 수정`(number) · `학교`(relation→학교) · `학부모 전화번호`·`학생 전화번호`(phone_number) · `특이사항`(text) · `재원생 등록`(button) |
| 학교 | `학교명`(title) · `선택`(select: 초등학교/중학교/고등학교) · `인원 수`(rollup) |
| 클래스 공지사항 | `이름`(title) · `클래스`(relation→클래스) · `공유 링크`(formula) |
| 문자 양식 | `이름`(title) · `문자 양식`(text) · `사용`(checkbox) · `학생`(relation→**학생 과목별 페이지**) |
| 과제 M | 빈 이름의 title · `과제`(relation→과제) — 마스터 테이블. 행 1건뿐이고 모든 과제 행이 이것을 가리킨다 |

## 지문표 참고

### 이름이 오해를 부르는 relation

relation 속성의 **이름과 실제 대상 DB가 다릅니다.** 위 표에서 굵게 표시한 것들이 그렇습니다.

| 속성 | 있는 곳 | 실제 대상 |
|---|---|---|
| `학생` | 출석부 | `학생 과목별 페이지` (`학생` DB가 아닙니다) |
| `학생` | 문자 양식 | `학생 과목별 페이지` |
| `이름 붙여넣기` | 과제 · 시험 · 수강료 납부 · 재원생 상담 | 전부 `학생 과목별 페이지` |

출석부·과제·시험·수강료 납부·재원생 상담에서 사람 이름을 얻으려면 `학생 과목별 페이지`를 거쳐 `학생` DB까지 두 단계를 가야 합니다. 한 단계로 끝난다고 보고 짠 조회는 빈 결과를 냅니다.

지문이 맞지 않으면 조용히 넘어가지 않습니다. 어느 데이터베이스가 어떤 속성 때문에 어긋났는지 사용자에게 보고하고 멈춥니다. 이는 템플릿 버전이 다르거나 사용자가 속성 이름을 바꾼 경우입니다.

### 지문표에 넣지 않는 속성

**`학생 과목별 페이지` 의 `클로드 문자`(text) 는 지문이 아닙니다.** 최초 스캔 이후에 추가된 속성이라, 그 전에 템플릿을 복제한 사본에는 없을 수 있습니다. 지문에 넣으면 이 속성 하나 때문에 13개 스킬 전부가 연결 단계에서 멈춥니다. 이 속성이 실제로 필요한 것은 `academy-message` 하나뿐이므로, **그 스킬이 시작할 때 있는지 확인**하고 없으면 그 스킬만 안내하고 멈춥니다(`academy-message` 「시작 전에 읽는다」).

같은 기준을 앞으로 추가되는 속성에도 적용합니다 — **구매자 사본마다 있고 없고가 갈릴 수 있는 속성은 지문표가 아니라 그것을 쓰는 스킬의 시작 확인으로 옮깁니다.**

**알림톡 변수 속성군(`클로드출결`·`클로드시험`·`클로드과제`·`클로드총평`·`클로드다음과제` 등)도 지문이 아닙니다.** `academy-template` 이 알림톡 템플릿을 준비할 때 만드는 속성이라, 알림톡을 쓰지 않는 구매자 사본에는 아예 없습니다. 지문에 넣으면 그분들의 연결이 전부 멈춥니다. 이 속성들이 필요한 것은 `academy-message` 의 알림톡 모드 하나뿐이므로, **그 모드가 시작할 때 있는지 확인**하고 없으면 `academy-template` 을 안내하고 멈춥니다.

속성 이름은 원장이 등록한 알림톡 템플릿의 변수명과 같아야 하므로 **사본마다 다를 수 있습니다.** 위 다섯은 기본값일 뿐이고, 어떤 이름을 쓰는지는 `~/.academy/config.json` 의 `send.templates.<이름>.variables` 가 권위 목록입니다.

## DB별 쓰기 불가 속성

`domain-rules.md` 「쓰기 불가 속성」이 가리키는 권위 목록입니다. **formula·rollup·button 에는 값을 쓰지 않습니다** — 무시되거나 실패합니다. 각 쓰기 스킬의 「쓰지 않는 것」은 이 표를 가리키고 자기 DB 한 줄만 남깁니다. 출처는 `templates/2027-academy-operation-pro/schema-map.md` 의 실측 스캔입니다.

| 데이터베이스 | formula | rollup | button |

## 제목 속성이 빈 데이터베이스

다음 데이터베이스들은 제목 속성의 **이름 자체가 빈 문자열**입니다:
- `출석부`
- `과제`
- `시험`
- `수강료 납부`
- `재원생 상담`
- `과제 M`

이는 설계된 것이므로 채우려 하지 않습니다. SQL 조회에서 `SELECT *`를 쓰고 빈 이름 컬럼을 직접 지정하지 않습니다. 지정하면 파싱 오류가 납니다.
