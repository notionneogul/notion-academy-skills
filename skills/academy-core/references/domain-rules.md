# domain-rules.md — 정합성 규칙

위반하면 데이터가 깨지는 규칙이다. 쓰기 전에 검증한다.

각 규칙에 **어겼을 때 실제로 일어난 일**을 한 줄로 남긴다. 규칙을 지켜야 하는 이유가 추상적이면 무시되기 때문이다.

| 규칙 | 내용 | 어긴 결과 | 검증 방법 |
|---|---|---|---|
| 클래스 요일 정합 | 출결·과제·시험 날짜는 그 학생 클래스의 `참여 요일`에만 존재한다. **보강은 이 규칙의 대상이 아니다** — `보강 예정일`, 그리고 `출결상태` 가 `보강` 인 출석부 행의 `출석 날짜` 는 정규 요일 밖에 있는 것이 정상이다 | 화요일에 월수금반 수업이 생긴다 | 대상 행의 학생 과목별 페이지 → `클래스` → `참여 요일` 을 조회하고, 날짜의 요일이 그 안에 있는지 본다. `보강 예정일` 컬럼과 `출결상태 = 보강` 인 행은 이 대조에서 뺀다 |
| 과제 평가 대상 | 과제 행의 `평가`·`피드백` 은 **그 행의 과제(제목)** 를 채점한 값이다. 과제는 학생마다 한 행이고, 같은 날 과제가 여럿이면 행도 여럿이며 각자 자기 평가를 갖는다 | 한 과제의 평가가 다른 과제에 붙어 학부모 문자에 엉뚱한 평가가 나간다 | 평가를 쓰려는 행의 제목(`과제 안내` 와 같은 값)이 원장이 말한 과제와 같은지 본다. 그 학생·그 날짜 과제가 둘 이상인데 어느 과제인지 말하지 않았으면 되묻는다 |
| 보강 | ① **예약** — 결석·지각 행의 `보강 예정일` 을 채운다(기존 행 수정). ② **완료** — 출석부에 **새 행**(`출결상태` = `보강`, `출석 날짜` = 그 결석 행의 `보강 예정일`, `학생` = 같은 과목 페이지, `보강완료` 는 비움)을 만든 **뒤** 원래 결석 행의 `보강완료` 를 켠다. 원래 행의 `출결상태` 는 스킬이 바꾸지 않는다. 순서는 새 행 → 체크다. 체크가 실패하면 성공으로 보고하지 않고 「기록은 만들어졌지만 원래 행 체크 실패」로 알린다. 같은 학생·같은 날에 `출결상태 = 보강` 행이 이미 있으면 새 행을 건너뛰고 체크만 한다. `보강완료` 를 켤 때는 `보강 예정일` 이 채워져 있어야 한다. QR 출결 위젯도 같은 규칙을 따른다 | 체크박스만 켜면 출석부에 행이 생기지 않아 **Make 가 출결 알림톡을 보내지 않는다**(Make 는 행 생성을 보고 보낸다). 체크를 먼저 하고 새 행이 실패하면 결석이 해결된 것처럼 보이는데 보강 기록도 문자도 없다 | `보강완료` 가 켜진 결석 행마다, 같은 `학생` 과 그 `보강 예정일` 로 `출결상태 = 보강` 인 행이 있는지 본다. 없으면 옛 방식으로 처리돼 문자가 안 나간 행이다 |
| 점수 상한 | `점수`·`재시험 점수` ≤ 해당 시험 카테고리의 `총점` | `성적(%)`이 237%를 출력한다 | 시험 행의 `점수`·`재시험 점수` 를 `시험 카테고리` → `총점` 과 비교한다 |
| 과목 페이지 필수 | 학생만 만들면 출결·과제가 붙을 곳이 없다 | 학생이 시스템에 나타나지 않는다 | 학생 행의 `학생 과목별 페이지` relation 이 비어 있는지 본다 |
| 퇴원 정합 | 퇴원 날짜 이후의 출결·과제·시험·수강료 행을 만들지 않는다. **재원생 상담은 대상이 아니다** — 퇴원 사유 상담·종료 상담은 퇴원일 이후에 하는 것이 정상이다 | 퇴원생이 계속 출석한다 | 학생의 `퇴원 날짜` 이후 날짜를 가진 출결·과제·시험·수강료 행이 있는지 본다 |
| 쓰기 불가 속성 | formula·rollup·button에는 값을 쓰지 않는다 | 무시되거나 실패한다 | `db-map.md` 「DB별 쓰기 불가 속성」 표가 권위 목록이다. 쓰려는 속성이 그 DB 줄에 있으면 넣지 않는다 — 지문표는 있어야 할 속성만 열거하므로 지문표만 보면 목록이 모자란다 |
| 발송 | **어떤 스킬도 알림톡·문자를 발송하지 않는다.** 출결 알림은 출석부에 행이 생기면 Make 가 곧바로 보내고, 데일리·위클리 리포트와 납부·미납 알림은 Make 가 정해진 시간에 루틴으로 보낸다. 문구는 `문자 양식` DB 의 행을 템플릿 수식이 채워 만든다(`db-map.md` 「문자 양식 변수」). 원장이 「보내줘」라고 하면 이 방식을 설명하고, 문구를 바꾸려면 `academy-template`, 총평을 넣으려면 `academy-message` 로 안내한다 | 클로드가 보내면 되돌릴 수 없는 문자가 승인 흐름 밖에서 나간다 | 스킬 문서 어디에도 발송 API 호출 절차가 없는지 본다 |

## 도구로 확인할 수 없는 것

템플릿 자동화(노션 자동화·버튼·Make 시나리오)가 무엇을 하는지는 도구로 읽을 수 없다. 예전 템플릿에는 `보강완료` 를 켜면 원래 행의 `출결상태` 를 `보강` 으로 덮어쓰는 자동화가 있었다. 개편판에서도 그런지는 확인되지 않았다 — 스킬은 `출결상태` 를 바꾸지 않을 뿐이고, 자동화가 바꾸면 그대로 둔다.

## 영구 기록이 아닌 속성

`학생 과목별 페이지` 의 `전송완료`(checkbox) 는 템플릿 자동화가 **주기적으로 초기화한다.** 역대 발송 이력이 아니라 최근 주기 안의 발송 여부이므로, 과거에 문자를 보냈는지의 근거로 삼지 않는다. 전원이 미체크로 나오는 것은 정상일 수 있다.
