# domain-rules.md — 정합성 규칙

위반하면 데이터가 깨지는 규칙이다. 쓰기 전에 검증한다.

각 규칙에 **어겼을 때 실제로 일어난 일**을 한 줄로 남긴다. 규칙을 지켜야 하는 이유가 추상적이면 무시되기 때문이다.

| 규칙 | 내용 | 어긴 결과 | 검증 방법 |
|---|---|---|---|
| 클래스 요일 정합 | 출결·과제·시험 날짜는 그 학생 클래스의 `참여 요일`에만 존재한다 | 화요일에 월수금반 수업이 생긴다 | 대상 행의 학생 과목별 페이지 → `클래스` → `참여 요일` 을 조회하고, 날짜의 요일이 그 안에 있는지 본다 |
| 저번 과제 방향 | 과제 행의 `평가`·`피드백`은 **직전 행 과제**의 채점이다. 각 과목 페이지의 첫 수업 행은 비운다 | 학부모 문자에 평가가 빈칸으로 나간다 | 같은 과목 페이지의 과제 행을 `수업 날짜` 오름차순으로 세우고, 첫 행만 `평가`·`피드백` 이 비어 있는지 본다 |
| 보강 자동화 | `보강 날짜`·`보강완료`를 채우면 템플릿 자동화가 `출결상태`를 `보강`으로 덮어쓴다. 또한 `보강완료`와 `보강 날짜`는 **함께** 채운다 — 보강완료만 체크하고 날짜를 비우지 않는다 | 지각으로 넣었는데 보강이 된다. 보강완료만 체크된 행은 언제 보강했는지 알 수 없어 보강 이력이 사라진다 | `보강 날짜` 나 `보강완료` 를 쓰면 `출결상태` 가 `보강` 으로 덮이므로, 지각·미출석을 유지하려면 두 속성을 비운 채 둔다. `보강완료` 가 체크되어 있는데 `보강 날짜` 가 비어 있는 행이 있는지도 함께 본다 |
| 점수 상한 | `점수`·`재시험 점수` ≤ 해당 시험 카테고리의 `총점` | `성적(%)`이 237%를 출력한다 | 시험 행의 `점수`·`재시험 점수` 를 `시험 카테고리` → `총점` 과 비교한다 |
| 과목 페이지 필수 | 학생만 만들면 출결·과제가 붙을 곳이 없다 | 학생이 시스템에 나타나지 않는다 | 학생 행의 `학생 과목별 페이지` relation 이 비어 있는지 본다 |
| 퇴원 정합 | 퇴원 날짜 이후의 출결·과제·수강료 행을 만들지 않는다 | 퇴원생이 계속 출석한다 | 학생의 `퇴원 날짜` 이후 날짜를 가진 출결·과제·수강료 행이 있는지 본다 |
| 쓰기 불가 속성 | formula·rollup·button에는 값을 쓰지 않는다 | 무시되거나 실패한다 | `db-map.md` 지문표에서 formula·rollup·button으로 표시된 속성에는 값을 넣지 않는다 |

## 영구 기록이 아닌 속성

`학생 과목별 페이지` 의 `전송완료`(checkbox) 는 템플릿 자동화가 **주기적으로 초기화한다.** 역대 발송 이력이 아니라 최근 주기 안의 발송 여부이므로, 과거에 문자를 보냈는지의 근거로 삼지 않는다. 전원이 미체크로 나오는 것은 정상일 수 있다.
