# completeness-checks.md — 누락 확인 규칙

항목을 세 갈래로 나눈다. 세 번째가 없으면 매번 잔소리가 된다.

| 분류 | 처리 |
|---|---|
| 필수 | 없으면 쓰기를 중단하고 묻는다 |
| 되물음 | 비어도 쓸 수는 있지만 한 번 확인한다 |
| 공란 허용 | 묻지 않는다 |

| 스킬 | 되물어야 할 것 |
|---|---|
| 출결 | 지각·미출석인데 보강 날짜가 없음 |
| 과제 | 수업 진도 없음 · 직전 행 평가가 비어 있음 · 진도만 주고 과제를 안 줌 |
| 시험 | 총점을 안 줌 · 재시험 평가인데 재시험 점수 없음 · 점수가 총점 초과(오류) |
| 신입생 등록 | 어느 클래스 · 과목 페이지도 만들지 · 수강료 · 첫 등원일 |
| 수강료 마감 | 형제 할인 · 결석 차감 · 중도 등록·퇴원 일할 계산 |
| 문자 생성 | 최근 데이터가 오래된 경우 그대로 보낼지 |
| 시간표 변경 | 새 요일과 어긋나는 기존 행을 어떻게 할지 |
| import | 확신도 낮은 열 · 노션에 없는 클래스 · 과목 페이지 생성 여부 |

공란 허용 목록: 각 과목 페이지 마지막 행의 `평가`·`피드백`, 출석부·과제·시험의 제목(설계상 빈 속성), 수강료 `비고`, 중학생의 `학생 전화번호`.

되묻는 방식 세 가지.

1. **한 번에 묶어서 묻는다.** 항목마다 왕복하면 원장이 지친다.
2. **기본값을 제시하며 묻는다.** "수업 진도가 뭔가요?"가 아니라 "진도는 비워둘까요, 아니면 지난 수업 `수열의 극한` 이어서 넣을까요?"라고 묻는다. 직전 행을 읽어 후보를 제시하면 "응" 한 마디로 끝난다.

   ```
   ❌ "수업 진도가 뭔가요?"
   ⭕ "진도는 비워둘까요, 아니면 지난 수업 `수열의 극한` 이어서 넣을까요?"
   ```

3. **공란 허용은 묻지 않는다.**
