# write-safety.md — 쓰기 경계

이 표에 없는 동작은 하지 않는다. 애매하면 사용자에게 묻는다.

| 동작 | 경계 |
|---|---|
| 행 추가 | 미리보기 표 + 승인 (`write-gate.md` 4단계) |
| 이번 실행에서 자기가 만든 행 수정 | 자율 |
| 기존 행 수정 | 건별 승인 |
| 행을 보관 페이지로 이동 | 일괄 승인 + 되돌리기 안내 |
| 보관 페이지 본문에 되돌리기 목록 쓰기 | 이동 승인에 포함된다. 따로 묻지 않는다 — 목록이 없으면 되돌릴 수 없다 |
| 스키마 변경 — 속성 추가 | 미리보기 + 승인 (`write-gate.md` 4단계). **`academy-template` 만 한다** |
| 스키마 변경 — 속성 삭제·이름 변경 | **하지 않는다** — 삭제는 전 학생분 값이 되돌릴 수 없이 사라지고(발송보다 나쁘다), 이름 변경은 등록된 알림톡 템플릿의 변수와 어긋난다. 원장이 노션에서 직접 한다 |
| 스키마 변경 — 그 밖(옵션 변경 등) | 금지 |
| 알림톡·문자 발송 | 미리보기 + 명시적 승인. 승인 없이는 한 통도 보내지 않는다 (`academy-send`). **되돌릴 수 없다** — 쓰기와 달리 보관 페이지로 되돌리는 방법이 없다 |
| DB 휴지통 이동 | 금지 |

## 되돌리기 절차

행을 보관 페이지로 옮긴 뒤 되돌리려면 `notion-move-pages` 의 `new_parent` 를 `{"type": "data_source_id", "data_source_id": "<원래 DB의 uuid>"}` 로 주면 된다. 이렇게 하면 날짜·select·relation 값이 전부 복원된다. 이는 실측으로 확인된 동작이다.

`~/.academy/config.json` 의 `databases` 값은 `collection://<uuid>` 형식으로 저장되어 있다. **접두어 `collection://` 를 떼고 uuid 만 넣는다.** 접두어를 붙인 채 넣으면 실패한다.
