# name-resolution.md — 사람 이름을 과목 페이지 uuid로 바꾸기

일곱 쓰기 스킬 전부가 같은 문제를 푼다: 원장이 말한 **사람 이름**을 relation에 넣을 **과목 페이지 uuid**로 바꾸는 것. 쿼리 자체의 제약(JOIN 불가, uuid 정규화, LIKE 조건)은 `query-limits.md` 를 따른다 — 여기서는 반복하지 않고 그 규칙을 이 문제에 적용하는 절차만 적는다.

## 문제

과목 페이지(`학생 과목별 페이지`)의 `이름` 은 `박시우 영어` 형식이라 사람 이름이 아니다. 출석부·과제·시험·상담·수강료의 relation은 전부 과목 페이지를 가리키지 학생을 가리키지 않는다.

**이름이 `학생` 인 relation도 대상은 과목 페이지다.** 출석부의 `학생` 속성, 문자 양식의 `학생` 속성 모두 그렇다. `db-map.md` 의 "이름이 오해를 부르는 relation" 표에 있는 사실이며, 이름 해석에서 가장 자주 틀리는 지점이다. `학생` 이라는 이름만 보고 학생 DB를 조회하면 그 uuid는 어느 relation과도 맞지 않는다.

절차는 세 갈래다. 어느 갈래든 마지막에는 과목 페이지의 url(들)을 얻는 것으로 끝난다.

## 학생 이름으로 지정

"김서준 지각" 처럼 개인을 지목하는 발화.

1. 학생 DB에서 이름으로 조회한다.

   ```sql
   SELECT id, url, "이름", "date:생년월일:start", "학교", "date:퇴원 날짜:start" FROM "collection://<학생>" WHERE "이름" = '김서준'
   ```

   **`date:퇴원 날짜:start` 를 SELECT 목록에서 빼지 않는다.** 이 쿼리가 이름 해석의 유일한 학생 DB 조회이고, `write-gate.md` 2단계 (라) 퇴원 검증이 근거로 삼는 값이 이 컬럼이다 — 여기서 안 읽으면 이름으로 지목한 경로에서 퇴원 판정 근거가 아예 사라진다. **값이 있으면 그대로 `write-gate.md` 2단계 (라)로 넘긴다**(막지 않고 알린다).

   0행이면 오타이거나 미등록이다. 임의로 비슷한 이름을 골라 진행하지 않는다. 이름을 다시 확인하거나, 신입생 DB(`신입생`)에 같은 이름이 있는지 함께 찾아본다.

2. 동명이인이면(2행 이상 반환) 생년월일과 **학교명**을 보여주고 되묻는다. 위 조회에서 얻는 `학교` 값은 relation이라 uuid를 담은 URL일 뿐 학교명이 아니다 — JOIN이 없으므로(`query-limits.md`) 학교 DB를 따로 읽어 이름으로 바꿔야 한다. 학교 DB는 행이 적으므로 통째로 읽는다.

   ```sql
   -- 학교 DB는 학생 수와 무관하게 개수가 고정에 가까우므로 통째로 읽는다
   SELECT id, "학교명" FROM "collection://<학교>"
   ```

   동명이인 각 학생의 `학교` 값(대시 없는 uuid)과, 학교 DB 조회 결과의 `id`(대시를 제거해 정규화한 값)를 대조해 학교명을 얻은 뒤 되묻는다.

   > 김서준이 두 명입니다 — 2011-03-14생 (신설중학교), 2010-09-02생 (동산중학교). 누구인가요?

3. 학생의 id를 대시 없이 정규화해, 과목 페이지에서 그 학생의 과목 페이지를 전부 얻는다.

   ```sql
   SELECT id, url, "이름" FROM "collection://<학생 과목별 페이지>" WHERE "학생" LIKE '%<대시 없는 학생 uuid>%'
   ```

4. 과목이 여럿이면 어느 과목인지 되묻는다. 단, 발화에 클래스가 있으면("고2 수학 심화 A 김서준") 그것으로 좁혀 되묻지 않는다.

   **날짜가 있으면 클래스가 없어도 좁힐 수 있다.** 과목이 여럿이어도 **그날 수업이 있는 클래스가 하나뿐이면** 그것으로 좁히고 되묻지 않는다. 각 과목 페이지의 클래스 `참여 요일` 을 날짜의 요일과 대조해 판정한다. 둘 이상이 그날 수업이면 되묻는다.

## 클래스 전체 지정

"고2 수학 심화 A반 전체 출석" 처럼 반 단위로 지목하는 발화.

1. 클래스 DB에서 클래스명을 조회한다. **부분 일치를 허용한다** — "고2 수학" 으로도 「고2 수학 심화 A」 를 찾아야 한다.

   ```sql
   SELECT id, url, "클래스명" FROM "collection://<클래스>" WHERE "클래스명" LIKE '%고2 수학%'
   ```

   부분 일치가 클래스를 2개 이상 반환하면(예: "고2 수학" 이 "고2 수학 심화 A" 와 "고2 수학 기초" 둘 다에 걸리면) 어느 클래스인지 되묻는다.

2. 클래스의 id를 대시 없이 정규화해, 과목 페이지에서 소속 학생을 전부 얻는다.

   ```sql
   SELECT id, url, "이름", "학생" FROM "collection://<학생 과목별 페이지>" WHERE "클래스" LIKE '%<대시 없는 클래스 uuid>%'
   ```

3. **퇴원생을 제외한다.** 방향에 주의한다 — 2단계에서 얻은 과목 페이지의 `학생` 값은 **대시 없는** uuid를 담은 URL이고, 학생 DB의 `id`는 **대시 있는** uuid다(`query-limits.md`). 대시 있는 학생 `id`를 정규화하지 않고 그대로 필터 조건에 넣으면 절대 일치하지 않는다.

   그래서 방향을 뒤집는다. 먼저 학생 DB에서 퇴원자만 뽑는다.

   ```sql
   SELECT id FROM "collection://<학생>" WHERE "date:퇴원 날짜:start" IS NOT NULL
   ```

   이 퇴원자 `id`들을 대시 없이 정규화한 뒤, 2단계에서 이미 얻어 놓은 과목 페이지 목록의 `학생` 문자열에 그 uuid가 포함되어 있는 행을 명단에서 뺀다.

## 클래스 전체에서 일부만 예외

"고2 수학 전체 출석, 김서준만 지각" 처럼 전체를 지목하되 일부에 다른 값을 주는 발화.

1. "클래스 전체 지정" 절차로 전체 명단을 얻는다.
2. 예외로 지목된 학생을 "학생 이름으로 지정" 절차로 찾아, 그 학생의 과목 페이지 행만 값을 다르게 준비한다.
3. **미리보기 표에서 예외 행이 눈에 띄게 배치한다.** 예외를 표의 위쪽으로 올려, 나머지와 섞이지 않게 한다. 미리보기 표 자체의 형식은 `write-gate.md` 3단계를 따른다.

## 동명이인

"학생 이름으로 지정"의 2단계에서 다룬 것과 같은 규칙이다. 이름이 같은 행이 여럿 나오면 절대 임의로 하나를 고르지 않는다. `date:생년월일:start` 와 **학교명**을 함께 보여주고 되묻는다 — 이 두 값이면 원장이 즉시 구분할 수 있다. `학교` relation은 uuid이지 이름이 아니므로, 학교 DB를 따로 읽어 이름으로 바꾸는 단계를 빼먹지 않는다.

이름 조회가 **0행**이면 동명이인과 반대로 다룬다. 오타이거나 미등록이니 비슷한 이름을 임의로 골라 진행하지 않고, 이름을 다시 확인하거나 신입생 DB를 함께 찾아본다.

## 클래스명 부분 일치

"클래스 전체 지정"의 1단계에서 다룬 것과 같은 규칙이다. 원장은 클래스명을 줄여 말한다("고2 수학"). `LIKE '%<입력값>%'` 로 조회해 전체 이름("고2 수학 심화 A")을 찾아야 한다. 정확히 일치하는 조건(`=`)만 쓰면 줄여 말한 입력은 항상 빈 결과를 낸다.
