## 1. 새 시험 — "8월 21일 고2 수학 데일리테스트 30점 만점, 김서준 27 이하윤 25 박시우 29"

이 예시는 새로 시작하는 상황이다 — 앞의 예시와는 무관하고, 예시 2가 바로 이어진다.

**발화**: "8월 21일 고2 수학 데일리테스트 30점 만점, 김서준 27 이하윤 25 박시우 29"

**클로드가 하는 일**: 2026-08-21은 금요일, 「고2 수학 심화 A」(월·수·금)의 수업일이라 (가) 통과. 총점(30점)·유형(데일리테스트)이 발화에 이미 있어 되묻지 않는다. 카테고리를 먼저 조회한다.

```sql
SELECT id, url, "시험명", "총점" FROM "collection://<시험 카테고리>" WHERE "시험명" = '8/21 고2수학 데일리테스트'
```

0행 — 실측 표에도 `8/21 고2수학` 조합이 없다. 새로 만든다. 클래스약칭은 기존 카테고리(`6/24 고2수학 모의고사` 등)에서 이미 쓰인 `고2수학`을 그대로 따른다. **카테고리 자체가 새로 만들어지므로 그 카테고리를 참조하는 기존 시험 행은 있을 수 없다 — (나) 학생별 중복 조회는 생략해도 안전하다.** 발화에 김서준·이하윤·박시우 세 명만 나와 있고 "전체"라는 말이 없다 — 「학생별 점수 입력 범위」에 따라 이 세 명만 만든다(조민준에게 되묻지 않는다). 통과·재시험 여부는 언급이 없으므로 `평가`는 비워 둔다.

**미리보기**:
```
시험 카테고리에 1건(8/21 고2수학 데일리테스트, 데일리테스트, 총점 30)을 만들고,
시험에 3행을 만듭니다.

| 학생 | 점수 | 평가 | 클래스 |
|---|---|---|---|
| 김서준 | 27 | (비어 있음) | 고2 수학 심화 A |
| 이하윤 | 25 | (비어 있음) | 고2 수학 심화 A |
| 박시우 | 29 | (비어 있음) | 고2 수학 심화 A |

이대로 만들까요?
```

**결과**: "시험 카테고리 1건과 시험 3행을 만들었습니다. 잘못됐으면 \"방금 거 취소해줘\" 라고 말씀하세요."

## 2. 기존 카테고리 재사용 — "조민준 26점도 추가해줘"

**발화**: "조민준 26점도 추가해줘"

**클로드가 하는 일**: 예시 1에 바로 이어지는 상황이다(같은 날 같은 시험에 한 명 추가). 카테고리를 다시 조회한다.

```sql
SELECT id, url, "시험명", "총점" FROM "collection://<시험 카테고리>" WHERE "시험명" = '8/21 고2수학 데일리테스트'
```

1행 — 예시 1에서 만든 카테고리가 있다(총점 30). 새 카테고리를 만들지 않고 그 url을 그대로 참조한다. 조민준은 「고2 수학 심화 A」 재원생이라 (가) 클래스 대조가 이미 끝난 상태다. 이번엔 카테고리가 이미 있으므로 (나) 중복을 확인한다 — 중복 키는 날짜가 아니라 **카테고리 + 과목 페이지**다.

```sql
SELECT id, "점수", "평가" FROM "collection://<시험>" WHERE "시험 카테고리" LIKE '%<8/21 고2수학 데일리테스트 카테고리 대시 없는 uuid>%' AND "이름 붙여넣기" LIKE '%<조민준 고2 수학 과목 페이지 대시 없는 uuid>%'
```

0행 — 조민준은 아직 이 카테고리에 점수가 없다. 시험 행 1건만 추가한다.

**미리보기**:
```
시험에 1행을 만듭니다(카테고리는 기존 8/21 고2수학 데일리테스트를 그대로 씁니다).

| 학생 | 점수 | 평가 | 클래스 |
|---|---|---|---|
| 조민준 | 26 | (비어 있음) | 고2 수학 심화 A |

이대로 만들까요?
```

**결과**: "조민준의 8/21 시험 점수를 추가했습니다. 잘못됐으면 \"방금 거 취소해줘\" 라고 말씀하세요."

## 3. 총점 누락 되물음 — "8월 19일 중3 수학 시험 봤어, 서다현 27점"

**발화**: "8월 19일 중3 수학 시험 봤어, 서다현 27점"

**클로드가 하는 일**: 이 예시는 앞의 두 예시와 무관한 독립 상황이다. 2026-08-19는 수요일, 「중3 수학 정규」(월·수)의 수업일이라 (가) 통과. 하지만 **총점과 유형이 둘 다 없다** — 카테고리를 만들기 전에 반드시 물어야 한다(「총점을 반드시 묻는다」). 둘을 한 번에 묶어서 묻는다.

> 몇 점 만점 시험인가요? 유형은 무엇인가요(단어시험/모의고사/데일리테스트/주간평가/월간평가)?

원장이 "40점 만점 데일리테스트야"라고 답한다. 카테고리를 조회한다.

```sql
SELECT id, url, "시험명", "총점" FROM "collection://<시험 카테고리>" WHERE "시험명" = '8/19 중3수학 데일리테스트'
```

0행 — 실측 표에 `8/19 중3수학` 조합이 없다(같은 날짜의 `8/19 고2수학 데일리테스트`는 다른 클래스라 별개 카테고리다). 새로 만든다. 클래스약칭은 기존 카테고리(`8/12 중3수학 월간평가`, `8/17 중3수학 주간평가`)에서 쓰인 `중3수학`을 따른다. 카테고리가 새로 만들어지므로 (나) 학생별 중복 조회는 생략한다(예시 1과 같은 이유).

**미리보기**:
```
시험 카테고리에 1건(8/19 중3수학 데일리테스트, 데일리테스트, 총점 40)을 만들고,
시험에 1행을 만듭니다.

| 학생 | 점수 | 평가 | 클래스 |
|---|---|---|---|
| 서다현 | 27 | (비어 있음) | 중3 수학 정규 |

이대로 만들까요?
```

**결과**: "시험 카테고리 1건과 시험 1행을 만들었습니다. 잘못됐으면 \"방금 거 취소해줘\" 라고 말씀하세요."

## 4. 재시험 — "박시우 재시험 28점"

**발화**: "박시우 재시험 28점"

**클로드가 하는 일**: 독립 상황이다. 박시우는 「고2 수학 심화 A」·「고2 영어 내신반」 두 과목 페이지를 가지고 있고, 발화에 날짜·클래스가 없어 요일로도 좁혀지지 않는다 — 조회 전에 `name-resolution.md` 「학생 이름으로 지정」에 따라 되묻는다: "어느 과목 재시험인가요? (수학/영어)" 원장이 "수학"이라고 답한다. 「고2 수학 심화 A」 박시우 과목 페이지로 가장 최근 시험 행을 찾는다.

```sql
SELECT id, url, "date:시험 날짜:start", "점수", "평가", "시험 카테고리"
FROM "collection://<시험>"
WHERE "이름 붙여넣기" LIKE '%<박시우 고2 수학 과목 페이지 대시 없는 uuid>%'
ORDER BY "date:시험 날짜:start" DESC LIMIT 1
```

가장 최근 시험 행은 `8/19 고2수학 데일리테스트`(총점 40)이고, 원점수 22, 평가 `재시험`, 재시험 점수 공란, 피드백 "재시험 일정 조율 중"이 이미 들어 있다. **박시우의 8/19 행은 실재하지만 실측값은 35점·평가 `통과` 다** — 이 예시가 쓰는 22점·평가 `재시험`·피드백 「재시험 일정 조율 중」은 그 행의 값이 아니라 재시험 입력 절차를 보이기 위한 가정이다(그 값의 실측 주인은 김서준이다 — 위 「실측 학생별 점수 행」). `재시험 점수` 28은 총점 40을 넘지 않아 경고 없음. 기존 행 수정이다 — `점수`(22)와 `피드백`은 그대로 두고 `재시험 점수`만 채운다.

**미리보기**:
```
박시우의 8/19 시험(고2 수학 심화 A, 8/19 고2수학 데일리테스트) 재시험 점수를 채웁니다.

| 학생 | 원점수 | 재시험 점수(기존 → 변경) |
|---|---|---|
| 박시우 | 22 | (비어 있음) → 28 |

이대로 고칠까요?
```

**결과**: "박시우의 8/19 시험 재시험 점수를 28점으로 채웠습니다." 기존 행 수정이라 자동 되돌리기 대상이 아니다.

## 5. 총점 초과 경고 — "6월 27일 고2 물리 데일리테스트 재시험으로 김서준 45점 넣어줘"

**발화**: "6월 27일 고2 물리 데일리테스트 재시험으로 김서준 45점 넣어줘"

**클로드가 하는 일**: 독립 상황이다. 시험을 명시로 지목했으므로 카테고리를 바로 조회한다.

```sql
SELECT id, url, "시험명", "총점" FROM "collection://<시험 카테고리>" WHERE "시험명" = '6/27 고2물리 데일리테스트'
```

실측 표에 그대로 있다 — 총점 40. **재시험 점수 45는 총점 40을 넘는다.** `domain-rules.md` 「점수 상한」에 따라 만들기 전에 경고한다.

> ⚠️ 이 시험(6/27 고2물리 데일리테스트)의 총점은 40점인데 재시험 점수로 45점을 넣으려 합니다. 총점을 넘습니다 — 그대로 넣을까요, 점수를 다시 확인할까요?

원장이 "어 오타야, 25점이야"라고 답한다. 25로 정정해 진행한다. **김서준의 이 시험 행의 원점수는 실측 범위 밖이라 예시를 위해 가정한 값이다.**

## 6. 미응시 — "8월 20일 고2 영어 모의고사 100점 만점, 김서준 88 박시우 91, 이하윤은 결석해서 못 봤어"

**발화**: "8월 20일 고2 영어 모의고사 100점 만점, 김서준 88 박시우 91, 이하윤은 결석해서 못 봤어"

**클로드가 하는 일**: 독립 상황이다. 2026-08-20은 목요일, 「고2 영어 내신반」(화·목)의 수업일이라 (가) 통과. 총점(100)·유형(모의고사)이 이미 있어 되묻지 않는다. 카테고리를 조회한다.

```sql
SELECT id, url, "시험명", "총점" FROM "collection://<시험 카테고리>" WHERE "시험명" = '8/20 고2영어 모의고사'
```

0행 — 실측 표에 `8/20 고2영어` 조합이 없다. 새로 만든다(클래스약칭 `고2영어`는 `6/23 고2영어 모의고사` 등 기존 카테고리에서 따온다). 카테고리가 새로 만들어지므로 (나) 학생별 중복 조회는 생략한다. 재원 명단(김서준, 박시우, 이하윤) 중 이하윤은 결석했다는 발화가 있으므로, 점수는 비우고 `평가`만 `미응시`로 채운 행을 만든다 — 아예 행을 생략하지 않는다(「미응시」, 실측에도 `8/11 중3영어 단어시험`에 같은 패턴의 행이 있다).

**미리보기**:
```
시험 카테고리에 1건(8/20 고2영어 모의고사, 모의고사, 총점 100)을 만들고,
시험에 3행을 만듭니다.

| 학생 | 점수 | 평가 | 클래스 |
|---|---|---|---|
| 김서준 | 88 | (비어 있음) | 고2 영어 내신반 |
| 박시우 | 91 | (비어 있음) | 고2 영어 내신반 |
| 이하윤 | (비어 있음) | 미응시 | 고2 영어 내신반 |

이대로 만들까요?
```

**결과**: "시험 카테고리 1건과 시험 3행을 만들었습니다. 잘못됐으면 \"방금 거 취소해줘\" 라고 말씀하세요."
