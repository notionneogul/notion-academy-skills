# 시험 입력

## 시작 전에 읽는다

- `../academy-core/references/db-map.md` — DB id 를 얻는다. `시험`·`시험 카테고리` 의 `collection://<uuid>` 가 여기 있다
- `../academy-core/references/write-gate.md` — 쓰기 관문 일곱 단계(되물음 → 사전 검증 → 미리보기 표 → 승인 → 쓰기 → 결과 보고 → 남은 항목 확인). 이 스킬은 이 절차를 그대로 따르되, 아래 「절차」에는 이 스킬 고유의 것만 적는다
- `../academy-core/references/name-resolution.md` — 발화의 사람 이름을 `이름 붙여넣기` relation에 넣을 **과목 페이지** url로 바꾸는 절차
- `../academy-core/references/query-limits.md` — 조회를 시작하기 전에 반드시 읽는다. JOIN 금지, `date:<속성>:start` 컬럼명, relation uuid 정규화, formula·rollup 조회 불가가 여기 있다
- `../academy-core/references/domain-rules.md` — 클래스 요일 정합, **점수 상한** 규칙의 판정 기준
- `../academy-core/references/completeness-checks.md` — 필수·되물음·공란 허용 세 분류
- `../academy-core/references/write-safety.md` — 쓰기 동작의 자율·승인 경계

`~/.academy/config.json` 이 없으면 즉시 멈추고 `academy-setup` 을 안내한다.

## 언제 쓰나

- "오늘 고2 수학 데일리테스트 30점 만점, 김서준 27 이하윤 25"
- "박시우 재시험 28점"
- "8/22 모의고사 결과 입력"

## 쓰는 속성

두 DB 에 나눠 쓴다. 순서와 이유는 「절차 → 카테고리 먼저」를 본다.

**시험**

| 속성 | 타입 | 값 |
|---|---|---|
| `date:시험 날짜:start` | date | 시험을 본 날짜(`YYYY-MM-DD`) |
| `점수` | number | 원점수. 재시험을 봐도 이 값은 그대로 둔다 |
| `재시험 점수` | number | 재시험 점수만 여기 넣는다 |
| `평가` | select | `통과` / `재시험` / `미응시` 중 하나 |
| `피드백` | text | 서술형 피드백. 새 행을 만들 때는 보통 비운다 |
| `시험 카테고리` | relation → 시험 카테고리 | 최대 1개. 한 건이어도 배열로 감싼다(`["https://.../<uuid>"]`) |
| `이름 붙여넣기` | relation → **학생 과목별 페이지** | `name-resolution.md` 로 얻은 과목 페이지 url |

**시험 카테고리**

| 속성 | 타입 | 값 |
|---|---|---|
| `시험명` | title | `<월/일> <클래스약칭> <유형>` 형식. 아래 「명명 규칙」을 본다 |
| `유형` | select | `단어시험` / `모의고사` / `데일리테스트` / `주간평가` / `월간평가` 중 하나 |
| `총점` | number | 이 시험의 만점. 추측하지 않는다 — 아래 「총점을 반드시 묻는다」를 본다 |

`date:<속성>:start` 표기는 `notion-create-pages`·`notion-update-page` 의 `properties` 키로도 그대로 쓴다. relation 은 대시 없는 uuid 가 아니라 **페이지 url 배열**을 넣는다 — `academy-attendance`·`academy-homework` 에서 실측으로 확인된 동작과 같다.

**쓰지 않는 것.** 쓰기 불가 속성의 권위 목록은 `../academy-core/references/db-map.md` 「DB별 쓰기 불가 속성」이다. `시험` 줄은 `DP`·`성적(%)`·`평균`·`시험 문자`·`시험 유형`·`클래스(그룹)`·`필터`(formula)와 `클래스`·`시험 유형(그룹)`(rollup), `시험 카테고리` 줄은 `시험 날짜`·`평균`(formula)이다. 그 밖에 시험의 title(빈 이름 속성)은 채우지 않는다 — 넘기지 않으면 자동으로 `""` 가 된다. 시험 카테고리의 `시험` relation 은 양방향이라 시험 쪽 `시험 카테고리` 를 채우면 자동으로 맞춰진다 — 카테고리 쪽에서 따로 채우지 않는다.

## 절차

`write-gate.md` 일곱 단계를 그대로 따른다. 아래는 이 스킬 고유의 것만 적는다.

### 카테고리 먼저

시험 카테고리를 **먼저** 만들고, 학생별 시험 행이 그 카테고리를 참조하게 한다(참조하는 쪽이 나중이다 — `../academy-core/references/routing.md` 의 원칙과 같다). `총점`은 카테고리에만 있고 시험 행에는 없으므로, 카테고리가 없으면 성적을 백분율로 계산할 근거 자체가 없다.

같은 시험명의 카테고리가 이미 있으면 새로 만들지 않고 재사용한다. **정확히 일치하는 `시험명` 만 본다 — 날짜 조건은 따로 걸지 않는다.** 카테고리 자체의 `시험 날짜`는 formula라 쿼리로 걸 수 없고(`query-limits.md`), 「명명 규칙」대로면 `시험명`이 이미 날짜를 담고 있어 이름 일치가 곧 날짜 일치다.

```sql
SELECT id, url, "시험명", "총점" FROM "collection://<시험 카테고리>" WHERE "시험명" = '8/21 고2수학 데일리테스트'
```

0행이면 새로 만든다. 시험 카테고리는 통째로 읽어 이름 규칙을 확인해도 무방하다(`query-limits.md` 「행이 많은 DB」). **정확히 일치하지 않아도** `유형` 이름이 팀마다 갈리는 경우가 있으므로(예: `데일리테스트`/`데일리평가` 혼용, 아래 「명명 규칙」), 날짜+클래스약칭까지만 `LIKE` 로 넓혀 조회해 비슷한 이름이 있으면 새로 만들기 전에 원장에게 같은 시험인지 확인한다.

### 사전 검증 (2단계)

`write-gate.md` 의 (가)·(나)·(라) 를 전부 한다. (다) 직전 과제 검증은 `academy-homework` 전용이라 이 스킬과 무관하다.

- **(가) 수업일 대조.** 판정 기준은 `domain-rules.md` 「클래스 요일 정합」을 그대로 따른다.
- **(나) 중복 — 단, 중복 키가 날짜가 아니다.** `write-gate.md` 의 일반 (나)는 "같은 날짜·같은 과목 페이지"를 키로 쓰지만, 이 스킬은 **같은 카테고리·같은 과목 페이지**를 키로 쓴다. 같은 날 시험이 둘 이상 있을 수 있다고 「명명 규칙」이 이미 전제하므로, 날짜만으로 중복을 판정하면 서로 다른 시험을 같은 것으로 오판한다.

  ```sql
  SELECT id, "점수", "평가" FROM "collection://<시험>" WHERE "시험 카테고리" LIKE '%<카테고리 대시 없는 uuid>%' AND "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'
  ```

  걸리면 새로 만들지 않고 `notion-update-page` 를 `command: "update_properties"` 로 호출해 바뀌는 속성만 넣는다 — 같은 시험을 원장이 여러 번에 나눠 부르다가 같은 학생을 두 번 부른 경우 등이다.
- **(라) 퇴원 — 한다.** 판정은 `../academy-core/references/write-gate.md` 2단계 (라)를 따른다. 시험은 `domain-rules.md` 「퇴원 정합」의 대상이고, 이 스킬은 「학생별 점수 입력 범위」대로 **이름이 불린 학생만** 행을 만든다 — 즉 언제나 이름 지목 경로라 `name-resolution.md` 「클래스 전체 지정」의 퇴원생 제외가 걸리지 않는다. 다른 어느 스킬보다 (라)가 필요한 자리다.

### 명명 규칙

`<월/일> <클래스약칭> <유형>` 형식이고, **날짜에 0 패딩을 쓰지 않는다**(`8/1`, `7/2`, `6/26` — `08/01` 아님). 실측 예: `7/4 고2물리 데일리테스트`, `6/24 고2수학 모의고사`, `8/12 중3수학 월간평가`.

이름과 `유형` select 값이 항상 같지는 않다 — 실측에 `6/26 고2수학 단원평가`(이름은 `단원평가`)인데 `유형` 은 `월간평가` 인 행이 있다. 새로 만들 때 이름에 쓸 단어와 `유형` select 값을 각각 확인하고, 다르면 왜 다른지 원장에게 확인한다(오타인지 의도한 별칭인지).

**클래스약칭**은 core 문서 어디에도 정의돼 있지 않다 — 이 스킬이 실측으로 확인한 것은 `고2물리`·`고2영어`·`고2수학`·`중3영어`·`중3수학` 처럼 클래스명에서 "기초"·"심화 A"·"내신반"·"정규" 같은 수식어를 뗀 `<학년><과목>` 형태라는 것뿐이다. 그 클래스의 기존 카테고리가 있으면 거기 쓰인 약칭을 그대로 따른다. **그 클래스의 첫 시험**이라 참고할 기존 카테고리가 없으면, `<학년><과목>` 으로 만들어 보여주고 원장에게 확인받은 뒤 쓴다 — 같은 학년·과목의 클래스가 둘 이상이면(예: 고2 수학이 두 반으로 나뉘면) 이 약칭만으로 구분되지 않으므로 특히 확인이 필요하다.

클래스약칭이 아예 없는 경우도 있다 — 제작자 템플릿 실측에 `2/24 전체모의고사`처럼 특정 클래스가 아니라 학원 전체를 대상으로 한 시험명이 있다. 반 단위가 아니라 전 학원 대상 시험이면 클래스약칭 자리에 "전체" 같은 표현을 쓰고, 어느 반들이 참여하는지는 원장에게 확인한다.

### 총점을 반드시 묻는다

실측 22건 전수에서 같은 `유형`(데일리테스트)의 총점이 30·40·50 으로 섞여 있었다 — 유형만 보고 총점을 추측할 수 없다. 총점 없이 시험 카테고리를 만들면 `성적(%)` formula 가 나눗셈 기준을 잃어 의미 없는 값을 낸다. 되물음 필수 항목은 `write-gate.md` 1단계 표를 따른다 — 그 표에서도 총점을 굵게 표시한 이유가 이것이다.

### 학생별 점수 입력 범위

발화에 이름이 나열되면(예: "김서준 27 이하윤 25 박시우 29") **언급된 학생만** 행을 만든다. `academy-attendance` 의 "반 전체 출석"처럼 클래스 전체를 기본값으로 채우지 않는다 — 시험은 채점이 끝난 사람부터 순서 없이 입력되는 경우가 흔하고, 반 전체를 강제하면 아직 채점하지 않은 학생 자리에 빈 값을 만들게 된다. 반 전체를 한 번에 넣고 싶으면 원장이 "전체"라고 말하거나 전원의 이름을 부른다 — 이때만 `name-resolution.md` 「클래스 전체 지정」을 쓴다.

### 점수 상한은 원점수에도 적용한다

새 시험 행을 만들 때도 원장이 부른 점수가 그 시험의 총점을 넘으면(오타로 자릿수를 잘못 부른 경우가 흔하다) 미리보기를 보여주기 전에 경고한다 — 아래 「재시험」 절의 경고와 같은 형식이되, 대상이 `재시험 점수`가 아니라 `점수`라는 점만 다르다.

### 재시험

`점수` 는 그대로 두고 `재시험 점수` 에만 넣는다. 원점수를 재시험 점수로 덮어쓰지 않는다 — 원점수와 재시험 점수는 둘 다 기록이 남아야 한다.

**재시험 점수가 총점을 넘으면 경고한다.** 판정 기준은 `domain-rules.md` 「점수 상한」을 그대로 따른다(재진술하지 않는다). 실측에도 총점 40점 시험에 재시험 95점이 붙어 있는 오류 사례가 있었다 — 그대로 쓰면 `성적(%)` 이 깨진다. 경고했는데도 원장이 그대로 진행하겠다고 하면(오타가 아니라 만점 기준이 다른 재시험이라 우기는 경우 등) 막지 않는다 — `write-gate.md` 2단계 원칙대로 검증은 자동 중단이 아니라 경고다.

발화에 어느 시험의 재시험인지 특정이 없으면("박시우 재시험 28점"), 그 학생의 **가장 최근 시험 행**을 찾는다. 그 전에 과목 페이지부터 좁힌다 — 학생이 과목 페이지를 여럿 가지고 있고 발화에 날짜·클래스가 없으면 요일로 좁힐 방법이 없으므로, `name-resolution.md` 「학생 이름으로 지정」의 되물음 절차부터 거친다.

```sql
SELECT id, url, "date:시험 날짜:start", "점수", "평가", "시험 카테고리"
FROM "collection://<시험>"
WHERE "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'
ORDER BY "date:시험 날짜:start" DESC LIMIT 1
```

`시험 날짜`는 시험 행 자체의 date 속성이라(`db-map.md` 지문표) 카테고리의 formula 를 거치지 않고 바로 정렬할 수 있다. 2건 이상이 같은 날짜로 걸리면(같은 날 시험을 두 개 봤으면) 원장에게 어느 시험인지 확인한다. 재시험은 **기존 행 수정**이다 — `notion-update-page` 를 `command: "update_properties"` 로 호출해 `재시험 점수`(와 필요하면 `평가`)만 넣는다. 나머지 속성은 생략하면 유지된다.

### 평가는 자동판정하지 않는다

`평가`(통과/재시험/미응시)는 점수와 총점만 보고 클로드가 자동으로 정하지 않는다. 합격선은 시험마다 원장이 다르게 잡고, core 어디에도 고정된 기준이 없다. 발화가 통과·재시험·미응시를 명시하지 않으면 `평가`는 비워 둔다 — 점수 87점이 100점 만점이라고 저절로 `통과`를 넣지 않는다. `미응시`만 예외로, 결석해서 못 봤다는 발화 자체가 그 값을 명시한 것이므로 채운다.

### 미응시

"이하윤은 결석해서 못 봤어" 는 그 학생의 행을 아예 만들지 않는 것이 아니라, **`점수`는 비우고 `평가` 만 `미응시` 로 채운 행을 만든다.** 행 자체를 만들지 않으면 이 학생이 이 시험을 놓쳤다는 기록이 사라진다 — 실측에도 같은 패턴의 행이 있다(`8/11 중3영어 단어시험`, 점수 없음·평가 `미응시`·피드백 "결석으로 미응시. 8/13 보강 때 응시함"). `평균` formula 가 빈 `점수` 를 어떻게 다루는지는 수식 내부(`formulaCode://`)를 읽을 수 없어 미확인이다 — 미응시 행을 넣은 뒤 노션 화면에서 카테고리 `평균` 이 기대대로 나오는지 원장이 한 번 확인하도록 안내한다.

### 미리보기 표 (3단계)

카테고리를 새로 만드는 경우 미리보기 맨 위에 카테고리 1건을 먼저 보여준다. 신규 시험 행의 기본 열은 **학생 / 점수 / 평가 / 클래스**다(카테고리에 이미 날짜·시험명이 있으므로 표 제목에 한 번만 적는다). 재시험처럼 기존 값이 바뀌는 경우에는 **학생 / 원점수 / 재시험 점수(기존 → 변경)** 처럼 무엇이 바뀌는지 보이는 열로 바꾼다. 30행 기준·요약 형식은 `write-gate.md` 3단계를 그대로 따른다.

### 점수를 그대로 비교하지 않는다

총점이 시험마다 다르므로(30·40·50·100 혼재) 점수를 그대로 견줘 말하지 않는다. 30점 만점에 27점은 100점 만점에 60점보다 낫다. 추세나 비교를 말할 때는 `query-limits.md` 의 「성적(%)」 계산법대로 `점수 ÷ 총점 × 100` 으로 환산한 뒤 말한다.

## 주의

- 쓰기 절차·배치 상한(100건)·되돌리기는 `../academy-core/references/write-gate.md` 4~6단계를 따른다. **되돌리기의 생성분/수정분 두 갈래도 거기 있다** — 재시험 처리처럼 기존 행을 고친 것은 **수정분**이라 보관 페이지로 옮기지 않고 고치기 전 값으로 되돌린다(건별 승인). 그래서 「재시험」 절의 조회로 얻은 기존 `재시험 점수`·`평가` 값을 고치기 전에 기억해 둔다. 미응시 행은 새로 만든 것이므로 생성분이다.
- 같은 발화에 출결이 함께 나오면 출결을 먼저 확정한 뒤 그 명단 위에서 시험을 처리한다. 순서와 넘기는 방법은 `../academy-core/references/routing.md` 를 본다.
