# 과제 입력

## 시작 전에 읽는다

- `../academy-core/references/db-map.md` — DB id 를 얻는다. `과제` 의 `collection://<uuid>` 와 지문(행마다 학생 1명, 제목 = 과제 이름)이 여기 있다
- `../academy-core/references/write-gate.md` — 쓰기 관문 일곱 단계(되물음 → 사전 검증 → 미리보기 표 → 승인 → 쓰기 → 결과 보고 → 남은 항목 확인). 이 스킬은 이 절차를 그대로 따르되, 아래 「절차」에는 이 스킬 고유의 것만 적는다. (다) 평가 대상 검증은 이 스킬 전용이다
- `../academy-core/references/name-resolution.md` — 발화의 사람 이름을 `이름 붙여넣기` relation에 넣을 **과목 페이지** url로 바꾸는 절차
- `../academy-core/references/query-limits.md` — 조회를 시작하기 전에 반드시 읽는다. JOIN 금지, `date:<속성>:start` 컬럼명, relation uuid 정규화, formula·rollup 조회 불가가 여기 있다
- `../academy-core/references/domain-rules.md` — 클래스 요일 정합(`수업 날짜`도 대상이다), 과제 평가 대상
- `../academy-core/references/completeness-checks.md` — 필수·되물음·공란 허용 세 분류
- `../academy-core/references/write-safety.md` — 쓰기 동작의 자율·승인 경계

`~/.academy/config.json` 이 없으면 즉시 멈추고 `academy-setup` 을 안내한다.

## 언제 쓰나

- "오늘 고2 수학 진도 삼각함수, 과제 자이스토리 3단원 15문항"
- "오늘 과제 두 개야 — 유형서 5단원, 단어 테스트 준비"
- "김서준 오늘 과제 우수, 피드백은 서술형까지 정확"
- "8월 20일 과제에 피드백 달아줘"

## 쓰는 속성

대상 DB는 `과제`. **행마다 학생 1명**이다 — 반 전체 과제면 학생 수만큼 행을 만든다. 아래 속성만 쓴다.

| 속성 | 타입 | 값 |
|---|---|---|
| `""`(제목) | title | 과제 이름. **`과제 안내` 와 같은 값을 넣는다.** 제목 속성의 이름이 빈 문자열이라 `properties` 키도 `""` 다(`db-map.md` 「제목 속성이 빈 데이터베이스」) |
| `date:수업 날짜:start` | date | 그 과제를 낸 수업 날짜(`YYYY-MM-DD`) |
| `수업 진도` | text | 그날 나간 진도 |
| `과제 안내` | text | 낸 과제 내용 |
| `평가` | select | `우수` / `보통` / `미흡` 중 하나. **그 행 자기 과제의 평가다** — 새 행을 만들 때 원장이 평가를 같이 말했으면 같이 채우고, 아니면 비운다 |
| `피드백` | text | 그 행 과제에 대한 서술형 피드백. 평가와 같은 기준 |
| `이름 붙여넣기` | relation → **학생 과목별 페이지** | `name-resolution.md` 로 얻은 과목 페이지 url. 한 건이어도 배열로 감싼다(`["https://.../<uuid>"]`) |

`date:<속성>:start` 표기는 `notion-create-pages`·`notion-update-page` 의 `properties` 키로도 그대로 쓴다. relation 은 대시 없는 uuid 가 아니라 **페이지 url 배열**을 넣는다(예: `"이름 붙여넣기": ["https://app.notion.com/095596e0..."]`) — 실측으로 확인된 동작이다.

**쓰지 않는 것.** 쓰기 불가 속성의 권위 목록은 `../academy-core/references/db-map.md` 「DB별 쓰기 불가 속성」이다. `과제` 줄은 `DP`·`클래스(그룹)`·`평가 점수`·`과제 문자`·`필터`(formula)와 `클래스`(rollup)다.

## 절차

`write-gate.md` 일곱 단계를 그대로 따른다. 아래는 이 스킬 고유의 것만 적는다.

평가·피드백은 **그 행 자기 과제**를 채점한 값이다 — `../academy-core/references/domain-rules.md` 「과제 평가 대상」. 같은 날 과제가 여럿이면 행도 여럿이고 각자 자기 평가를 갖는다.

### 되물음 (1단계)

필수 항목은 `write-gate.md` 1단계 표를 따른다. 그 중 **수업 진도**가 특히 자주 빠진다 — 진도 없이 과제 안내만 받으면 반드시 되묻는다.

과제가 여럿이면(「과제 두 개야」) 과제 안내를 하나씩 나눠 받는다. 한 줄에 두 과제를 이어 붙여 행 하나로 만들지 않는다 — 평가가 과제마다 따로 붙어야 한다.

평가·피드백을 채우는 발화에서 학생의 과목 페이지가 여럿이고 클래스·날짜로 좁혀지지 않으면 `name-resolution.md` 「학생 이름으로 지정」 4단계에 따라 되묻는다.

### 사전 검증 (2단계)

`write-gate.md` 의 (가)·(나)·(다)·(라) 를 전부 한다. (다) 는 평가·피드백을 채울 때만 적용한다 — 새 과제 행만 만드는 발화에는 해당 없다. 문구와 기본 판정 기준은 `write-gate.md` 2단계를 그대로 따르고, 여기는 이 DB 에 적용한 조회와 이 스킬 고유의 판단만 적는다.

- **(가) 수업일 대조.** `수업 날짜` 는 `domain-rules.md` 「클래스 요일 정합」의 대상이다 — 과제에는 보강 같은 예외가 없으므로 `수업 날짜` 하나가 곧 대조 대상이다.
- **(나) 중복 — 같은 날·같은 학생·같은 과제.** 같은 날 과제가 여럿인 것은 정상이므로 날짜와 학생만으로는 막지 않는다. 과제 이름까지 본다. 제목 컬럼은 이름이 `""` 라 SQL 에서 지정할 수 없어, 같은 값인 `과제 안내` 로 대조한다.

  ```sql
  SELECT id, "평가" FROM "collection://<과제>"
  WHERE "date:수업 날짜:start" = '<날짜>'
    AND "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'
    AND "과제 안내" = '<과제 안내>'
  ```

  걸리면 새로 만들지 않고 「기존 행 수정」 경로로 전환한다. **같은 날 다른 과제는 걸리지 않으므로 새 행이 된다.**
- **(다) 평가 대상.** 평가·피드백을 채우기 전에 그 학생·그 날짜의 과제 행을 조회한다.

  ```sql
  SELECT id, "과제 안내", "평가", "피드백" FROM "collection://<과제>"
  WHERE "date:수업 날짜:start" = '<날짜>'
    AND "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'
  ```

  - 1행이면 그 행이다
  - **2행 이상인데 원장이 과제 이름을 말하지 않았으면** `과제 안내` 목록을 보여 주고 어느 과제인지 되묻는다. 클로드가 고르지 않는다
  - 0행이면 그날 과제가 없다고 알리고, 과제를 먼저 넣을지 묻는다
  - 날짜를 말하지 않은 평가 발화("김서준 과제 우수")는 오늘 날짜로 보되, 오늘 과제 행이 없으면 가장 최근 수업 날짜의 과제들을 보여 주고 확인받는다
- **(라) 퇴원 — 한다.** 판정은 `../academy-core/references/write-gate.md` 2단계 (라)를 따른다. 과제는 `domain-rules.md` 「퇴원 정합」의 대상이다 — 반 단위 발화는 `name-resolution.md` 「클래스 전체 지정」이 퇴원생을 이미 빼지만, 이름으로 지목한 발화("정예린 오늘 과제 우수")는 이 검증이 유일한 방어선이다.

### 미리보기 표 (3단계)

신규 생성 시 기본 열은 **학생 / 날짜 / 과제(제목) / 수업 진도 / 클래스**다(`클래스` 는 쓰지 않지만 원장이 눈으로 확인하도록 보여준다). 같은 날 과제가 둘이면 학생마다 두 줄이 된다 — 반 전체면 표가 길어지므로 `write-gate.md` 3단계의 30행 기준·요약 형식을 따른다. 평가·피드백만 고치는 경우에는 **학생 / 날짜 / 과제(제목) / 평가(기존 → 변경) / 피드백** 처럼 어느 과제의 무엇이 바뀌는지 보이는 열로 바꾼다. uuid 는 넣지 않는다.

### 기존 행 수정 (평가·피드백 채우기)

"평가를 채워 달라"·"피드백 달아줘" 는 예외 없이 **기존 행 수정**이다 — 새 행을 만들지 않는다.

1. (다) 로 대상 행을 하나로 정한다.
2. 그 행의 `id` 로 `notion-update-page` 를 `command: "update_properties"` 로 호출해 바뀌는 속성(`평가` 또는 `피드백`)만 넣는다. **나머지 속성은 생략하면 그대로 유지된다** — `평가`만 고치려다 `수업 진도`·`과제 안내` 까지 함께 넘기면 그 값으로 덮어써 버리므로 주의한다.
3. 승인 경계는 `../academy-core/references/write-safety.md` 「기존 행 수정: 건별 승인」을 따른다 — 미리보기 표에 "기존 행 수정"으로 표시해 무엇이 바뀌는지 보고 승인하게 한다.

## 주의

- 쓰기 절차·배치 상한(100건)·되돌리기는 `../academy-core/references/write-gate.md` 4~6단계를 따른다. **되돌리기의 생성분/수정분 두 갈래도 거기 있다** — 새로 만든 과제 행은 **생성분**이라 보관 페이지로 옮기고, 평가·피드백을 채운 행은 **수정분**이라 고치기 전 값으로 되돌린다(건별 승인). 그래서 `평가`·`피드백` 을 고치기 전에 기존 값을 먼저 읽어 둔다.
- 과제 알림톡은 템플릿 수식(`과제문자`·`과제안내`·`위클리과제`)이 이 행들을 읽어 만들고 Make 가 보낸다(`domain-rules.md` 「발송」). 이 스킬은 보내지 않는다. 평가를 늦게 채우면 이미 나간 알림톡에는 반영되지 않는다.
- 같은 발화에 출결이 함께 나오면 출결을 먼저 확정한 뒤 그 명단 위에서 과제를 처리한다. 순서와 넘기는 방법은 `../academy-core/references/routing.md` 를 본다.
