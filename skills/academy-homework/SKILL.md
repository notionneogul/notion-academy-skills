# 과제 입력

## 시작 전에 읽는다

- `../academy-core/references/db-map.md` — DB id 를 얻는다. `과제`·`과제 M` 의 `collection://<uuid>` 가 여기 있다
- `../academy-core/references/write-gate.md` — 쓰기 관문 일곱 단계(되물음 → 사전 검증 → 미리보기 표 → 승인 → 쓰기 → 결과 보고 → 남은 항목 확인). 이 스킬은 이 절차를 그대로 따르되, 아래 「절차」에는 이 스킬 고유의 것만 적는다. (다) 직전 과제 검증은 이 문서에 이 스킬 전용으로 적혀 있다
- `../academy-core/references/name-resolution.md` — 발화의 사람 이름을 `이름 붙여넣기` relation에 넣을 **과목 페이지** url로 바꾸는 절차
- `../academy-core/references/query-limits.md` — 조회를 시작하기 전에 반드시 읽는다. JOIN 금지, `date:<속성>:start` 컬럼명, relation uuid 정규화, formula·rollup 조회 불가가 여기 있다
- `../academy-core/references/domain-rules.md` — 클래스 요일 정합(`수업 날짜`도 대상이다), 저번 과제 방향의 판정 기준
- `../academy-core/references/completeness-checks.md` — 필수·되물음·공란 허용 세 분류
- `../academy-core/references/write-safety.md` — 쓰기 동작의 자율·승인 경계

`~/.academy/config.json` 이 없으면 즉시 멈추고 `academy-setup` 을 안내한다.

## 언제 쓰나

- "오늘 고2 수학 진도 삼각함수, 과제 자이스토리 3단원 15문항"
- "김서준 저번 과제 우수로 평가"
- "8월 20일 과제에 피드백 달아줘"

## 쓰는 속성

대상 DB는 `과제`. 아래 속성만 쓴다.

| 속성 | 타입 | 값 |
|---|---|---|
| `date:수업 날짜:start` | date | 그 과제를 낸 수업 날짜(`YYYY-MM-DD`) |
| `수업 진도` | text | 그날 나간 진도 |
| `과제 안내` | text | 낸 과제 내용 |
| `평가` | select | `우수` / `보통` / `미흡` 중 하나. **새 행을 만들 때는 비운다** — 아래 「평가·피드백의 방향」을 본다 |
| `피드백` | text | 서술형 피드백. 새 행을 만들 때는 비운다 |
| `이름 붙여넣기` | relation → **학생 과목별 페이지** | `name-resolution.md` 로 얻은 과목 페이지 url. 한 건이어도 배열로 감싼다(`["https://.../<uuid>"]`) |
| `과제 M` | relation → `과제 M` | 항상 채운다. 마스터 행 1건에 연결한다 — 아래 「과제 M」을 본다 |

`date:<속성>:start` 표기는 `notion-create-pages`·`notion-update-page` 의 `properties` 키로도 그대로 쓴다. relation 은 대시 없는 uuid 가 아니라 **페이지 url 배열**을 넣는다(예: `"이름 붙여넣기": ["https://app.notion.com/095596e0..."]`) — 실측으로 확인된 동작이다.

**쓰지 않는 것.** 쓰기 불가 속성의 권위 목록은 `../academy-core/references/db-map.md` 「DB별 쓰기 불가 속성」이다. `과제` 줄은 `DP`·`저번 과제`·`클래스(그룹)`·`평가 점수`·`과제 문자`·`필터`(formula)와 `클래스`(rollup)다. 그 밖에 title 속성은 이름이 빈 문자열이다 — 넘기지 않으면 자동으로 `""` 가 된다.

## 절차

`write-gate.md` 일곱 단계를 그대로 따른다. 아래는 이 스킬 고유의 것만 적는다.

### 평가·피드백의 방향

`../academy-core/references/domain-rules.md` 「저번 과제 방향」이 정의한 규칙이다. 이 스킬의 존재 이유라 아래에 다시 적는다 — 다른 core 규칙과 달리 여기는 포인터만 남기지 않는다.

> 과제 행의 `평가`·`피드백` 은 **그 행의 과제를 채점한 값이 아니라 직전 과제를 채점한 값이다.** `저번 과제` formula 가 직전 행을 가리키고, 학부모 문자가 그 값을 읽는다.
>
> - 새 과제 행을 만들 때 `평가`·`피드백` 은 **비워 둔다**
> - "김서준 저번 과제 우수" 는 **가장 최근 행의** `평가` 를 채우는 것이다
> - 각 학생의 **첫 수업 행**은 평가가 영원히 비어 있는 것이 정상이다 (`저번 과제` 가 "이전 과제 없음")
>
> 이 규칙을 틀리면 전 학생의 문자가 한 칸씩 밀린다.

이 규칙이 `completeness-checks.md` 의 「마지막 행 공란 허용」과 어떻게 공존하는지는 `../academy-core/references/write-gate.md` 2단계 (다) 를 본다.

### 되물음 (1단계)

필수 항목은 `write-gate.md` 1단계 표를 따른다. 그 중 **수업 진도**가 특히 자주 빠진다 — 진도 없이 과제 안내만 받으면 반드시 되묻는다.

평가·피드백을 채우는 발화("김서준 저번 과제 우수")에서 학생의 과목 페이지가 여럿이고 클래스·날짜로 좁혀지지 않으면 `name-resolution.md` 「학생 이름으로 지정」 4단계에 따라 되묻는다.

### 사전 검증 (2단계)

`write-gate.md` 의 (가)·(나)·(다)·(라) 를 전부 한다. (다) 는 새 과제 행을 만들 때만 적용한다 — 평가·피드백만 고치는 기존 행 수정에는 적용하지 않는다. 문구와 기본 판정 기준은 `write-gate.md` 2단계를 그대로 따르고, 여기는 이 DB 에 적용한 조회와 이 스킬 고유의 판단만 적는다.

- **(가) 수업일 대조.** `수업 날짜` 는 `domain-rules.md` 「클래스 요일 정합」의 대상이다 — 출결과 달리 과제에는 "보강 날짜" 같은 예외 컬럼이 없으므로, `수업 날짜` 하나가 곧 대조 대상이다.
- **(나) 중복.** 실측으로 확인한 조회 형태:

  ```sql
  SELECT id, "date:수업 날짜:start" FROM "collection://<과제>"
  WHERE "date:수업 날짜:start" = '<날짜>' AND "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'
  ```

  걸리면 새로 만들지 않고 「평가·피드백의 방향」 절의 기존 행 수정 경로로 전환한다.
- **(다) 직전 과제.** 학생별 가장 최근 과제 행을 다음처럼 조회한다.

  ```sql
  SELECT id, "평가" FROM "collection://<과제>"
  WHERE "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'
  ORDER BY "date:수업 날짜:start" DESC LIMIT 1
  ```

  `저번 과제`·`저번과제평가` 는 formula 라 SELECT 목록에 넣어도 결과에 나타나지 않는다(`query-limits.md`) — 그래서 원본 `평가` 컬럼을 이렇게 직접 읽는다.

  - 0행이면(그 학생의 과제 행이 아예 없다, 즉 첫 과제) 검증 대상이 없으므로 통과다 — 경고하지 않는다.
  - 1행이 나오고 그 행의 `평가` 가 비어 있으면 `write-gate.md` 2단계 (다) 의 문구로 경고하고 되묻는다. **반 전체 과제라면 이 조회를 학생마다 따로 돌려**, 걸리는 학생만 골라 경고한다 — 한 명이 걸렸다고 반 전체를 막지 않는다.
  - "지금 채울까요?"에 원장이 채우면 그 기존 행을 먼저 고치고 나서 새 행을 만든다. "나중에"라고 답하면 경고만 남기고 새 행 생성을 진행한다 — `write-gate.md` 2단계 원칙대로 검증에 걸렸다고 자동으로 막지 않는다.
- **(라) 퇴원 — 한다.** 판정은 `../academy-core/references/write-gate.md` 2단계 (라)를 따른다. 과제는 `domain-rules.md` 「퇴원 정합」의 대상이다 — 반 단위 발화는 `name-resolution.md` 「클래스 전체 지정」이 퇴원생을 이미 빼지만, 이름으로 지목한 발화("정예린 저번 과제 우수")는 이 검증이 유일한 방어선이다.

### 미리보기 표 (3단계)

신규 생성 시 기본 열은 **학생 / 날짜 / 수업 진도 / 과제 안내 / 클래스**다(`클래스` 는 쓰지 않지만 원장이 눈으로 확인하도록 보여준다). 평가·피드백만 고치는 경우에는 **학생 / 날짜(대상 행) / 평가(기존 → 변경) / 피드백** 처럼 무엇이 바뀌는지 보이는 열로 바꾼다. uuid 는 넣지 않는다. 30행 기준·요약 형식은 `write-gate.md` 3단계를 그대로 따른다.

### 과제 M — 마스터 행에 연결한다

`과제 M` 은 마스터 테이블이다. 행이 하나뿐이고 모든 과제 행이 그것을 가리킨다. 새로 만들지 않고 그 1행의 url 을 새 과제 행의 `과제 M` relation 에 채운다. 반 단위든 개인 과제든 구분 없이 매번 같은 1행을 쓴다.

그 1행의 url 은 다음 조회로 얻는다.

```sql
SELECT url FROM "collection://<과제 M>"
```

한 건만 나온다. 그 url 을 새로 만드는 모든 과제 행의 `과제 M` relation 에 배열로 채운다(예: `["https://app.notion.com/ab6596e0..."]`).

### 기존 행 수정 (평가·피드백 채우기)

"평가를 채워 달라"·"피드백 달아줘" 는 예외 없이 **기존 행 수정**이다 — 새 행을 만들지 않는다.

1. `이름 붙여넣기` 로 좁힌 과목 페이지의 과제 행을 `수업 날짜` 내림차순으로 찾는다. 다만 정렬 기준이 미확정이므로(아래 「주의」), 최근 생성 순서와 결과가 갈리면 원장에게 어느 행인지 확인한다.
2. 그 행의 `id` 로 `notion-update-page` 를 `command: "update_properties"` 로 호출해 바뀌는 속성(`평가` 또는 `피드백`)만 넣는다. **나머지 속성은 생략하면 그대로 유지된다**(`academy-attendance` 「수정」 절과 같다) — `평가`만 고치려다 `수업 진도`·`과제 안내` 까지 함께 넘기면 그 값으로 덮어써 버리므로 주의한다.
3. 승인 경계는 `../academy-core/references/write-safety.md` 「기존 행 수정: 건별 승인」을 따른다 — 미리보기 표에 "기존 행 수정"으로 표시해 무엇이 바뀌는지 보고 승인하게 한다.

## 주의

- 쓰기 절차·배치 상한(100건)·되돌리기는 `../academy-core/references/write-gate.md` 4~6단계를 따른다. **되돌리기의 생성분/수정분 두 갈래도 거기 있다** — 이 스킬에서 "기존 행 수정"으로 고친 행(평가·피드백 채우기)은 **수정분**이라 보관 페이지로 옮기지 않고 고치기 전 값으로 되돌린다(건별 승인). 그래서 `평가`·`피드백` 을 고치기 전에 기존 값을 먼저 읽어 둔다. 소급 입력으로 다른 행의 `저번 과제` formula 가 가리키는 값이 바뀐 것은 어느 갈래로도 되돌릴 수 없다 — 스킬이 그 값을 쓴 것이 아니라 formula 가 다시 계산한 것이다.
- **소급 입력(과거 날짜로 과제 끼워 넣기) 은 방어적으로 다룬다.** `저번 과제`·`저번과제평가`·`저번과제피드백` 은 전부 formula 이고, 이 정렬 기준이 `수업 날짜` 인지 생성 순서인지는 쿼리로도 `notion-fetch` 로도 값을 읽을 수 없었다(원장이 직접 실물로 확인하기 전까지는 미확정). 새로 넣으려는 `수업 날짜` 가 그 학생의 **기존 행 중 가장 최근 날짜보다 이르면**(그 사이에 끼워 넣는 경우) 다음을 승인 전 미리보기에 경고로 붙인다.

  > ⚠️ 이 과제는 8월 12일자이고, 조민준의 가장 최근 과제 행은 8월 19일입니다. 중간에 끼워 넣으면 앞뒤 행의 「저번 과제」 평가·피드백 정렬이 밀릴 수 있습니다. 저장 후 노션 화면에서 「저번 과제」가 가리키는 값을 확인해 주세요.

  이 경고는 (다) 직전 과제 검증과는 별개다 — (다)는 평가 공란 여부를, 이 경고는 순서 자체가 흔들릴 위험을 알린다. 둘 다 걸리면 함께 보여준다.
- 같은 발화에 출결이 함께 나오면 출결을 먼저 확정한 뒤 그 명단 위에서 과제를 처리한다. 순서와 넘기는 방법은 `../academy-core/references/routing.md` 를 본다.
