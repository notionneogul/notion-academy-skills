**`학교` DB 전수 4건**: 백양고등학교(고등학교), 늘봄고등학교(고등학교), 해솔중학교(중학교), 상록중학교(중학교).

**퇴원생(실측)**: 정예린(2026-08-08 퇴원, 「고2 물리 기초」 소속이었다), 조민혁(2026-02-26 퇴원).

**학생 과목별 페이지 버튼(실측 스키마 확인, 동작은 미확인)**: `학생` 행에 `국어`·`영어`·`수학`·`과학` 네 버튼이 있다. `물리`는 이 넷에 없다 — 물리 과목은 항상 스킬이 직접 만든다.

아래 8개 예시는 전부 독립 상황이다 — 서로 이어지지 않는다. 각 예시는 조회 결과를 항상 그 예시만의 새 세션으로 가정한다(예: `납부 월` `2026년 9월`은 각 예시에서 매번 0행으로 시작한다).

## 1. 완전 신규 등록(신입생 DB 없이) — "신입생 김민준 등록해줘. 중3, 수학이랑 영어, 월 30만원"

**발화**: "신입생 김민준 등록해줘. 중3, 수학이랑 영어, 월 30만원"

**클로드가 하는 일**: `김민준`은 위 7건 실측 신입생 명단에도, 재원 명단에도 없는 이름이다 — 완전히 새로운 유입을 보여주기 위한 예시 전용 이름이다. (나) 중복 확인부터 한다.

```sql
SELECT id, url, "이름", "date:생년월일:start", "date:퇴원 날짜:start" FROM "collection://<학생>" WHERE "이름" = '김민준'
```

0행 — 새로 등록해도 된다. 되물음을 한 번에 묶는다.

> 생년월일, 성별, 학부모 전화번호, 다니는 학교, 학생 전화번호(있으면), 어느 반에 배정할지, 수강료는 과목당 30만원이 맞는지, 첫 등원일을 알려 주세요.

원장이 답한다: 2011-05-02생, 남, 010-1234-9001, 해솔중학교, 학생 전화번호 없음(중학생이라 `completeness-checks.md` 공란 허용 대상이기도 하다), 중3 수학 정규·중3 영어 내신반 배정, 과목당 30만원, 첫 등원일은 수학이 9월 2일(수, 「중3 수학 정규」 수업일)·영어가 9월 1일(화, 「중3 영어 내신반」 수업일)부터(→ 첫 청구월 둘 다 9월).

**1. 신입생 확인.** `신입생` DB에서 `김민준`을 조회 — 0행. **2. 학교.** 학교 DB를 통째로 읽어 `해솔중학교`를 찾아 재사용한다(신규 학교 아님). **3. 신입생 행 채우기/생성.** 완전히 새로 만든다 — `상태` 초기값은 원장에게 확인한다: "신입생 상태는 `상담 전`으로 둘까요?" 원장이 "응"이라고 답한다.

**미리보기 1(신입생)**:
```
신입생 「김민준」 행을 새로 만듭니다.

| 이름 | 생년월일 | 성별 | 학교 | 학부모 전화번호 | 학생 전화번호 | 학년 수정 | 상태 |
|---|---|---|---|---|---|---|---|
| 김민준 | 2011-05-02 | 남 | 해솔중학교 | 010-1234-9001 | (없음) | 3 | 상담 전 |

이대로 채울까요?
```

승인 후 쓴다.

> 신입생 행을 채웠습니다. 노션에서 그 행의 `재원생 등록` 버튼을 눌러 주세요. 다 되면 알려 주세요.

**4. 버튼 안내** 후 원장이 "눌렀어"라고 답한다. **5. 버튼 결과 검증.**

```sql
SELECT id, url, "이름", "date:생년월일:start", "성별", "학교", "학부모 전화번호", "학생 전화번호", "특이사항", "학년 수정" FROM "collection://<학생>" WHERE "이름" = '김민준'
```

1행 — 값이 신입생 행과 일치한다(생년월일·성별·학교·학부모 전화번호·학년 수정 전부 넘어옴). `학생 전화번호`는 애초에 없다고 답했으므로 빈 채로 넘어온 것이 정상이다. `상태`가 `등록 완료`로 바뀐 것도 확인된다.

**6. 학생 과목별 페이지 판정.** 수학·영어 둘 다 버튼 이름(`국어`·`영어`·`수학`·`과학`)과 정확히 일치하므로 각각 시도한다.

> 학생 행의 `수학` 버튼과 `영어` 버튼을 눌러 주세요.

원장이 눌렀다고 답한다.

```sql
SELECT id, url, "이름", "학생", "클래스" FROM "collection://<학생 과목별 페이지>" WHERE "학생" LIKE '%<김민준 학생 대시 없는 uuid>%'
```

2행이 나온다 — `이름`이 `김민준 수학`·`김민준 영어` 형식으로 이미 채워져 있어 클로드가 대조로 매칭한다. 둘 다 버튼이 만든 것이라 재사용한다. `클래스`는 둘 다 비어 있다.

**7. 클래스 배정 + 수강료 납부.** 클래스 DB에서 `중3 수학 정규`·`중3 영어 내신반` url을 얻는다. 납부 월에서 `2026년 9월`을 조회한다 — 0행, 새로 만든다.

**미리보기 2(학생 과목별 페이지·클래스·수강료)**:
```
납부 월에 1건(2026년 9월)을 만들고, 학생 과목별 페이지 2건에 클래스를 배정하고, 수강료 납부에 2행을 만듭니다.

| 이름(과목 페이지) | 출처 | 클래스 |
|---|---|---|
| 김민준 수학 | 버튼이 생성 | 중3 수학 정규 |
| 김민준 영어 | 버튼이 생성 | 중3 영어 내신반 |

| 이름 붙여넣기 | 수강료 | 상태 | 납부 월 |
|---|---|---|---|
| 김민준 수학 | 300,000 | 미납 | 2026년 9월 |
| 김민준 영어 | 300,000 | 미납 | 2026년 9월 |

이대로 진행할까요?
```

**결과**: "납부 월 1건, 수강료 납부 2행을 만들고 과목 페이지 2건에 클래스를 배정했습니다(학생·과목 페이지 행 자체는 버튼이 만들었습니다). 잘못됐으면 \"방금 거 취소해줘\" 라고 말씀하세요 — 스킬이 직접 쓴 것만 되돌립니다."

## 2. 신입생 DB 에서 전환, 이미 채워진 학교는 건드리지 않는다 — "신입생 백준영 등록시켜줘"

**발화**: "신입생 백준영 등록시켜줘"

**클로드가 하는 일**: (나) 중복 확인부터 한다.

```sql
SELECT id, url, "이름", "date:생년월일:start", "date:퇴원 날짜:start" FROM "collection://<학생>" WHERE "이름" = '백준영'
```

0행 — 진행해도 된다. **1. 신입생 확인.**

```sql
SELECT id, url, "이름", "상태", "date:상담 날짜:start", "date:생년월일:start", "성별", "학교", "학부모 전화번호", "학생 전화번호", "특이사항", "학년 수정" FROM "collection://<신입생>" WHERE "이름" = '백준영'
```

1행 — 실측 그대로다(상태 `상담 전`, 상담 날짜 2026-08-22, 생년월일 2011-04-12, 성별 남, 학교 **상록중학교(이미 채워짐)**, 학부모 전화 010-1234-6604, 학생 전화번호 없음, 특이사항 없음). **`학교`가 이미 채워져 있으므로 「2. 학교」를 건너뛴다 — 다른 학교로 덮어쓰지 않는다.** 비어 있는 것은 `학년 수정`뿐이다. 나머지(수강 과목·배정 클래스·수강료·첫 등원일)와 함께 묻는다.

> 학년, 수강 과목과 배정 반, 수강료, 첫 등원일을 알려 주세요. 학교는 이미 상록중학교로 등록돼 있어 그대로 둡니다.

원장이 답한다: 중3, 수학·영어 각각 중3 수학 정규·중3 영어 내신반 배정, 과목당 30만원, 첫 등원일은 수학이 9월 2일(수, 「중3 수학 정규」 수업일)·영어가 9월 3일(목, 「중3 영어 내신반」 수업일)부터. 학생 전화번호는 언급이 없어 중학생 공란 허용으로 묻지 않는다.

**3. 신입생 행 채우기.** 이미 있는 행이므로 **비어 있던 `학년 수정`만** 채운다.

**미리보기 1(신입생)**:
```
신입생 「백준영」 행의 빈 칸을 채웁니다(이름·상담 날짜·생년월일·성별·학교·학부모 전화번호는 이미 있어 그대로 둡니다).

| 이름 | 학년 수정(신규 채움) |
|---|---|
| 백준영 | 3 |

이대로 채울까요?
```

승인 후 쓴다. **4. 버튼 안내.**

> 신입생 행을 채웠습니다. `재원생 등록` 버튼을 눌러 주세요.

원장이 눌렀다고 답한다. **5. 버튼 결과 검증** — 학생 DB 조회 1행, 값(학교 `상록중학교` 포함)이 넘어온 것을 확인한다. `상태`도 `등록 완료`로 바뀜.

**6. 학생 과목별 페이지 판정.** `수학`·`영어` 둘 다 버튼 이름과 일치해 시도한다 — 눌렀다는 답을 받아 uuid 기준으로 조회하면 2행(버튼이 생성). **7. 클래스 배정 + 수강료 납부.** 클래스 DB에서 두 반을 조회하고, 납부 월에서 `2026년 9월`을 조회한다 — 0행, 새로 만든다.

**미리보기 2**:
```
납부 월에 1건(2026년 9월)을 만들고, 학생 과목별 페이지 2건에 클래스를 배정하고, 수강료 납부에 2행을 만듭니다.

| 이름(과목 페이지) | 출처 | 클래스 |
|---|---|---|
| 백준영 수학 | 버튼이 생성 | 중3 수학 정규 |
| 백준영 영어 | 버튼이 생성 | 중3 영어 내신반 |

| 이름 붙여넣기 | 수강료 | 상태 | 납부 월 |
|---|---|---|---|
| 백준영 수학 | 300,000 | 미납 | 2026년 9월 |
| 백준영 영어 | 300,000 | 미납 | 2026년 9월 |

이대로 진행할까요?
```

**결과**: "납부 월 1건, 수강료 납부 2행을 만들고 과목 페이지에 클래스를 배정했습니다. 잘못됐으면 \"방금 거 취소해줘\" 라고 말씀하세요."

## 3. 완전 신규 + 학교 신규 생성 — "신입생 이도윤 등록, 다솜고등학교 다녀. 고2, 수학만"

**발화**: "신입생 이도윤 등록, 다솜고등학교 다녀. 고2, 수학만"

## 5. 버튼 없는 과목 + 승인 후 쓰기 중 부분 실패 — "신입생 장태윤 등록, 수학이랑 물리"


1행 — 실측 그대로다(상태 `상담 중`, 상담 날짜 2026-08-10, 생년월일 2010-05-21, 성별 남, 학교 **늘봄고등학교(이미 채워짐)**, 학부모 전화 010-1234-8846, **학생 전화번호 010-5678-9017(이미 있음)**, 특이사항 "현재 타학원 재원 중, 9월 이동 희망"). 학교·학생 전화번호가 이미 있어 새로 묻지 않는다. 비어 있는 것은 `학년 수정`뿐이다.

> 학년, 수학·물리 각각 배정할 반, 수강료, 첫 등원일을 알려 주세요.

원장이 답한다: 고2(생년월일만 보면 고1로 계산될 수 있지만 `학년 수정`이 우선), 수학은 고2 수학 심화 A, 물리는 고2 물리 기초, 과목당 30만원, 첫 등원일은 수학이 9월 4일(금, 「고2 수학 심화 A」 수업일)·물리가 9월 5일(토, 「고2 물리 기초」 수업일)부터(특이사항의 "9월 이동 희망"과 일치).

**3. 신입생 행 채우기** — 빈 칸(`학년 수정`)만 채운다. 승인 후 쓴다. **4. 버튼 안내** 후 원장이 눌렀다고 답한다. **5. 버튼 결과 검증** — 학생 DB 조회 1행, 값(학교·학생 전화번호 포함) 일치, 상태 `등록 완료`로 바뀜.

> 지금까지 만든 것을 보고합니다.
> - 신입생 「장태윤」 행: 학년 수정 채움 완료(수정분)

> - 학생 과목별 페이지 「장태윤 수학」: 버튼으로 생성됨, 클래스 배정(고2 수학 심화 A) 완료(수정분)
> - 수강료 납부 「장태윤 수학」 300,000원 미납: 생성 완료(생성분)
> - 학생 과목별 페이지 「장태윤 물리」: **생성 실패** (오류: relation target not found) — 이후 클래스 배정·수강료 납부는 아예 시도하지 않았습니다
>
> 물리 쪽만 다시 시도할까요, 아니면 지금까지 만든 것(수학 쪽 클래스 배정·수강료 납부, 납부 월)을 되돌릴까요?

원장이 "다시 시도해줘"라고 답하면 물리 과목 페이지 생성부터 다시 시도한다. "되돌려줘"라고 답하면 **생성분**(수강료 납부 1행, 납부 월 1건)은 `write-gate.md` 6단계 「보관 페이지 절차」대로 `🗃️ 샘플 보관`으로 옮기고, **수정분**(장태윤 수학의 클래스 relation)은 페이지를 옮기지 않고 `notion-update-page` 로 **고치기 전 값**으로 되돌린다(건별 승인) — 이 경우는 6단계 조회에서 `클래스`가 비어 있던 것을 확인했으므로 되돌릴 값이 빈 값이다. 조회에서 값이 있었다면 그 값으로 되돌린다(`write-gate.md` 6단계 「되돌리기는 생성분과 수정분 두 갈래다」). **버튼이 만든 학생 행·「장태윤 수학」 과목 페이지 자체는 어느 쪽으로도 되돌리기 대상이 아니다**(스킬이 쓴 것이 아니라 노션 자동화의 산출물이다). 신입생 행의 `학년 수정` 값은 성격이 다르다 — 이것은 수정분이라 되돌릴 수는 있지만, 원장이 명시적으로 답해 채운 실제 값이라 되돌릴 이유가 없다(원장이 별도로 지우라고 하지 않는 한 그대로 둔다).

## 6. 중복 등록 차단 — "신입생 배건우 등록시켜줘"

**발화**: "신입생 배건우 등록시켜줘"

**클로드가 하는 일**: 어떤 값을 쓰기 전에 (나) 중복 확인부터 한다.

```sql
SELECT id, url, "이름", "date:생년월일:start", "date:퇴원 날짜:start" FROM "collection://<학생>" WHERE "이름" = '배건우'
```

1행 — `date:생년월일:start`가 2011-03-25로, 신입생 DB의 배건우 행과 정확히 같은 생년월일이다(동명이인이 아니라 같은 사람). **배건우는 이미 재원생이다**(실측: 상록중학교, 타학원에서 이동, 6/15부터 중3 영어 내신반 등원). 신입생 행의 `상태`도 이미 `등록 완료`다 — 상태와 학생 DB 조회가 서로 맞고, 둘 다 "이미 끝난 등록"을 가리킨다.

신입생 행을 채우지 않고, 버튼 안내도 하지 않는다. 대신 원장에게 알린다.

> 배건우는 이미 재원생입니다(중3 영어 내신반, 6/15 등원). 신입생 행의 상태도 이미 「등록 완료」로 맞습니다 — 다시 등록할 필요가 없어 보입니다. 혹시 다른 과목을 추가로 등록하려는 것이었나요, 아니면 상태 확인만 필요했나요?

이 스킬은 재원생에게 과목을 추가하는 절차를 따로 정의하지 않는다 — 원장이 "과목 추가"를 원하면 그 요청은 이 스킬의 범위를 벗어난다고 알리고 진행하지 않는다.

**결과**: 아무 것도 쓰지 않았다. 조회만 하고 끝났다.

## 7. 상태가 등록 완료인데 학생 DB엔 없는 경우 — "문서연 신입생 등록 확인해줘"

**발화**: "문서연 신입생 등록 확인해줘"

**클로드가 하는 일**: (나) 중복 확인부터 한다.

```sql
SELECT id, url, "이름", "date:생년월일:start", "date:퇴원 날짜:start" FROM "collection://<학생>" WHERE "이름" = '문서연'
```

**0행 — 학생 DB에 문서연이 없다.** 신입생 DB의 `문서연` 행은 `상태`가 `등록 완료`다(실측: 상담 날짜 2026-07-06, 생년월일 2011-07-19, 성별 여, 학교 **해솔중학교(이미 채워짐)**, 학부모 전화 010-1234-5527, 학생 전화번호 없음, 특이사항 "언니가 고2 영어 내신반 재원생"). **`상태` 표시와 실제 등록 여부가 어긋난 것이다** — 원인은 이 스킬이 판정하지 않는다. 중단하지 않고 정상적으로 등록을 진행하되, 이 불일치를 먼저 알린다.

> 문서연은 신입생 목록에 「등록 완료」로 표시돼 있지만 학생 DB에는 아직 없습니다 — 실제로는 등록이 안 끝난 것 같습니다. 지금 등록을 진행할까요?

원장이 답한다: 30만원, 첫 등원일 9월 1일(화, 「중3 영어 내신반」 수업일). 학생 전화번호는 중학생 공란 허용이라 묻지 않는다.

**결과**: "신입생 행을 채우고 학생 등록을 완료했습니다(기존 상태 표시와 달리 실제 학생 DB에는 이번에 처음 생겼습니다). 납부 월 1건과 수강료 납부 1행을 만들고 과목 페이지에 클래스를 배정했습니다. 잘못됐으면 \"방금 거 취소해줘\" 라고 말씀하세요."

## 8. 퇴원 이력 있는 동명 학생 — "신입생 정예린 등록해줘"

**발화**: "신입생 정예린 등록해줘"

**클로드가 하는 일**: 되물음으로 생년월일을 포함한 기본 정보를 먼저 받는다. 원장이 답한 생년월일로 (나) 중복 확인을 한다.

1행이 나오고, 원장이 답한 생년월일과 정확히 일치한다(같은 사람). 이 행의 `date:퇴원 날짜:start`가 **2026-08-08**로 채워져 있다 — 실측 퇴원생 정예린(원래 「고2 물리 기초」 소속)과 같은 사람이다. **찾은 기존 학생 행이 퇴원 처리된 행이므로 재등록 판단이 필요하다.** 이 스킬은 재등록 절차를 정의하지 않으므로, 신입생 행을 채우지 않고 진행을 멈춘다.
