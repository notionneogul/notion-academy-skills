# 학원 운영 브리핑

시작 전에 읽는다.

- `../academy-core/references/db-map.md` — DB ID 를 얻는다
- `../academy-core/references/query-limits.md` — **조회를 시작하기 전에 반드시 읽는다.** formula·rollup 은 조회되지 않고, relation 은 uuid 를 정규화해야 대조되며, 연월 문자열은 부등호로 비교할 수 없다. 이 제약을 모르고 짠 쿼리는 오류 없이 틀린 답을 낸다
- `../academy-core/references/domain-rules.md` — 판정 기준을 맞춘다

`~/.academy/config.json` 이 없으면 즉시 멈추고 `academy-setup` 을 안내한다.

**이 스킬은 노션에 쓰지 않는다.** 요청이 쓰기를 요구하면 해당 스킬로 넘긴다.

## 조회의 기본 골격

세 모드 모두 아래 두 가지를 반복해서 쓴다. 각 모드에서 다시 설명하지 않으므로 여기서 익혀 둔다.

### 이름 해석 절차

출석부·과제·시험·수강료 납부·재원생 상담은 사람 이름을 갖고 있지 않다. 전부 `학생 과목별 페이지` 를 가리키고, 사람 이름은 그 너머 `학생` DB 에 있다. 사람 이름으로 출력하려면 두 단계를 거친다.

1. `SELECT url, "이름", "학생", "클래스" FROM "collection://<학생 과목별 페이지>"` — 과목 페이지의 `이름` 은 `이름 2 영어` 처럼 학생명+과목 형식이라 사람 이름이 아니다
2. `SELECT url, "이름", "date:퇴원 날짜:start" FROM "collection://<학생>"` — 사람 이름과 퇴원 여부가 여기 있다

두 결과를 uuid 로 잇는다. 1단계의 `학생` 값(대시 없는 uuid 의 JSON 배열 문자열)에서 uuid 를 뽑고, 2단계 `url` 에서도 uuid 를 뽑아 **양쪽 대시를 제거한 뒤** 비교한다. `=` 로 직접 비교하면 절대 맞지 않는다.

학생 수가 많으면 1·2단계를 통째로 읽지 말고, 브리핑 대상으로 이미 좁혀진 uuid 만 `LIKE '%<대시 없는 uuid>%'` 로 조회한다.

### 날짜 기준선

`CURRENT_DATE`·`INTERVAL` 은 쓰지 않는다. 오늘·1주 전·4주 전·6주 전·8주 전 같은 기준선은 **클로드가 실행 시점에 계산해 `YYYY-MM-DD` 리터럴 문자열로 쿼리에 넣는다.** 요일 판정, 주 단위 구간 나누기, 몇 주 지났는지 세기도 전부 클로드가 값을 읽은 뒤 계산한다.

## 세 가지 모드

### 1. 오늘 할 일

네 가지를 한 번에 모은다. 템플릿에서는 뷰 네 개를 돌아다녀야 하는 것들이다.

| 항목 | 조회 절차 | 클로드가 계산하는 것 |
|---|---|---|
| 보강 필요 | `SELECT id, "date:출석 날짜:start", "출결상태", "date:보강 예정일:start", "학생" FROM "collection://<출석부>" WHERE "출결상태" IN ('지각', '미출석') AND ("보강완료" IS NULL OR "보강완료" = '__NO__') AND "date:출석 날짜:start" >= '<기준선 날짜>'` — 체크박스는 `'__YES__'`/`'__NO__'` 문자열이다. 기준선은 클로드가 계산해 리터럴로 넣는다(기본 최근 8주). 출석부는 학생 수 × 기간만큼 늘어나므로 기간을 반드시 자른다. **`출결상태 = 보강` 행은 넣지 않는다** — 보강 완료 때 만드는 기록 행이라 `보강완료` 가 비어 있어도 보강이 필요한 게 아니다(`domain-rules.md` 「보강」) | `학생` 값을 이름 해석 절차로 사람 이름으로 바꾼다. `보강 디데이` 는 formula 라 조회되지 않으므로, 보강 예정일이 있으면 오늘과의 차이를 직접 센다. 예정일이 없으면 「보강 미정」으로 보인다 |
| 미납 | `SELECT id, "수강료", "상태", "납부 월", "이름 붙여넣기" FROM "collection://<수강료 납부>" WHERE "상태" = '미납'` 과 `SELECT url, "납부 년월" FROM "collection://<납부 월>"` 를 각각 조회한다. 납부 월은 월 단위 DB라 통째로 읽어도 된다 | `납부 년월` 은 `2026년 1월` 처럼 0 패딩이 없어 **부등호로 정렬·비교하면 틀린다.** 연·월을 숫자로 파싱해 오래된 순으로 정렬한다. `이름 붙여넣기` 는 이름 해석 절차로 사람 이름으로 바꾼다 |
| 상담 공백 | `SELECT url, "이름", "학생", "재원생 상담" FROM "collection://<학생 과목별 페이지>"` 와 `SELECT id, "date:상담 날짜:start", "이름 붙여넣기" FROM "collection://<재원생 상담>"` 를 각각 조회한다 | 과목 페이지의 `재원생 상담` 값이 비어 있으면 상담이 한 번도 없는 것이다. 비어 있지 않으면 상담 행 쪽 `이름 붙여넣기` 의 uuid 를 **대시를 제거해 정규화**해 과목 페이지 url 과 대조하고, 그 학생의 가장 최근 `상담 날짜` 를 골라 오늘과의 주 수를 센다. 6주 이상이면 공백으로 본다. `최근 상담 날짜` 는 formula 라 조회되지 않는다 |
| 문자 미발송 | `SELECT url, "이름", "학생" FROM "collection://<학생 과목별 페이지>" WHERE "전송완료" IS NULL OR "전송완료" = '__NO__'` | `전송완료` 는 템플릿 자동화가 주기적으로 초기화하므로 역대 기록이 아니라 최근 주기 안의 발송 여부다. 전원이 미체크로 나오는 것은 정상일 수 있다. 이 사실을 결과에 함께 적는다 |

각 항목은 **건수와 명단**을 함께 준다. 건수만 주면 원장이 다시 물어야 한다.

### 2. 이탈 위험

네 신호를 조합해 순위를 매긴다. 각 학생마다 근거를 함께 낸다.

| 신호 | 조회 절차 | 판정 |
|---|---|---|
| 결석 증가 | 클로드가 오늘 기준 8주 전 날짜를 계산해 리터럴로 넣는다. `SELECT id, "date:출석 날짜:start", "출결상태", "학생" FROM "collection://<출석부>" WHERE "date:출석 날짜:start" >= '<8주 전 YYYY-MM-DD>'` — 학생이 많으면 클래스 단위로 나눠 여러 번 조회한다 | 클로드가 결과를 4주 전 날짜를 경계로 **최근 4주 / 그 이전 4주** 두 구간으로 나누고, 학생별로 `출결상태` 가 `지각`·`미출석` 인 행을 각각 센다. 최근 구간이 이전 구간보다 많으면 신호로 잡는다. 구간 나누기와 날짜 비교는 SQL 이 아니라 클로드가 한다 |
| 성적 하락 | `SELECT url, "시험명", "총점" FROM "collection://<시험 카테고리>"` (시험 종류 수만큼만 있는 DB라 통째로 읽어도 된다) 와 `SELECT id, "date:시험 날짜:start", "점수", "시험 카테고리", "이름 붙여넣기" FROM "collection://<시험>" WHERE "date:시험 날짜:start" >= '<기준선 날짜>'` 를 각각 조회한다. **`성적(%)` 은 formula 라 조회되지 않는다. SELECT 목록에 넣지 않는다** | 시험 행의 `시험 카테고리` uuid 를 정규화해 카테고리의 `총점` 을 찾고, 클로드가 `점수 ÷ 총점 × 100` 으로 백분율을 계산한다. 시험마다 총점이 다르므로(30점짜리와 100점짜리가 섞여 있다) **점수를 그대로 비교하면 안 된다.** 학생별로 백분율을 시험 날짜 오름차순으로 세워, 최근 3회 중 마지막 회차가 첫 회차보다 낮고 직전 회차보다도 낮으면 신호로 잡는다. 시험이 3회 미만이면 이 신호는 판정하지 않는다 |
| 상담 공백 | 1번 모드의 「상담 공백」 과 같은 조회·대조를 쓴다 | 마지막 상담이 6주 이상 전이거나 아예 없다 |
| 미납 | 1번 모드의 「미납」 과 같은 조회를 쓴다 | 그 학생 앞으로 `상태` 가 `미납` 인 행이 있다 |

두 개 이상 겹치면 위험으로 본다. **점수만 내지 말고 왜 그런지 문장으로 쓴다.** "한소율 — 8월 결석 3회(이전 0회), 최근 시험 36%로 하락(직전 62%), 상담 7주 공백" 형태다. 백분율로 말하되, 원장이 확인할 수 있도록 원점수와 총점(`36/100`)을 괄호로 함께 적어도 좋다.

### 3. 상담 준비

학생 한 명을 지정받아 그 학생의 전 데이터를 요약한다.

먼저 **대상 학생을 uuid 로 확정한다.** `SELECT url, "이름", "date:생년월일:start", "학년 수정", "학교", "특이사항", "date:퇴원 날짜:start" FROM "collection://<학생>" WHERE "이름" LIKE '%<입력받은 이름>%'` 로 학생 행을 찾고(`생년월일` 은 date 속성이라 **반드시 `date:생년월일:start` 로 써야 한다.** 속성명을 그대로 쓰면 `no such column` 이다), 여러 건이면 생년월일·`학교` 를 보여 주고 어느 학생인지 되묻는다. 그 다음 `SELECT url, "이름", "학생", "클래스" FROM "collection://<학생 과목별 페이지>" WHERE "학생" LIKE '%<학생 url 의 대시 없는 uuid>%'` 로 그 학생의 과목 페이지 url 을 모두 얻는다. 아래 조회는 전부 **이 과목 페이지 uuid 로 좁혀서** 한다.

| 항목 | 조회 절차 | 클로드가 계산하는 것 |
|---|---|---|
| 기본 정보 | 위에서 읽은 학생 행. `학교` relation uuid 를 정규화해 `SELECT url, "학교명", "선택" FROM "collection://<학교>"` 와 대조한다. 수강 과목은 과목 페이지 `이름` 목록에서 얻는다 | `학년` 과 `참여 요일 및 시간` 은 formula 라 조회되지 않는다. 학년은 **먼저 `학년 수정`(number) 을 본다** — 원장이 직접 보정한 값이라 이게 있으면 그대로 쓴다. 비어 있을 때만 `date:생년월일:start` 로 추정해 적고 **추정임을 밝힌다.** 실측 표본에서는 `학년 수정` 이 10명 중 9명 비어 있었으므로 대개 추정 경로로 간다. 템플릿에 등록일 속성은 없으므로, 등록 시점이 필요하면 그 학생의 가장 이른 출석부 날짜를 근사로 쓰고 근사임을 밝힌다 |
| 출결 | 클로드가 오늘 기준 8주 전 날짜를 계산해 넣는다. 과목 페이지마다 `SELECT id, "date:출석 날짜:start", "출결상태", "date:보강 예정일:start" FROM "collection://<출석부>" WHERE "학생" LIKE '%<과목 페이지 대시 없는 uuid>%' AND "date:출석 날짜:start" >= '<8주 전 YYYY-MM-DD>'` | 출석률은 (`출석` 행 수 + `보강완료` 가 켜진 `미출석`·`지각` 행 수) ÷ (`출결상태 = 보강` 행을 뺀 전체 행 수)로 클로드가 계산한다. 보강을 마치면 원래 결석 행이 남은 채 보강 행이 하나 더 생기므로(`domain-rules.md` 「보강」), 보강 행을 분모에 넣으면 같은 회차가 두 번 세어진다. 결석 사유는 학생 행의 `특이사항` 에 있으면 함께 낸다 |
| 성적 | `SELECT url, "시험명", "총점" FROM "collection://<시험 카테고리>"` 와, 과목 페이지마다 `SELECT id, "date:시험 날짜:start", "점수", "재시험 점수", "평가", "피드백", "시험 카테고리" FROM "collection://<시험>" WHERE "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'`. 클래스 평균을 내려면 같은 시험 카테고리를 가리키는 **다른 학생들의 시험 행도** 같은 방식으로 읽는다: `SELECT id, "점수", "시험 카테고리", "이름 붙여넣기" FROM "collection://<시험>" WHERE "시험 카테고리" LIKE '%<카테고리 대시 없는 uuid>%'` | `성적(%)` 도 시험 카테고리의 `평균` 도 formula 라 조회되지 않는다. 백분율은 `점수 ÷ 총점 × 100` 으로, 클래스 평균은 **같은 시험 카테고리에 속한 시험 행들의 `점수` 를 모두 읽어 클로드가 평균을 내** 구한다. 대비 위치는 그 평균과의 차이로 적는다. 추세는 시험 날짜 오름차순 백분율 나열로 본다 |
| 과제 | 과목 페이지마다 `SELECT id, "date:수업 날짜:start", "수업 진도", "과제 안내", "평가", "피드백" FROM "collection://<과제>" WHERE "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'` | 평가 분포는 `우수/보통/미흡` 건수를 센다. `평가`·`피드백` 은 **그 행 자기 과제**의 채점이다(`../academy-core/references/domain-rules.md` 「과제 평가 대상」). 같은 날 과제가 여럿이면 각각 따로 센다. 반복되는 피드백 주제는 클로드가 문장을 읽고 묶는다 |
| 수강료 | 과목 페이지마다 `SELECT id, "수강료", "상태", "date:납부 날짜:start", "납부 월", "비고" FROM "collection://<수강료 납부>" WHERE "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'` 와 `SELECT url, "납부 년월" FROM "collection://<납부 월>"` | `납부 월` uuid 를 정규화해 대조하고, `납부 년월` 은 연·월을 숫자로 파싱해 정렬한다. 문자열 정렬은 틀린다 |
| 상담 이력 | 과목 페이지마다 `SELECT id, "date:상담 날짜:start", "상담 기록" FROM "collection://<재원생 상담>" WHERE "이름 붙여넣기" LIKE '%<과목 페이지 대시 없는 uuid>%'` | 상담 날짜 내림차순으로 세우고, 지난 상담에서 약속한 것을 `상담 기록` 본문에서 뽑는다. 기록이 `상담 내용 입력` 같은 템플릿 안내문이면 실제 기록이 아니므로 그렇게 말한다 |

마지막에 **할 말 3~5줄**을 정리한다. 좋은 점 하나, 개선점 하나, 제안 하나를 포함한다.

## 출력 규칙

- 표로 낸다. 문단으로 늘어놓으면 원장이 못 읽는다
- 학생 이름은 과목 페이지 이름(`김서준 수학`)이 아니라 **사람 이름**으로 낸다. 이름 해석 절차를 거친다
- 퇴원생은 제외한다(학생 행의 `퇴원 날짜` 가 비어 있지 않으면 퇴원생이다). 단 이탈 위험 모드에서 최근 퇴원자는 참고로 언급한다
- 계산해서 얻은 값(백분율·평균·주 수)은 그렇게 얻었다는 것을 감추지 않는다. 근거가 된 원본 값을 함께 낸다

발화 예시는 `references/examples.md` 를 본다.
